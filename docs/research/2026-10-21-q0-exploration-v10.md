## 1. 为什么做这一轮

- **Q0 的优势出乎预期，而它还只是 H0 机制的机械移植。** v9 的 `qwen-wide` 在 dp10-cut 同一接缝下两类 accuracy 都显著好于 Hy-MT2（剧集 −0.058、电影 −0.091），用的却是 Hy joint 提示原样拆成 system／user、同样的 ID JSON grammar、同样的切包。专名表没有注入（v9 明确排除），生成后替换是产品 `names` 阶段的事，Q0 未进产品，两者至今没有一起跑过。
- **H0 机制里的多数约束是 Hy-MT2 的产物，不是字幕任务本身的要求：**

  | H0 约束 | 来源 | 对 Qwen 的状态 |
  | --- | --- | --- |
  | 可见 ≤12、前 1 后 1 | Hy 输入上限 4032 tokens；v3 §4.2 测得 ctx3 对 Hy 无效 | v9 已证伪：前 20＋后 5 显著改善，无泄漏 |
  | 每批 ≤10 条输出 | v3 §4.1：Hy 的 wrong-referent 随输出 ID 数增长 | 未在 Qwen 上测过 |
  | 提示只有任务说明，无角色、风格、示例 | Hy 是专用 MT，提示空间很窄 | Qwen 的 system 提示空间完全没用上；v9 唯一稳定的反向信号 unnatural 正是提示能直接作用的维度 |
  | 严格逐 ID、不重排 | v8：Hy 在任何约束下都按日文行序输出 | 未测，但 v8 的结构性风险（划组不知道说话人）与模型无关，本轮不重开 |
  | 专名靠建表后替换 | v5 第 10 步：术语表注入 Hy 提示使 accuracy +0.022 | 建表与翻译现在是同一个模型，注入的前提变了；ADR-0013 指出剩余覆盖缺口是一次性音译，规则替换原理上够不到 |
  | 不利用"源文是 ASR"这一事实 | Hy 没有纠错能力 | v5 第 02 步：产品中文错误约四分之三来自 ASR；v9 人工阅读看到 Hy 把片假名误读照译而 Qwen 更好 |

- **先验要如实：** 单 seed 到三 seed 的效应已回落约一半；裁判是 Claude（`claude-opus-5-5-mqm-v1`），同类 LLM 偏好同类译文风格的疑问没有独立检验；dev 集是干净的字幕组日文，产品输入是 ASR 稿。所以本轮第一阶段不是新方向，而是把 Q0 的优势坐实，后面的方向才有意义。

### 2.2 v9 留下的方向性结论

- 宽邻文对 Qwen 有效（wide − narrow 剧集 −0.038、电影 −0.057），改善主要是 mistranslation、wrong-referent；没有邻文泄漏（同一检测下标记率不高于对照，人工 19 条真泄漏 0）。
- **unnatural 显著变差**（三 seed 两类都显著，+0.019／+0.014）；grammar 无差、register 略好；电影 omission +0.011 小幅变差；cue-attribution 几乎为 0。
- 专名相关裁判错误与不一致率在 Q0 与 H0 之间无一致方向：世界知识的预期优势在干净源上没有显现。
- 人工阅读 |Δ| 最大 20 包：Qwen 更好 17、Hy 更好 2、争议 1；Hy 失分在极性反转、主语指代、方言与片假名误读，Qwen 的问题是翻译腔与生硬直译。
- v9 §5 按纪律禁止提示搜索，`qwen-joint-v1` 是 Hy 任务文字的机械拆分，没有为 Qwen 写过一个字。

## 3. 本轮要回答的问题

1. **Q1 Q0 的优势是否真实**：重复 seed 上 `qwen-wide` 对 dp10-cut 的两类 accuracy Δ 是否复现；非 LLM 指标（与中文参考的相似度）与人工盲读是否与 Claude 裁判方向一致。
2. **Q2 自然度能否用提示修复**：为 Qwen 写的 system 提示能否把 unnatural 压回 H0 水平或更低，同时 accuracy 非劣、不新增 addition 与泄漏。
3. **Q3 Qwen 的理解范围边界**：只读邻文从 20＋5 继续放宽，accuracy 与 wrong-referent 的方向；输出包从 ≤10 放大，wrong-referent 是否像 Hy 那样随输出 ID 数增长。
4. **Q4 产品 ASR 源上的差距与 ASR 感知翻译**：在 HF II／III 的产品 `ja.srt` 上 Q0 对 H0 是否仍更好；告诉模型源文是 ASR 稿并允许按上下文与作品知识纠正误识后，heavy／light 桶的错误是否下降，exact 桶是否不变差（幻觉纠正）。
5. **Q5 专名表注入对替换**：把产品 `name-table.json` 注入 Qwen 提示，相对"Q0 生成后替换"（产品等价链）在不一致率、专名相关错误与 accuracy 上的方向；注入＋替换是否叠加。
6. **Q6 整片简报与有界思考**（若预算允许）：每部一次请求产出的角色／称呼／语体简报注入 system 后的方向；`--reasoning-budget` 有界思考在长包上的收益与墙钟。
7. **Q7 代价**：每臂墙钟、输入／输出 token、显存峰值、重试／降级／交付失败，与 Q0 并列。
8. **Q8 结论写法**：对每个方向给出三种之一——"关闭，重开条件 X"／"非劣无改善，不进候选"／"非劣且某维度显著改善，列为 Q1 候选成分"。本轮**不组合、不锁定最终候选**：各方向的候选成分列成清单交用户裁定如何组合与确认（§8）。

成功的定义是 **Q1–Q5 都有带区间或明确计数的答案**；Q6 可因预算或门未过而只报"未做"。

## 4. 已定的设计（2026-10-21 讨论结论）

### 4.0 通用规则

- **对照**：所有 Qwen 候选臂的对照是 **Q0**（`qwen-wide`）；H0 只在 A1（复现）与 D0（产品 ASR 源基线）里出现。每个比较都写明对照是 Q0 还是 H0（ADR-0015）。
- **同包配对**：改提示、改邻文的臂必须与 Q0 的包组成（目标 ID 序列）逐字相同，执行者核对；改输出包大小的臂（C2）包组成必然不同，按 v7 的做法逐 cue 配对、全集裁判。
- **对照译文复用**：Q0 主 seed 20261011–13 的三个 run 来自 v9，可直接作对照译文；但每次比较都要同期重判对照（v7 §2.1），不得复用 v9 的分数。
- **采样与请求**：除明确要改的字段外与 Q0 相同（采样、grammar、两次尝试、`cache_prompt`、context 预算规则）。context 需要放大时只对该臂放大并记录显存峰值。
- **一个臂一个变量**；一个阶段的臂数固定在下文，补充臂走 §4.7。

### 4.1 阶段 A：地基——复现与裁判偏好检验

### 4.2 阶段 B：为 Qwen 写的提示（攻 unnatural）

| 臂 | 内容 | 终点 | 门 |
| --- | --- | --- | --- |
| **B1 `qwen-joint-v2`** | 新 system 提示，**只针对自然度**：角色（日本影视中文字幕译者）、字幕中文的口语与简洁要求、避免翻译腔与生硬直译、长度与原文相称、不解释不加注；**归属规则原句保留**（共同理解、逐 ID 承载、不搬运邻条、不提前补完、保留歧义与信息揭示顺序）。不加示例、不加专名、不改 user 消息结构。执行者定措辞，版本化进 hash | unnatural（主）、accuracy（非劣界）、addition、泄漏检测（v9 同一规则） | smoke（5 包）合规后 3 seed 全集筛选。**采纳为候选成分**：两类 unnatural CI90 上界 <0 且两类 accuracy CI90 上界 <0.05。unnatural 无改善 → 允许**一次**措辞修订 `v2b` 再筛一遍；仍无 → 关闭"提示修自然度"方向 |

## 5. 判定纪律、预算与停止条件

- 判定纪律沿用 [v5 §3](2026-10-16-quality-exploration-v5.md)：裁判 `claude-opus-5-5-mqm-v1`（dev）与 `v5-asr-pairwise-v1`（产品 ASR 源）不改；需要新量尺时新建版本化 profile 并先做噪声校准；三 seed 起谈质量（1 seed 只定方向与开关）；作品为聚类单位；剧集与电影分开；筛选与确认分离；成本与失败随结果一起记；未知值不填 0；隐私边界不变（裁判只收 packet，简报与专名表是转写内容不进日志）。
