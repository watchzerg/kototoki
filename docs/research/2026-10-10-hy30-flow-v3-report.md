# Hy30 字幕翻译流程第三轮探索报告（v3）

日期：2026-10-10。计划：[v3 计划](../plans/hy-mt2-translation-flow-exploration-v3.md)。逐候选记录：[v3 台账](../context/2026-10-10-hy30-flow-exploration-v3.md)。实验入口：[translation_v3](../../experiments/translation_v3/README.md)。
本报告只给出证据和建议，**不替换基线**；是否采纳由用户决定。基线仍是 [ADR-0005](../adr/0005-apex-i-compact-translation-baseline.md) 的 `official30b-cached-v1`（即本轮的 C0）。

## 1. 结论摘要

**结论：本轮没有配方通过确认，结果为 0 个候选，基线 C0 保持不变。** 唯一锁定的配方 b10-joint 在筛选集的 96 窗上判为 promising（Δ −0.093，区间 [−0.124, −0.054]）；但在独立确认集（48 窗 × 3 seed）上，总体 Δ 为 −0.012，区间 [−0.053, 0.033]，Holm p = 0.31，**未通过**。而且类别方向与筛选集相反：剧集 +0.072（劣于非劣界），电影 −0.097。

- 13 个单因素候选中，没有一个在 96 个筛选窗上达到 promising。只有组合 **b10-joint** 达标：每批 10 条，并把 C0 提示里“每个值独立理解”换成“跨 cue 共同理解”。它在 96 窗和 screen-b 单独比较时都判为 promising。
- 最稳定的规律是：增大批次（b8–b20、tok300–tok500）能明显减少剧集的误译（mistranslation），但同时带来跨 cue 的指代错误（wrong-referent）和电影侧的劣化。joint 提示在 b10 上能抵消这部分代价，到 b20 就不行了。
- 被否定的方向：
  - 有界空白 grammar（bws）：96 窗 Δ +0.018。
  - 术语预分析（terms）和选择性审校（review）：screen-a 上都变差；review 的墙钟多 64%，critical 是 C0 的 4 倍。
  - 只读邻文 ctx0／ctx3／ctx3-1：都没有达到 promising，电影侧不稳定。
- 成本：b10-joint 的墙钟比 C0 少约 7%（34 个场景 608 秒对 653 秒），请求数减半，显存不变。

## 2. 评测方法与校准（S0）

- **主终点**：每条评分 cue 的 accuracy 惩罚均值（minor 1、major 5、critical 10），越低越好。先在 3 个 seed 上取均值，再按作品等权汇总，剧集和电影各占 50%。风险窗单列，不进总体均值。

## 4. 方向结论与机制

### 4.1 批大小（B、T）：剧集受益，电影受损

- 96 窗 Δ：b5（C0）为 0，b8 −0.015，b10 −0.061，b15 +0.089，b20 −0.024，b40 +0.020。剧集在 b8–b20 区间稳定改善 −0.07 到 −0.21；电影在 +0.05 到 +0.24 之间波动，几乎完全由 M03（以及一次 M04 交付失败）决定。
- token 分批也是同样的分化，而且目标越大分化越强：tok500 剧集 −0.311、电影 +0.274。
- 错误类别（3 个 seed 的 96 窗合计惩罚，剧集）：wrong-referent 从 C0 的 34 升到 58（b10）、79（b20）、94（b40），mistranslation 从 297 降到 200 左右。电影的 negation-number-condition 在 b20、b40、tok400 上从 20 升到 30–35。
- 推断：批次越大，上下文越多，词义消歧越好；但一次要输出的 ID 越多，指代对象和条件就越容易串到别的 cue 上。剧集的净效应为正，电影为负。

### 4.2 只读邻文（X）

- ctx0 和 ctx3 都让剧集改善约 0.09–0.14，但电影都变差，而且 screen-b 上 M03、W09 的个别窗口反复出现 +0.5 到 +0.9 的劣化。ctx3 的墙钟多 5%。
- “宽只读上下文、小输出批次”这个假设没有得到支持。

### 4.3 联合理解提示（J）及其与批大小的组合

- joint 单独使用时，效应小但最一致：96 窗 Δ −0.031，区间不含 0，3 个 seed 都为负，电影不劣化。
- b10-joint 把 b10 的 wrong-referent 从 58 压回 36（C0 为 34），同时保留了 mistranslation 的下降（297 → 211）；电影的 negation-number-condition 从 20 降到 0。这与 4.1 的机制解释一致。
- 机制有边界：b20-joint 的 wrong-referent 仍为 79，tok400-joint 也没有达标。joint 只在中等批次下有效。

### 4.4 工程项（W）与其他

- bws：96 窗 Δ +0.018，3 个 seed 都没有改善，淘汰。全轮约 1400 个场景 run 中，4096 空白循环只出现 1 次（b15，M04），按不可交付计分。这个频率很低，但一旦发生会损失整个场景。
- terms（场景术语表）、review（否定／条件触发的审校）：质量方向都为负，review 的成本还高 64%。

### 4.5 方法学观察

- screen-a 与 screen-b 的结论经常相反（bws 为 +0.056／−0.022，b40 为 −0.071／+0.118）。只看 48 窗时，噪声大于 MDE，所以 promising 必须以 96 窗为准。
- 作品异质性依然很大（M03、W09 反复主导）。逐作品表格和 LOO 门槛起到了作用：多数“均值看起来好”的候选都卡在 LOO 上。
- 漂移排查：S1 期间对 C0 s10 做了重评，结果略严（剧集 +0.044），可以排除“后评的候选被裁判放宽”这种解释。

3. 确认集现已开封，不能再用于确认后续候选。如果之后想再做确认，需要新建独立的确认集。

## 7. 适用范围、风险与建议

- **建议：继续使用 C0（`official30b-cached-v1`），不替换基线。** 本轮没有配方通过确认。
- 可以作为后续线索、但**不是已证实优势**的：
  - b10-joint 在两个集合上都没有增加 critical，fluency 更好，速度约快 7%，请求数减半。如果以后更看重速度或请求数，可以把它作为“非劣待证”的工程选项另行验证，需要新的确认集，并且要专门检查剧集的非劣性。
  - 批大小对错误类型的影响（大批次误译少、串条多）在筛选集上很一致，可以作为机制性先验；但它在不同窗口上的净效应不稳定。
- 不建议再投入的方向：
  - 有界空白 grammar：质量无改善；空白循环约每 1400 个场景 run 出现 1 次，可在交付层用重试处理。
  - 场景术语表、选择性审校：质量为负，审校成本还高 64%。
  - 单纯调整只读邻文。
  - b20 以上的批次，以及 token 500 级别的分批。
- 方法层面的风险与改进：
  - 作品和窗口的异质性大于配方效应。这与 v1/v2 的教训一致，而这一次在新裁判下得到了证实。
  - 以后若要再做筛选，应当每个作品取更多窗口，或者把筛选窗换成整集或整段评分，以降低窗口层面的方差；也可以把当前的 MDE 0.05 视为偏乐观的下限。
- 适用范围：
  - 结论只针对固定模型 Hy-MT2 30B-A3B APEX-I-Compact、固定采样、8192 context，以及本库的 10 部作品（6 部剧集、4 部电影）。
  - 裁判是单一的 Opus 5.5 MQM 量尺，没有人工日语评审。
  - 只在原生 Windows 加 RTX 5080 上验证过。
