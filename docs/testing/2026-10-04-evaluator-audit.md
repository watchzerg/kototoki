## 审查结论

连续文字计分、原始字符来源、底层时间粒度和完整分母的实现可用于探索性开发对比。合句或拆句不进入主 CER；保持相同底层时间映射时，时间表也不变。文字匹配先于时间，重复台词不能通过寻找更近时间获得确定匹配。

审查发现的几个问题会把已确认不完整、无时间或时间显然超标的重复内容错误地算入成功率乐观上界，或把 crop 的源时间与局部时长混用。修复后，联合最优文字路径必须同时满足完整内容、有效单元、至少一个精确字符锚点和单调时间，才可能进入对应门槛的未决上界。不能仅独立检查每个字符是否“可能匹配”，也不能只看起止时间而忽略内部失败。

这是计分工具的验证，不能据此称任何 STT 路线已达到 500 ms 或 2 s 目标。原始 SRT 仍是未经声学核对的显示参考；口述身份、编辑性时间差、章节边界和实际静音仍需要独立证据。

## 独立验证证据

环境为本机原生 Windows、项目 uv 建立的 `.venv`、Python 3.12.15。全部检查使用合成文字或 PCM，不加载模型、不下载资产、不占用 GPU，没有读取保留集参考或转写内容。

1. 独立完整矩阵与最优路径遍历，对二元字符集长度 0–4 的全部 961 对字符串验证：编辑距离、S+D+I 总数和每个字符的匹配歧义集合全部相同。
2. 对这 961 对字符串的全部 6,882 个非空参考跨度，枚举全部最优完整映射，验证 `complete_possible` 与 `possible_span_bounds`；另外验证偶数/奇数/空的允许位置集合、精确字符锚点和任意成对时序谓词。全部相同。这覆盖的是路径语义，超出仅与另一份距离矩阵比较。
3. 项目评测器 22 个 unittest 全部通过，覆盖合拆不变性、标点/NFKC、遗漏/重复/静音、整体 1 s 移动、粒度不足、失败与插值、重复文本、完整性、人工区间、源时间恢复、严格门槛及 CLI 输出保护。语料的 4 个离线测试通过，包括准确样本 crop、样本范围身份复用、越界拒绝和 SRT 源坐标。
4. harness 在独立临时根目录注入 5 种情况：正常退出、前置缺音频、缺执行文件、后端退出码 7、启动后合成参考被删除。全部没有残留 GPU 锁。最后一种保留 `reference_unchanged=false` 且返回非零，不把子进程正常退出视为素材保护成功。

检查脚本保存在 Git 忽略的 `.local/audit/`，分别为 `check_alignment.py`、`check_span_feasibility.py`、`check_harness.py`；它们不包含私人内容。可在项目根目录用 `.venv/Scripts/python.exe` 重新执行。harness 故障测试的 GPU 监测命令被合成返回值替代，它不证明实际 nvidia-smi、超时终止或设备执行。

## 长文本成本

固定 seed 42、16 字符合成字母表，约 10% 字符被替换为表外字符，独立运行 `align`；各长度生成一对新字符串。时间包括精确自适应带扩展与歧义遍历。

| 参考字符数 | 实际编辑距离 | CPU 用时 |
| ---: | ---: | ---: |
| 1,000 | 104 | 0.218 s |
| 6,000 | 581 | 15.461 s |
| 15,000 | 1,526 | 71.007 s |

这证明该规模的精确全文文字计分可以运行，不是实际整片评测耗时预测。高删除/插入、大量重复或高 CER 可能产生更宽 band 和更大的最优路径图，最坏复杂度仍接近全文矩阵。没有测量本次 CPU 峰值内存，也没有用真实保留文本做规模检查。正常比较优先使用预先冻结场景并汇总完整文字，再保留整片完整总分核对；不能按候选时间删除迟到字符或按看到的结果重新切场景。

## 执行与证据边界

语料按容器章节和固定缓冲划分，并保存样本整数索引；crop 从同一份解码 PCM 读取，直接恢复源时间，避免累积舍入。章节并非已核对的语义场景。短前置括号删除是预先冻结的弱参考规则，可能遗漏实际发声的括号内容，当前标记未听辨；自动结构抽查不能称为 40 项人工参考复核。

harness 的互斥锁只保护通过该入口启动的作业；它不能识别其他手动 GPU 作业。约 1 s 的 nvidia-smi 采样是整张显卡的使用量，包含桌面基线，既不是每进程峰值，也不是 ASR/FA 实际 device 的证明。设备需由 adapter 的实际模型/输入/输出或运行图证据独立证明。离线环境变量是请求而非网络隔离的证明；完整离线重载仍须实测。

每轮必须比对 harness 的音频 SHA256 与后端实际输入身份，记录模型文件与 revision、环境包版本、实际生效参数、窗口、阶段复用和音频变换。计分 rule_version 不等于正式晋级配置已经冻结。没有人工声学真值时，只能报告相对 SRT 的差异并继续诊断，不能把待测模型生成的边界当真值。

仍未验证：真实模型输出覆盖、专名/数字错误归因、静音幻觉连续事件/分钟、人工盲审、共同有效子集成对比较、配对 bootstrap、native/统一 writer 的听觉显示体验、Windows 超时或取消的实际进程树清理、整片稳定性与真实 GPU 资源/速度。以上缺口应随最终选型报告保留。

## 后续复核：内部文字歧义与可观察时间边界

本节记录同日追加的概念审查与 v2 修复。前述代码 hash 和 22 项测试对应较早快照，不自动代表本节实现。该变更由合成反例及测量可观察性原则提出，在正式筛选规则冻结前实施；旧评分应保留，新评分使用独立输出身份，不混成同一计分版本。

原实现只要跨度内任意字符存在文字匹配歧义，就把整个跨度列为 `matching_ambiguity`。这是保守做法，却把可确定的内容时间也变为未决。例如参考 `aba`、候选 `abba`，恰有两条最优映射 `(0,1,3)` 与 `(0,2,3)`；两条都完整，首尾候选身份固定，差别只在内部重复的 `b`。原生字符时间依次为 `[i/10,(i+1)/10]` 时，同内容跨度的预测边界在两条路径上都是 0–0.4 s。旧实现报告成功下界 0、上界 1，尽管这个时间测量并无歧义。文字的 I=1、CER=1/3 仍必须保留，不能通过提升时间可测性删除重复错误。

反向参考 `abba`、候选 `aba` 的首尾也固定，但内部必有删除；首尾相同不能证明完整内容同步。因此 v2 的提升条件是**所有**全文最优文字路径都完整映射该跨度、首尾候选字符身份完全一致、每条路径都有至少一个精确字符锚点、所有可能选中的原生单元有效，以及所有可达的相邻参考字符映射都满足时序。任何条件不满足，都不得把某条有利路径提升为确定成功。时间只验证预先由文字证明的唯一边界，不寻找最小偏移路径。

这些条件的充分性可直接证明：若每条最优路径都完整且首尾映射相同，则任何路径给出的首尾原生单元固定；所有可能选择的单元都有效，保证不会借另一路径隐藏失败；任何完整路径的倒序至少发生在某个相邻参考字符对，所以逐一检查所有可达相邻对足以覆盖全部路径。路径内部的文字对应仍可歧义，必须保留 `character_mapping_ambiguous` 元数据。两个重复发声即使碰巧拥有完全相同的数字时间，只要首尾文字身份不一致，也不能因此变成确定匹配。

实现的 rule_version 为 `nfkc-punctuation-v2-universal-complete-invariant-boundaries`。独立完整路径枚举的全部 6,882 个跨度再次通过，新增核对了 universal completeness、固定端点、所有可达候选位置和每条路径存在精确锚点。7 个独立计分反例通过：内部插入重复可测；内部删除重复确认不完整且 U=0；一个可能内部单元失败或倒序仍保留未决；两份内部单元都失败 U=0；重复端点身份不明即使数字时间相同也保持未决。

一个细节是，两种互斥内部位置可能彼此呈数字时间倒序，但从不存在同时选择它们的完整路径，而且每条实际可达路径都单调。把位置的并集机械排序再检查会制造不存在的路径。v2 检查实际可达相邻对，因此该情况可以测量；这一行为也通过独立合成验证。此修复不改变主 CER、参考分母或失败保护线，也不修复任何模型时间。

### 规范化补充检查

空字符串、标点和空白按已声明规则规范化为空；U+200B、U+FEFF 等 `Cf` 格式字符仍保留，因为它们既不是 Unicode 标点，也不满足 Python `isspace()`。这是现有规则的明确结果，不应看到候选后只对其中一方删字符。若要增加格式字符政策，应统一应用两侧并建立新的规则身份。

另一个合成反例暴露了来源映射边界问题：两个固定参考跨度分别含 `か` 与 U+3099 组合浊点，拼接后 NFKC 为 `が`，字符原文来源 `[0,2]` 跨越跨度边界。旧 containment 逻辑把两个跨度均记为 `empty_reference`，时间分母变成 0，而全文参考字符数仍是 1。不能把这种映射失败当作非口述内容静默排除。经主 agent 授权，实现已在文字对齐之前明确拒绝跨参考跨度的规范化来源簇，要求独立修订或预先合并参考；不能依据某个候选结果临时决定合并。新增回归测试及独立脚本均证明其现在明确报错，不再生成 N=0 的假评分。

上述追加脚本位于 `.local/audit/check_endpoint_invariance.py`、`check_invariant_scoring.py`、`check_cross_span_normalization.py`；完整路径穷举脚本也已扩展。全部只使用合成内容。

v2 最终独立复核：26 项项目测试全部通过，6,882 个完整路径跨度穷举、7 个计分反例和跨参考簇拒绝检查全部通过。可对已保存的开发输出统一重新评分；新分数须注明 v2，不能复用旧输出文件或把评分重算算作新推理。该结论不涉及任何实际候选的结果，也未读取保留集。
