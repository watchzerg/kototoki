## 1. 目标与本次复核结论

目标是找出值得投入的引擎、模型、aligner 组合，再通过有界调参选出适合后续实现的少数基准。“最优”指在公开记录的素材、资源和试验预算内得到的最佳可复现配置，不宣称全局最优。

用户提供的组合、暂不降噪的想法和 P95/P99 示例都是设计参考。评估方式由实际问题决定，优先级为：时间同步、识别完整性与准确度、稳定性，再到速度和部署成本。

本次复核做了以下调整：

- 不按 SRT 行号或句子数量比较识别准确性；一句拆两句、两句合一句，只要连续文字相同，就不产生文字识别扣分。
- 将文字识别、相同内容的时间位置、字幕断句与显示分别评分。合理合句不能直接判为 ASR/aligner 失败。
- 漏词、重复、幻觉、时间缺失与评测器无法确定对应关系分别统计，不能删除困难样本，也不能把所有匹配困难都归罪于模型。
- 500 ms/2 s 保留为初始目标；原来拟定的 CER 15%、删除率 2% 等缺少本地依据，不直接作为淘汰线。正式规则在开发集试跑后冻结，不能看了保留测试结果再修改。
- 先运行最新官方文档推荐的完整流程，再做必要的组件对照；保留自带 VAD/预处理，有依据时加入降噪、分离等消融实验。
- 整片推理不必每次重跑所有候选；先短片定位，再验证配置，最终只对入围者做整片和重复性测试。

评估公式、分母和判定规则以[配套评估标准](../testing/subtitle-timing-benchmark.md)为唯一依据。

## 2. 已知约束和版本原则

遵循[推理选型原则](../development/inference-selection.md)、[Windows 与 GPU 约束](../development/windows-nvidia.md)和[工具链约定](../development/toolchain.md)。最小 Python 评测环境与任务入口已开始建立，候选运行状态由运行记录维护。

- 所有音频、转写和推理保留在本机。ASR、aligner 及新增推理模型使用 GPU，不自动回退 CPU；普通文件、音频处理和评测算法可以使用 CPU。
- 优先完整 large-v3 和 Qwen 1.7B；不能只为方便安装而改小模型。显存不足先检查 batch、窗口和模型顺序驻留。
- 翻译不在范围内；说话人分离、LLM 润色和 UI 不是第一轮目标。
- 保持源文件不变；模型下载与离线推理分离，模型、缓存、私有音频和完整字幕不得进入 Git。

**实测启动时重新核查最新官方文档、模型卡、发布说明和迁移指南。** 选择与推荐 API 相符的最新稳定兼容实现，记录文档 URL、访问日期、源码 revision、模型/processor revision、转换来源和实际参数。旧调研中的版本仅作为证据快照。

如果最新文档写的是尚未发布的功能，需要明确标出文档与稳定包的差异；必要时另设开发版实验，不能把两者混为一谈。每轮比较冻结整个环境和配置，升级另开一轮，不在调参途中悄悄换版本。

## 3. 首轮候选和对照

| 编号 | 组合 | 用途 |
| --- | --- | --- |
| W0 | faster-whisper + large-v3 CT2 + 原生词时间 | 简单工程基准，观察不增加独立 aligner 时的效果 |
| W1-native | WhisperX + large-v3 + 日语 CTC aligner | 评估官方完整流程，包含其分段、VAD 和对齐 |
| W1 | 保存的 W0 文字与预测区间 + WhisperX 日语 CTC | 组件对照：在识别文字不变时，独立对齐能改善多少 |
| Q0 | 官方 Qwen3-ASR-1.7B + Qwen3-ForcedAligner-0.6B | 另一模型家族；便于检查 ASR 与 FA 各自的结果 |
| Q1 | Crisp + Qwen 1.7B GGUF f16 + FA GGUF f16 | 对比原生部署、转换精度和完整流程的收益 |

W1 和 W1-native 属于同一条候选路线。WhisperX 使用 faster-whisper 做识别，不应被当作另一个独立训练的 ASR 模型。日语 CTC 曾采用 `jonatasgrosman/wav2vec2-large-xlsr-53-japanese`，实测时按最新文档复核默认模型和兼容性。

Q0 采用届时官方推荐的接口和配套 checkpoint，可能是 native `-hf` 路线；不因旧调研采用旧 wrapper 就优先沿用。原 wrapper 可保留为诊断对照，不同依赖代际用独立环境。

只有发现具体问题才增加以下分支：

- W2：W0 文字 + 官方 Qwen FA，检查最佳识别和最佳对齐是否来自不同家族。
- Q1-q8：先固定 FA f16，只把基础 ASR 从 f16 换为 q8_0；不能同时量化两个模型而失去归因能力。
- large-v2、`anime.ja` 或 Qwen anime 微调：用于明确的动画识别短板；先核实 checkpoint、转换、训练数据和许可。`1.7b-amine-q8_0` 仍不能默认为某个下载 ID。
- turbo、小号 Qwen、whisper.cpp 等：只有质量基准暴露明确性能或部署缺口时再扩展。

这不是全排列试验，也不是提前宣布模型优劣。微调模型若可能训练过 FateStay 或其字幕，应标注潜在测试污染；来源不清的成绩不能当作独立泛化证据。

| 历史经验 | 本方案的处理 |
| --- | --- |
| Subtitle Edit 的引擎 writer、导入和 Adjust timings 都可能改时间 | 保存每层产物，不把最终 SRT 错位直接归到模型 |
| VideoLingo 的识别与对齐可能使用不同音频；文字匹配不等于声学对齐 | 分别记录 ASR/FA 的 PCM 身份，对照实验固定输入 |

| 窗口、VAD、标点等调整可能只改善局部案例 | 保留成对回归样本和独立测试集，不寻找万能参数 |

## 5. 预处理和对照原则

先比较各路线最新文档推荐的完整流程，再通过对照解释差异：

1. **原生流程**：相同源音频、相同目标任务，保留推荐预处理和分段。记录实际送入 ASR/FA 的音频，不能将结果差异全部归因于模型权重。
2. **组件对照**：固定实际 PCM、文字或预测窗口，只改变要研究的阶段。例如保存一次 W0 识别结果，再交不同 aligner；不用参考 SRT 边界帮助模型定位。
3. **有针对性的消融**：官方建议或开发集失败案例指向 VAD、降噪、人声分离、padding 时才测试。一次改变一个因素，同时检查弱语音遗漏、幻觉、音频延迟、显存和端到端耗时。

30 秒连续窗口可作为组件试验的初始共同条件，不是所有模型的最佳用法。原生流程允许使用自身合理上下文。关闭 VAD 不等于关闭 decoder 的无语音判断；部分 Crisp 版本还有独立的能量过滤。必须检查实际执行窗口和有效参数，不能只记录命令行开关。

如果接口无法接受共同控制，不大量改造上游来制造表面公平；标记该层不可直接对比，保留端到端评价。新增预处理模型同样需要记录版本、许可和 GPU 执行。

## 6. 数据和评估设计

后续轮次遵循[当前素材优先级](../testing/fatestay-reference.md)：II、III 的原版内嵌日文 SRT 为精确主参考，优先比较并逐片报告；I 的双语抽取 SRT 可信度较低，Black Panther 的日语配音/字幕可信度最低，两者仅作补充，不混入主排名。直接读取各影片目录已有的日语音频，Fate 为 `.jpn.flac`、Black Panther 为 `.jpn.eac3`，不重复提取视频音轨；按后端需求转换 PCM，记录哈希和时间映射，遵守前后 SRT SHA256 校验。

本轮已经完成的单片实测继续绑定原冻结输入和 scoring-v2。以下抽样预算为设计建议，新轮次需为两片主参考重新冻结分集及身份，不沿用旧 1,030 条 cue 作为新分母；既有测试和机器抽查片段均记录接触历史。原始显示时间与人工声学真值仍须区分。

- 先按场景分成调参、验证和保留测试集，同场景及其重叠上下文不得跨集合。目标约 200/150 条参考字幕用于开发/验证，其余保留；具体按场景和合格内容调整。
- 先抽查至少 40 个片段的参考文字、音视频原点和显示时间；确认是否存在非口述文字、系统性提前显示或延迟消失。
- 全范围保留原始 SRT 对照；另分层抽取约 200 个可听辨语音片段人工核对文字和发声起止，初始建议开发 60、验证 40、保留测试 100。数量是标注预算，不是“100 条即可证明 P99”。
- 语音、音乐、短弱语音、重复台词、重叠、静音和窗口边界分别报告。代表性样本与刻意挑选的困难样本分表，后者不能无权重混入总体统计。
- 全文 CER 忽略候选的句子/字幕切分；同内容时间用固定文本跨度映射；最终字幕的合句、拆句、跨静音显示单独评价。
- 原 SRT 显示偏移和人工声学偏移分开，不能平均成一个分数。错误很多的参考区域只作为弱参考，不能冒充精确声学真值。

具体匹配、计分例子、尾部不确定性和质量门槛见[评估标准](../testing/subtitle-timing-benchmark.md)。参考文字仅供评测，不能进入正常 ASR prompt、纠错或切窗。使用已知文字的 FA 诊断必须独立标识。

## 7. 实测阶段与退出条件

### 阶段 0：环境、参考和评测器预检

- 核查最新文档和现有资产；核对已分离音频、对应 SRT、可信度层级、源时间原点、PCM 参数和输入身份。
- 使用 mise/uv/just 建立最小 demo 环境。依赖冲突则分路线锁定环境，不强行合并，不修改全局 CUDA 来掩盖问题。
- 为模型、缓存和私有输出选择 `D:/movie/` 以外的 Git 忽略目录；验证忽略规则后再生成文件。
- 完成参考抽查和场景划分，记录标注能力与不确定性。没有可靠听辨条件时明确保留该缺口，不伪造声学标签。
- 用合成数据验证评测器：分句不变性、遗漏/重复、时间映射、失败分母，以及无法确定匹配时的处理。
- 在各路线执行短语音、静音和弱语音预检，分别证明 ASR/FA 的 GPU 执行、离线重载和资源释放。只看 GPU 列表不算通过。

退出条件：可复现的本机 GPU 配置与可信评测入口；阻塞的路线单独记录。显存不足先 batch 1、顺序 ASR/FA 驻留，再有依据地调整精度；不静默回退 CPU、WSL 或更小模型。

### 阶段 1：原生基线与故障定位

在开发场景先跑 W0、W1-native、Q0、Q1，保存实际参数、文字、时间单元、处理窗口、回退与 writer 输出。再做 W1 和必要的固定窗口对照；用少量人工核对文字测试 aligner 的潜力，但不得将这种 oracle-text 结果放进正常识别榜单。

保存原生字幕和统一最小 writer 字幕。前者代表完整使用体验，后者帮助隔离上游时间质量。检查问题首次出现于音频原点、识别、切窗、对齐、回退还是字幕组织。

完成开发集试跑后冻结评测配置：参考版本、匹配规则、阈值、质量保护线、候选晋级方法和最大试验数。不能等看过保留集再制定规则。

### 阶段 2：有界调参

每条主路线初始预算最多 12 个不同配置，包含基线、组件与原生对照；W1/W1-native 共用预算。每条路线最多两个配置进入验证，然后锁定一个测试配置。条件触发的跨家族分支最多另加四个开发配置。

| 优先顺序 | 可调因素 | 必须同时检查 |
| --- | --- | --- |
| 1 | 输入窗口、上下文、对齐搜索范围、padding | 切断语音、遗漏、重复、offset 恢复，不用参考边界切窗 |
| 2 | aligner 文本处理、日语分词、插值/回退 | 原文映射、时间来源、失败覆盖率，不能靠删字改善指标 |
| 3 | 实际生效的 decoding、语言、token 上限、context | 截断、重复、幻觉；不同框架不能套同一参数表 |
| 4 | 有证据支持的 VAD、降噪/分离对照 | 弱语音、音频变形和延迟、端到端成本 |
| 5 | 精度、batch、顺序/同时驻留 | 重新核对质量、实际 GPU 与总体峰值显存 |

可从 Whisper beam 1/5、窗口 15/30 秒，Qwen 窗口 30/60/120 秒，对齐 padding 0/0.25/0.5 秒开始选择少量有意义的试验；所有值须符合届时 API 和模型限制，不做这些参数的全排列。

优先调整一类因素，再用少量试验检查交互。没有改善就停止该方向，不为了用完预算而运行。FA/formatter 试验复用保存的上游产物；ASR 输入或参数改变才重跑 ASR。缓存身份绑定音频、窗口、模型和参数，缓存命中不能当作速度测量。

### 阶段 3：验证、保留测试和整片可靠性

验证集选择各路线最终配置；保留集只用于冻结后的比较。先发布所有入围者的完整分母、失败和不确定性，再对表现有价值的最多两条路线做整片运行。若验证无明显优胜且路线互有取舍，可保留更多候选，但必须记录扩大预算的理由。

整片结果用于检查累计漂移、边界衔接、长静音、内存、回退和长期稳定性；其中开发场景不算新的独立证据。全片与场景运行是不同上下文条件，必须标明，不能用后者的通过替代前者。

入围者在相同固定片段重复三次无缓存运行，检查输出变化和耗时波动；先做一次整片，只有不稳定、统计需要或未解决风险才重复整片，避免无理由三次全片成本。冷启动、warm ASR、FA、预处理、writer 和总体 RTF 分开记录，不让多个模型任务同时争用 GPU。

发现测试集故障可以进入下一轮修复，但那一轮必须标为已接触该测试集；新独立结论需要新保留数据，不能反复调到通过仍称盲测。

### 阶段 4：选择实施基准

按技术可运行性、时间尾部与完整性、文字质量、稳定性、成本依次决策，同时提供 Pareto 比较。统计证据相近时允许并列，不以几毫秒差异强行宣布冠军。

- 工程对照：优先保留 W0，即使其时间质量尚未达到字幕目标，也可以作为诊断基准。
- 时间优先路线：在 W0、W1、W1-native、Q0、Q1 或触发的跨家族组合中择优，不预设 FA 一定优胜。
- 原生部署备选：只有 Q1 展示实际质量或部署收益，才值得承担额外的转换与诊断成本。

最终原则上留下最多两个实施候选及一个已有诊断对照。可分别给出“工程可用”“时间目标达到”“证据不足/需扩大测试”结论。没有路线达到目标就报告最佳诊断配置和缺口，不包装成已验证的生产赢家。正式采用后再写 ADR。

## 8. 最小 demo 和交付物

只建设必要的本地 CLI/harness：输入清单 → 路线执行 → 原生结果 → 可选 FA → 源时间恢复 → 最小 writer → 评测。暂不建设 UI 或通用工作流系统。

统一 writer 保留文字和时间来源，冻结标点、停顿、分段规则，不按参考 SRT 强行断句，不通过删 text-only 段、截短时间或补满静音让输出看起来合法。原生 writer 的行为另存，避免掩盖框架实际体验。

交付环境/model/run manifest、分集和标注版本、匹配规则、最佳配置、失败分类、各项得分、最差案例、资源测量和选型理由。完整文本/音频只存本机被忽略的输出目录，Git 仅保存可公开的汇总和合成测试。

规划复核本身仅修改文档；后续执行证据见运行记录。文档校验通过不等于推理测试通过，GPU 性能和实际用时以真实运行记录为准。
