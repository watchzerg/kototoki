## 1. 要回答的问题与固定边界

本计划回答：在当前模型和原生 Windows／RTX 5080 条件下，怎样组织完整字幕翻译，才能在忠实度、自然度、跨批一致性、时间对应、可靠交付与总成本之间取得更好的取舍？“最优”只能相对于所测场景和资源约束成立；可能最终保留轻量、质量优先两种模式，而非强行选出唯一流程。

流程范围包含 SRT 解析、语义单元、上下文准备、分批、请求组装、推理、解析、跨批合并、可选修订和 SRT 写出。`runner`、`demo`、JSONL 都属于可更换的实现组成，不限制研究范围。[共同设计](../specs/subtitle-translation-common.md)和[Hy-MT2 草案](../specs/subtitle-translation-hy-mt2.md)提供已有假设，也可被本轮证据修订。

固定模型文件、revision、SHA256 与兼容 loader 身份，以[ADR-0005](../adr/0005-apex-i-compact-translation-baseline.md)为准；第一轮复用 llama.cpp b11429／CUDA 13.4 兼容引擎。模型换量化、微调／LoRA 属于另一轮选型，不能混入本轮流程收益。允许研究辅助步骤，但必须声明辅助模型、原文可见范围及全部成本，不能将其收益说成单独 Hy-MT2 的能力。

本文件保留起始计划；下面数值、优先级、架构和候选均为**待验证提案**，不代表执行结果。实施配方、冻结清单、预算和状态由探索台账及新输出目录维护，保留现有基线与历史结果。翻译仍是独立实验，不改变 STT 保留原语言的边界。

因此 `4096 − 1024 − 64 = 3008` 是当前应用的输入预算，三个数都不是 Hy-MT2 强制参数。1024 是最大输出量，不是每批必然消耗量。当前 `/completion` 未显式发送 `top_p`、`top_k` 等字段；不能把“没有发送”写成“关闭了这些采样器”。实施前记录服务端实际生效设置。

上述设计有合理的比较与交付动机，但已有量化比较主要证明的是固定流程下的模型取舍，**没有证明 7／5、重复 JSON、无记忆、4096／1024 最优**。原 83 窗及新增 1,200 窗已参与选择，只能再作开发／回归材料，不能重新称为未见保留集。[历史与选择边界](../adr/0005-apex-i-compact-translation-baseline.md#历史与后续回归)

## 3. 官方能力：区分提示变量、模板选项和推理参数

以下根据 2026-10-07 访问的 [30B 官方模型页](https://huggingface.co/tencent/Hy-MT2-30B-A3B/blob/main/README_CN.md)、[官方任务指令表](https://github.com/Tencent-Hunyuan/Hy-MT2#hy-mt2-translation-task-instruction-examples-chinese-english-comparison)与[技术报告 v1，§3.6](https://arxiv.org/html/2605.22064v1)整理。公开示例说明这些能力值得测试，不能直接推出 APEX 量化在日译中字幕上的通过率。

### 3.1 提示词中的控制能力

| 官方名称／变量 | 实际含义 | 有希望的字幕测试 | 主要反证／降级条件 |
| --- | --- | --- | --- |
| Default Translation／`source_text`、`target_lang` | 正文与目标语言的提示变量；语言名使用全称 | 原生单语义单元纯文本控制，明确“简体中文” | 请求开销、片段间一致性落后 |
| Terminology | 在正文前给源词与指定译法 | 人名、专有术语、重复口号；比较全表与本批命中项 | 同形词、敬称、作用域冲突；硬套译名改变含义 |
| Style／`target_style` | 目标文体提示 | 简洁自然对白、保留口语语气；比较最小风格约束 | 风格压过事实、角色语气被统一、过度压缩 |
| Personalization／`user_preferences` | 多条用户翻译要求 | 称呼／敬称策略、简体中文、占位符保护、字幕可读性 | 条件叠加后遵循度降低；彼此矛盾 |
| Delimiters | 要求保留分隔符数量与位置 | 低开销 ID＋分隔符、TSV／标记块协议 | 数量正确而归属错误；源文碰撞、符号转义 |
| Structured Data 1／`format_type` | 指定结构格式、选择性翻译可见值、保护非正文 | 最小 JSON／数组、XML、SRT 原格式；只改正文 | ID 值／时间码被改；结构保持不等于语义对应 |
| Structured Data 2／`background_text` | 背景段辅助翻译正文 | 局部邻文、源文场景卡、相关关系证据 | 背景诱发增译、提前揭示或错误主语 |

这些名称和 `{format_type}`、`{background_text}` 是**文本提示范式／占位变量**，不是向当前 HTTP 请求直接添加同名字段就能生效的模型 API。应用负责选择来源、渲染和校验；不要把所有条件一次堆入默认请求。源文、术语、背景均是数据，台词里的命令仍按台词翻译。

### 3.2 原生模板与 reasoning

30B 使用自己的 [chat_template.jinja](https://huggingface.co/tencent/Hy-MT2-30B-A3B/blob/main/chat_template.jinja)，当前适配包含 `<｜hy_User｜>`、`<｜hy_Assistant｜>`、`reasoning_effort:no_think` 和空 `<think></think>`。不能沿用 7B 的 `<|startoftext|>…<|extra_0|>` 包装，或在已套模板的内容外重复加模板。

该 30B 模板接受 `no_think`、`low`、`high`，默认 `no_think`；模板可表达 system／多轮信息，均不证明相应翻译模式更好。保留 no_think 为主控制；仅当疑难场景仍有稳定错误时，再给 low 模式一个有界兼容性试验。先确认引擎能区分 reasoning 与最终答案，输出预算计入 reasoning，GBNF 不会在思考阶段强制 JSON；不兼容则记录并停止该分支。high 不作为初轮必测项。

### 3.3 官方生成建议与长度口径

30B-A3B 官方推荐如下；**不是** 1.8B／7B 的另一套 `top_p=0.6`、`top_k=20`、`repetition_penalty=1.05`。[30B 推理说明](https://huggingface.co/tencent/Hy-MT2-30B-A3B/blob/main/README_CN.md#推理和部署)

```json
{"temperature":0.7,"top_p":1.0,"top_k":-1,"repetition_penalty":1.0,"max_tokens":4096}
```

官方 `max_tokens` 是生成上限；映射到当前 native `/completion` 时使用 `n_predict`，`repetition_penalty` 对应后端的 `repeat_penalty`。`top_k=-1` 表达不限制 top-k；执行前核对兼容引擎实际支持的等价值，并显式处理 `min_p`、采样器顺序等额外默认，避免所谓“官方参数”仍被其他采样器截断。[b11429 server 参数](https://github.com/ggml-org/llama.cpp/blob/b11429/tools/server/README.md#post-completion-given-a-prompt-it-returns-the-predicted-completion)

首轮将新候选的 `top_p=1.0`、禁用 top-k、`repeat_penalty=1.0` 固定为 30B 专属起点，不纳入常规参数网格，不另测 7B 推荐组合。固定的是本轮实验配置，不是把这些值写死在实现里；只有出现可复现的问题或新的依据时，再登记相关参数实验。原 B0 保留实际生效配置；若显式固定值与 B0 不同，先建立同提示、同预算的参数对照，避免把采样变化误归为格式收益。temperature 与输出预算仍可独立比较。

官方示例确实是 **`max_tokens:4096`（最多生成 4096 tokens）**，不是“输入＋输出总共 4096”。当前 demo 的 `context_size=4096` 和 `n_predict=1024` 是另一套应用配置。计划明确保留 4096 输出上限候选；测试前须保证 `实际输入 + 输出上限 + 余量 <= runtime context`，例如 context 8192、输出 4096、余量 64 时，输入预算为 4032。不能在总 context 仍为 4096 时直接预留 4096 输出并声称采用了可用的官方配方；容量／显存不足则报告该候选不可运行。输出上限与真实输出长度分别记录。

长度存在两个官方口径：GitHub 部署 README 写 `max_context: 8192`；30B [config.json](https://huggingface.co/tencent/Hy-MT2-30B-A3B/raw/main/config.json)写 `max_position_embeddings: 262144`。两者都记录，不能选较大数宣布可用 262K。前者是公开部署说明，后者是位置配置；APEX GGUF／本机 loader 的真实容量、长文质量与显存稳定性另测。[部署原文](https://github.com/Tencent-Hunyuan/Hy-MT2#inference-and-deployment)

当前 4096 是实测起点。先在 4096 下优化信息密度，再按条件试 6144／8192；通过显存、截断、归属和长文质量门槛后，才另立超 8192 的探索。基线长跑最低空闲仅 255 MiB，扩大 context、并发和 KV 配置要分别验证，不能自动降层／回退 CPU后仍声称相同配置。[当前资源证据](../adr/0005-apex-i-compact-translation-baseline.md#采纳理由与已知代价)

## 4. 完整 SRT→SRT：先建立比较对象，再允许换结构

完整候选的逻辑流程如下，阶段可合并、删除或重排；只有不可变来源、覆盖记账和可追溯交付是共同底线：

```text
jpn.srt → 源 cue／时间身份 → 单元与上下文策略 → 批次与输出预算
        → 原生请求／生成 → 结构与归属检查 → 有界恢复／可选修订
        → 全片结果合并／一致性检查 → 显示与时间映射 → chn.srt＋sidecar
```

1. 读取编码、序号、起止时间、正文、标签和多行信息；保存输入哈希，建立稳定 cue ID。重复序号、空项、异常时间、多说话人和歌曲须按明确政策记账。清理产生副本与映射，不能覆盖原文或静默删除内容。
2. 冻结源跨度、正文范围与排除理由。区分“字幕显示 cue”“翻译语义单元”“一次请求批次”；三者可一对一，也可不同。上下文重复读取不计作再次翻译。
3. 建立最小全片控制 `B0-SRT`：仅补源 SRT 解析、覆盖完整的固定目标块与导出；翻译继续使用当前重复 JSON／GBNF／生成配方。其前后原文作为只读重叠，目标块不重叠，覆盖开头、结尾和尾批。不要照搬评测抽样的 7 条块而漏掉每块两条上下文。
4. `B0-SRT` 是新建的端到端控制，不是已经实测的基线产品。现有冻结窗 `B0-window` 原样保留，用于隔离提示／调用变化；所有全片候选与 B0-SRT 同跑，包含其新包装成本。
5. 合并由全局目标 ID／源跨度和 attempt 身份驱动；正常目标唯一归属，重试只选符合冻结规则的有效结果。覆盖缺失、冲突、重复、来源不明均不能用按顺序 zip、复制整段或原文回填伪装成功。
6. 第一条显示控制保留源 cue 时间，程序写 SRT；直接 SRT 路径也要逐项验证原时间未改。重新分段另设显示协议，保留完整译文及源／目标跨度；语序调整不等于可以任意搬动到不同时间。
7. 若只有 cue 级时间，细粒度新中文时间没有声学证据；不得按字数声称精确同步，也不能把中文对齐到日语音频证明内容时刻。显示质量、语义归属、时间来源分别报告。
8. 只在声明范围完整交付时输出成功 `chn.srt`；部分结果另标 partial 并附失败清单。保存运行配方、原始返回、解析记录、重试、SRT 映射和 sidecar，支持断点恢复与复核。

## 5. 探索空间与可证伪假设

下面是候选池，不是全组合任务清单。每轮选择收益可解释、实现可检验的少量分支；当前 n+m+n 可以保留、变为非对称、动态选择，也可以彻底取消。

### 5.1 交互与输出格式

| 编号／方向 | 具体候选 | 预期收益与必须观察的失败 |
| --- | --- | --- |
| F1 去重复 | 前文＋待译 JSON＋后文，各条只出现一次 | 减少 tokens／prefill；可能弱化正文聚焦；同信息同目标配对 |
| F2 单份上下文 | 一份带 ID 原文＋目标 ID 列表，返回最小 ID→中文 | 更紧凑；可能译出只读项或遗漏目标 |
| F3 最小结构 | ID 键控对象、`id/text` 数组、紧凑 JSON；对照当前较长指令 | 减少格式／说明成本；测 key 保持、ID 值保持和语义串项 |
| F4 单单元纯文本 | 程序绑定请求 ID，模型只生成译文，可带官方背景范式 | 取消模型生成 ID 负担；独立请求成本和句间连贯性可能变差 |
| F5 分隔协议 | ID＋唯一分隔符、TSV、XML／标记块 | 降低 JSON 开销；须转义源文碰撞，检查 ID及内容归属而非仅数量 |
| F6 直接 SRT | 一个块或场景的 SRT＋结构保持要求，仅改正文 | 减少中间映射；模型处理时间／序号额外成本、擅改、长输出失败 |
| F7 段落先译后映射 | 完整话轮／场景自由译文，再映射到源跨度 | 允许中文自然重排；映射成本、不可归属和错误时间安放可能抵消收益 |
| F8 输出约束强弱 | 同 prompt 比较固定 ID GBNF、较松 JSON grammar、无 grammar严格校验 | 结构成功率与恢复成本；约束改变生成分布或强制填值掩盖遗漏 |

F7 的映射器不能改写初译；若允许映射时后编辑，另设组合候选、保留每版文本。若重排导致不能可靠拆回单 cue，可交付有源跨度的较大显示单元，但需按相应契约评价，不能套用旧逐 ID 校验得分。重复 ID 约束、非空字符串等都不能证明内容正确。

GBNF／schema只约束生成，不自动告诉模型任务格式；预期输出结构仍须在提示中说明。支持范围以兼容引擎实测为准。[b11429 grammar说明](https://github.com/ggml-org/llama.cpp/blob/b11429/grammars/README.md#json-schemas--gbnf)

### 5.2 分段、批量与 n+m+n 的替代

| 方向 | 有界候选 | 区分什么问题 |
| --- | --- | --- |
| 上下文大小／方向 | 无邻文、前1后1、前2后2；疑难组再比较前4后0／前0后4／动态检索 | 前文、后文、对称性各自贡献；更长可能无效或泄露揭示 |
| 正文大小 | 当前目标数控制；正文 token 档位如 256／512／1024 | 吞吐、接缝、输出归属、长尾恢复；条数不是硬容量 |
| 完整句／话轮单元 | 原 cue控制；规则合并连续碎句；源文模型提出边界后程序验证 | “共同理解、分别交付”是否优于“每个值独立” |
| 自然边界打包 | 标点、话轮、时间间隔、场景提示＋token上限 | 固定窗是否切断否定、条件、问答；不能把未知换人当已知 |
| 单次大场景／更长段落 | 通过容量检查后放大请求；必要时自适应小块 | 全局连贯性是否改善，长输出失败／定位与修复成本是否增加 |
| 接缝策略 | 仅原文重叠、边界依赖组扩大、重叠初译再选择／复核 | 边界漏译、重复与前后不同译法；重叠输出需唯一最终版本 |

固定格式试验先保持同一信息与目标范围；分段试验保持同一源覆盖，改变单元或批次。信息范围和格式一起改的全流程试验单独标记，不能把扩大上下文的收益归因为 JSON 格式。

### 5.3 背景、术语、风格、记忆与一致性

1. **背景来源对照：**局部完整原文、较远原文检索、源文场景卡、全片源文预分析；比较原文与压缩摘要，保存证据 IDs、不确定项和适用范围。模型不确定的关系不能被摘要固定成事实。
2. **术语作用域：**无表控制、用户已有术语、只基于日文抽取的候选表；比较全片表和本批命中表。测人名／别名／敬称／同形词／首次揭示；背景只帮助解释，不应提前把未知人物写成已知姓名。
3. **风格与偏好：**一次只增加一个明确条件，再比较有收益的组合；例如自然口语、保留人物语气、字幕简洁、敬称策略。用漏义和关系改变约束“简洁”，不将与中文参考词句相似当质量。
4. **显式记忆：**每批新请求＋静态术语；相关已接受句对；源文场景事实；场景级滚动记忆；连续聊天作为独立后续对照。句对来源必须有版本，不能把未经检查的初译当事实循环强化。
5. **全片一致性检查：**先并行／独立初译，再查跨批译名、重复表达和角色称呼；与顺序记忆比较。修复按源文决定，不做全局字符串替换；统计修复带来的新错。
6. **准备步骤能力验证：**Hy-MT2 能翻译不代表擅长摘要、实体抽取、审校和映射；分别做任务资格检查。若引入其他本地模型，保留 Hy-only 与 assisted 两条身份，计算冷加载、切换和准备成本。

这些步骤不必全部存在于最终流程。源文全文知识可辅助理解，但任何情节事实都必须服从当前台词的表达与不确定性；不得引用作品百科或裁判记忆补齐剧情。

### 5.4 输出预算、解码与运行效率

| 类别 | 起始对照与后续方向 | 接受前检查 |
| --- | --- | --- |
| 解码 | B0原样；新候选固定30B的top_p1／禁用top-k／repeat_penalty1，比较temperature0／0.2／官方0.7 | 参数显式化先与B0对账；不引入7B参数网格；非零温度用至少3个预冻结seed测均值／方差，不挑最佳seed |
| 输出预算 | 当前1024、容量允许时的官方4096、按正文token＋ID／格式开销估算的动态上限 | 同输入、同runtime context下比较输出上限；扩容成本另记；记录实际输出、停止原因和p95，不能以平均长度避免截断 |
| context与余量 | 4096控制，条件试6144／8192；固定64与保守动态余量比较 | 总预算包括全部包装、背景、重复与reasoning；严禁静默截掉必要上下文 |
| 重复／停止 | 正确EOS与显式stop；仅有重复病理证据再试轻度惩罚 | 真正重复台词、代词和术语不能被惩罚漏掉；记录后端生效参数 |
| 前缀缓存 | 排好稳定指令／术语前缀后试 `cache_prompt` | 计算复用不等于聊天记忆；冷／暖分别计时，检查质量和重复性 |
| 请求调度 | 单槽控制，资源允许后试2槽；区分联合翻译与独立并发 | 每槽有效context、KV与VRAM；顺序记忆不可假装无依赖并发 |
| 内核参数 | batch／ubatch、线程、Flash Attention、KV f16／条件试q8 | 不是字幕条数；改变KV精度需质量回归；测OOM、shared／paging及总墙钟 |
| 其他加速 | 流式接收、tokenize复用、候选prefill、后续兼容speculative decoding | 流式是交付延迟变量，不自动提升吞吐；额外模型资源／输出分布另验证 |

采样器、KV和并发先做兼容／资源门槛，后做质量比较；引擎升级或替换若确有必要，另立 runtime identity 并重跑同输入控制。缓存可能因不同batch计算引入非位级一致结果，不能仅凭固定seed承诺完全重复。[缓存官方说明](https://github.com/ggml-org/llama.cpp/blob/b11429/tools/server/README.md#post-completion-given-a-prompt-it-returns-the-predicted-completion)

### 5.5 恢复、定向修订与尚未列出的方向

当前重复同一确定性请求未必能修复稳定内容错误。比较：原样有限重试；结构失败局部修复；超预算／触顶后按语义依赖组缩批；歧义扩大原文上下文；仅异常段重译；按需审校；全量后编辑作为高成本控制。先限制一轮审校＋一轮修订，设原批总请求／tokens／墙钟上限，留存全部失败。

检测与修订是不同能力：自动风险规则会漏报／误报，同模型自审可能重复旧错。用dev测“改正旧错”“引入新错”“无必要改动”和未解决问题，再决定是否启用。正式评测的中文参考、评分和裁判反馈不得传回这些步骤。

其他可登记方向包括重复对白的受控缓存、相关少样本例子、依语义风险调节批量／背景、初译多候选后按源文选优、只在必要处恢复标签／标点、提示段次序与长度消融。新方向需写清依据、可测收益、完整交付规则和成本；少样本及选择器不得读保留集参考。尚无证据的复杂编排不进入默认全流程。

## 6. 分阶段实验：小样本控制变量与有限全片验证

**用户明确约束：任何阶段都不得使用全测试集合横向比较。** 上次四模型比较耗时约13小时并消耗大量tokens；本轮不重复这种规模。广泛列举探索方向不等于承诺全部执行，不做参数／模式的笛卡尔积，不以“正式验证”或“完整分母”为理由扩成全库运行。完整分母只指本轮预先选定的小集合。

### 6.1 控制变量与候选数量

每个实验卡记录假设、唯一主要变化、固定项、样本IDs、对照配方、晋级与停止标准，以及调用／token／时间预算。同一轮固定模型、runtime、源范围、目标范围、解码、评估规则；测试其中某项时才改变它。格式先用相同信息比较；容量变化和输出上限变化分开；无法分开的复合变更明确标记，不能声称单变量收益。

每轮默认只有**一个对照＋一个候选**，最多再加一个有明确理由的候选。每个探索主题先做一轮，最多两轮小筛；没有清晰信号就搁置，不轮番跑遍候选池。只有单项已显示优势，或有具体失败证据表明存在交互，才试最多2×2的小矩阵，并复用同条件的已有结果。预算按整个阶段累计，不能用不断新建小轮次绕过上限。

| 阶段 | 建议规模与执行方式 | 晋级／停止条件 |
| --- | --- | --- |
| P0事实与契约 | 核对资产／模板／参数，建立B0-SRT；合成检查＋4–6个真实开发组，最多对照＋1候选 | 仅确认接口、覆盖、归属和成本；不作质量排名 |
| P1单变量小筛 | 固定12–20个开发依赖组；普通对白与疑难组分开报告；每轮对照＋1候选，最多3配方 | 出现可解释、跨多个组重复的质量或总成本优势，且无明显严重退化才晋级；微小均分波动不晋级 |
| P2独立小样本确认 | 对照＋最多2个晋级配方；另选24–40个未用于该轮调参的组，覆盖少量不同作品 | 优势方向重复，完整交付／严重错误无明显退化；否则停止或回开发，不扩大集合“寻找显著性” |
| P3有限组合 | 最多2个有依据的组合与对照比较，先复用P1小集合；只对最有希望者做P2式确认 | 分辨协同与抵消，留下至多1个主候选；确有质量／速度两种取舍时可留2个 |
| P4少量高质量全片 | 先只选1部高质量来源的完整剧集单集或电影，对照＋1个主候选；首部通过后最多再加1部不同作品 | 每部全部字幕推理与机械检查；核验接缝、早中晚一致性、SRT交付及总成本；不运行全测试集合 |
| P5有限保留验证 | 优先让P4的第2部作为事前隔离的验证作品，避免重复全片运行；无法保留时选小规模隔离片段 | 配方、抽样和阈值事前冻结，原样验证；数据不足则限制结论，不扩成全库 |
| P6结论与采纳 | 汇总单变量证据、有限全片结果与取舍；无明确优势则保留基线 | 不强求最优结论，不为凑结论追加测试 |

这些样本数是执行起点，须结合P0实测成本在运行前向下收紧；不构成扩大运行的默认授权。P1–P3质量评估继续采用既定自动流程，但只评价该轮选定的小样本，不先生成全库结果再抽样。非零温度的3-seed稳定性检查、重复计时先限定在晋级方案的小集合，不要求每个全片配方跑3遍。

“明显有优势”至少满足：改善不只来自一个幸运样本或一个seed；普通组没有被疑难组收益掩盖；新增严重错／遗漏和完整交付没有明显退化；包含恢复与辅助步骤后仍有质量或成本收益。P2按原样配方确认方向。具体最低有意义差异在看该轮结果前写入实验卡，小样本只能支持筛选，不据此宣布普遍最优。

### 6.2 预算、复用与及时停止

先用P0测量单组翻译、主评、复评和裁决成本，再估计本轮与整个阶段的调用数、输入／输出tokens及墙钟；同时计入参考准备、术语／摘要、映射、重试和修订。语义调用估算不能只算初次主评，须给风险窗并集和争议裁决留预算。平台不暴露实际tokens时记录估算及其依据，仍以可观测调用数／墙钟设硬上限。

每阶段预先保存 `max_translation_calls`、`max_judge_calls`、`max_estimated_tokens`、`max_wall_seconds` 和剩余额度；额度须依据实测写成具体数值，未填写不启动。调度按最坏剩余复评／裁决成本预留，不能以“快做完了”为由自动突破。到达任一上限即停止新增工作，保留已完成结果和未决状态，不悄悄省掉必需复评并宣称完整。

源文、prompt、模型、全部生效参数、seed、上下文／memory、代码版本一致的对照输出可复用，保存身份和原始证据；性能比较需要同条件新计时时只重跑小集合。参考和裁判packet完全相同且符合盲评契约时可复用已有判断；新增候选导致风险复评并集扩大时，只补缺少的复评，不把旧分数塞给新的评审请求。配方变更或记忆状态改变不得复用不匹配结果。

不支持loader、覆盖无法校验、明显质量退化的分支及时停止；最多两轮小筛仍无清晰收益就搁置。新方向登记依据后排优先级，必须替换或共享既有阶段预算，不能无限增加轮次。

### 6.3 高质量来源、全片范围与保留边界

“全片测试”指**选定1–2部作品的全部字幕实际翻译与全量机械检查**，不等于全语料库，也不默认逐条全片LLM评分。进入P4前核对日文来源、中文参考可用范围、时间／轨道对应和既有复核质量；全片参考未经核验，不能因已有SRT就称高质量金标准。优先复用已可靠核验的来源，不为本轮额外重建大规模参考库。

全片语义评估事前冻结少量共同窗口：每部先选12–20个覆盖早中晚／场景与接缝的分层窗口，另列术语／跨批一致性诊断。对照与候选用同一源范围，必需盲复评和风险并集仍在这份评分清单内完成。清单外机械风险保留完整记录，需追加语义诊断时从预留预算中安排并单列，不能混进概率样本均分。若预算不足以支持所需质量结论，报告证据不足；不得宣称全片语义已全量验证。

筛选集覆盖普通对白、日文省略、跨cue否定／条件、换人、数量、人名／敬称、重复短句、多行／标签、长句和尾批；不要求每一小轮囊括所有类型，但晋级确认必须覆盖对应风险。风险精选与概率样本分开，不合成无偏总体均值。

保留作品／片段提前隔离，优先跨作品／系列；冻结清单、哈希、评分范围与允许上下文。原83窗／新增1,200窗只从中选小子集作开发或回归，**不全量重跑**，也不能称未见保留集。新参考准备者不看候选结果；参考、裁判意见不得进入翻译、背景或术语构造。只有1–2部作品时不作跨作品总体优胜的强统计结论。

## 7. 公平比较、评估与“更好”的判定

**两条比较轨：**格式／调用层消融沿用相同可见日文与目标范围，可作为新的 `V2-native-adapted` 配方；全文、场景卡、额外术语、记忆、重分段和反思属于 `P-flow`。P-flow 内各流程使用相同可访问源范围／允许辅助来源，但允许不同选择策略；记录实际读取范围，差异本身属于流程效应。不能将P-flow分数直接宣称为旧窗口模型能力提升。

全流程质量在冻结的共同源范围上评价，输出可用不同分段。重分段先冻结源／目标跨度评价契约，再建统一packet；上下文不计分，目标不得丢失。映射无法判断是 `mapping_unjudgeable`／null；违反自身交付契约是交付失败；评测映射配置错误阻止可比统计，不能混成翻译零分。[映射与分轨规则](../agents/subtitle-translation-evaluation.md#1-mechanical-checks-and-source-mapping)

仅对本轮预先冻结的评分小集合遵循 [sol-high-auto-v1](../agents/subtitle-translation-evaluation.md)：所选输入／全片输出全量机械检查；`gpt-6.1-sol / high` 对评分小集合全量主评；全新同模型请求盲复评（固定20%作品内抽样＋各候选风险窗并集）；必要时一次有界裁决；程序汇总。不安排人工日语复核。裁判隐藏模式名、价格、速度和旧分；参考不是唯一正确措辞，判据以给定原文为准。复评是同模型核查，不能称作独立金标准。

输入隔离：中文参考、原中文字幕、裁判反馈和候选身份映射只给评估侧；翻译、源文预分析、术语准备、记忆、映射修订和反思不得读这些材料。参考库修订另立版本，对所有候选一致重评。默认本地推理，任何新外部服务／上传另按有效授权处理。

| 维度 | 必须报告 | 不能用于掩盖问题的做法 |
| --- | --- | --- |
| 忠实度／严重错 | 分作品、电影／剧集的语义0–4；遗漏、增译、否定、关系、数量、major／critical | 只报可评分成功子集；自然度加权抵消错意 |
| 自然度／一致性 | 自然度0–2单列；称呼／术语跨批变化、场景连续性错误 | 奖励参考措辞模仿；将有理由的称呼变化视为必错 |
| 完整交付 | 全分母、缺ID、失败、未处理、格式／映射不可评、恢复后覆盖 | 原文／空串回填算成功；删除难窗、重复长译文补齐 |
| 显示／时间 | 原时间保留、源跨度、输出可解析；重叠、阅读速度／行宽等诊断 | 无显示profile就虚构通过阈值；文字评分证明音画同步 |
| 效率／资源 | 冷加载、准备、prefill、生成、映射、审校、重试、导出、总墙钟；峰值与最低余量 | 仅tokens/s；漏掉辅助步骤、OOM／失败耗时、模型切换 |
| 稳定性 | p50／p95批耗时，整片早中晚退化、多轮、seed波动、恢复一致性 | 最快一轮或最佳seed代替典型表现；缺测填估计值 |

统计以作品等权，电影和剧集分别报告；保留完整预期分母。语义缺分按0／4替代给上下界，自然度显示有效覆盖；不能把judge失败当译文失败。配对区间在作品／系列层重采样，保留候选配对，不能把相邻cue当独立样本。控制多重筛选；保留验证前冻结主比较、最低有意义差异和非劣门槛，未冻结不得事后以“小涨分”宣布胜出。

建议先满足交付／来源／映射硬门槛，再画质量—总耗时—资源的Pareto集合。轻量模式可用质量非劣、严重错／交付无退化且成本明显降低为目标；质量模式要求语义或严重错误有稳定改善并披露成本。具体差异阈值根据开发波动在P5前冻结；信号小、区间交叠或缺分改变排名时，结论为证据不足，不宣称全局最优。

## 8. 运行产物、长跑和完成条件

每种模式保存：模型／引擎身份、源与参考冻结哈希、prompt／模板／grammar版本、完整生效采样设置、分段与映射、context来源／记忆版本、每次调用tokens与停止原因、原始响应、解析错误、attempt树、缓存状态、SRT／sidecar和成本ledger。原始字幕与大产物留ignored运行目录，不进Git；报告用合成例子或ID说明。

晋级后的长跑只覆盖第6节选定的1–2部作品，逐部执行全部字幕，不跑全测试集合，也不默认多轮重复全片：记录显存／shared及paging证据、耗时漂移、服务重启、断点恢复、重复输出、尾批与不可恢复项。故障注入另做离线／接口验证：超时、截断、乱序返回、重复ID、写出中断、memory版本改变。缓存键包括源哈希、模型、所有流程／prompt设置与记忆；旧配方结果不能当新配方已完成。

本计划的完成条件是：有端到端控制和若干明确命名的候选；有同范围消融和全片证据；有未参与选择的冻结验证及完整失败／成本；有可复现Pareto取舍和剩余限制。可以得出“保留当前翻译核心”“更换交互协议”“分两种模式”或“仍无足够证据”，不预设某个增强一定有用。

当前执行进度以[探索台账](../context/2026-10-07-hy30-flow-exploration.md)为准。接跑先核对[工具链](../development/toolchain.md)、[Windows／GPU约束](../development/windows-nvidia.md)、[评估入口](../testing/translation-model-evaluation.md)及实际冻结产物；本文件不代表候选已采用。
