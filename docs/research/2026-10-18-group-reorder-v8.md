# 字幕翻译流程第八轮探索（v8）：同一句话小组内语序重排——方案、进度与结论

状态：proposed（2026-10-18 立项，等待执行会话；§7 空）  
范围：固定 Hy-MT2 30B-A3B APEX-I-Compact（[ADR-0005](../adr/0005-apex-i-compact-translation-baseline.md)）与流程基线 **dp10-cut**（[ADR-0010](../adr/0010-dp10-cut-translation-flow-baseline.md)）。本轮只动一件事：**在包内按"同一句话"小组放开语序**，即改 joint 提示里限制逐 ID 归属的那一句，并把小组告诉模型。不换模型、不换量化、不换采样、不换裁判、不改切包与邻文、不改 grammar、不自动替换任何基线；单次生成，不涉及"翻译多次再挑选"（[ADR-0008](../adr/0008-no-multi-translation-selection.md)）。  
执行载体：tracker 目录 `.scratch/group-reorder-v8/`（spec、map、票据；Git 忽略）。**本文是唯一进 Git 的进度与结论记录。**

本文与 v7 的分工相同：划组规则、提示形状、变体数与评测设计已在 2026-10-18 的讨论中定下（§4），执行者只填实现细节（提示的最终措辞、`groups` 注入格式、重排率与校验器的具体阈值）并在票据里说明理由。

## 1. 为什么做这一轮

现在的流程逐条翻译：每条中文直接继承那条日文的编号与时间，joint 提示明确要求"每个值只承载对应源 ID，不搬运邻条事实、不提前补完后文"。日文一句话常被拆成 2～3 行字幕，中日语序不同，逐 ID 对应时模型只能把中文硬拆成与日文行一一对应的碎片，是生硬、翻译腔的一个来源。

技术设计 §11 已经把方向定下：**包的大小决定理解范围，内容可挪动的范围另按"同一句话"划分**；停顿是硬边界，内容不能跨停顿挪动，否则字幕出现在无人说话的时刻。v7 的 Q3 为此验证了"按 <1 s 小组拼包不劣于直接拼"，dp10-cut 又保证了 68%（dev）／95%（产品）的切点落在 ≥1 s 停顿上。[离线统计](2026-10-18-reorder-group-offline-stats.md)则把划组规则定了下来。前置条件都齐了，这一轮直接做 GPU 变体。

需要同时承认的反面：

- 这条线的收益预期在 **fluency**，不在 accuracy。v3 以来 accuracy 的差异多在噪声内，本轮若只看 accuracy，大概率得到"非劣、无改善"。
- 模型可能无视提示：Hy-MT2 在 ID JSON 约束下是否会真的在组内挪内容，没有任何证据。所以本轮必须先回答"重排是否发生"，再谈质量。
- v5 第 2 步：产品中文错误约四分之三来自 ASR，翻译侧在产品输入上的收益上限有限。本轮的价值是把 §11 这条线做成可复现的肯定或否定，并留下可复用的划组与校验设施。

## 2. 已知事实（不要重复）

### 2.1 基线里已经为此留好的接缝

- **joint 提示**（`joint-understanding-v1`）只有一句是本轮的对立面："每个值只承载对应源 ID，不搬运邻条事实、不提前补完后文"。前半句"先共同理解全部可见台词……再分别表达各源 ID 的信息"与"保留原文歧义和信息揭示顺序"保留。
- **ID JSON grammar** 要求每个目标 ID 按原顺序各出现一次、字符串非空。组内挪内容不违反它：输出契约、SRT 回填、双语合并都不用改。grammar 禁止空字符串，所以"并句后某条留空"不可能发生，模型只能给每条都留内容。
- **裁判** `claude-opus-5-5-mqm-v1` 规则 3：源句跨多条 cue 时，相邻 cue 之间断句位置不同、信息完整且顺序不误导，不算 cue-attribution；内容移到相邻 cue 不算 omission；只有落到错误说话人或错误时间点才记 cue-attribution（major）。所以"严格一一对应"与"组内重排"可在同一把尺子下配对比较，裁判不改。
- **划组实现**：v7 的 `batching.gap_groups`（停顿 <1 s 连续 cue）可复用思路；本轮的规则加了标点条件，在 [`experiments/reorder_groups/stats.py`](../../experiments/reorder_groups/stats.py) 里已有实现与测试。
- **产品降级** 10→5→1：单条批次没有小组，等价于现在的严格模式，不需要另写分支。

### 2.2 来自离线统计（dev 5397 条、产品 HF II／III 2318 条，切包固定为 dp10-cut）

- **规则 R2+**（停顿 <门槛，且前一行去掉行尾空白与右括号后不以 `。？！?!.` 结尾）。字面全角 `。？！` 在产品上无效：产品 `ja.srt` 的句末标点几乎全是半角 `? !`，全角 `。` 只占 1.2%。R2+ 拆开的 R1 连接对 dev 13.2%、产品 11.5%。
- **门槛 1.0 s** 时 dev 有 78% 的 cue 落在多 cue 小组（剧集 80%、电影 74%），0.8 s 为 72%、1.5 s 为 84%，没有拐点；剧集与电影覆盖率接近，不需要按类别分门槛。**产品只有 50%**，要到 2.0 s 才与 dev 的 1.0 s 相当。
- **小组大小**：按组数 dev 上 1 条 49%、2 条 22%、3 条 11.5%、4+ 条 17%；但按 cue 数 4+ 条的大组覆盖 42%（最大就是整包 10 条）。产品上 4+ 条组只覆盖 8%，最大 7 条。§11"多数是 2～3 行"只按组数成立。
- **被包边界截断的小组**：包内划组等价于接受截断。dev 上整片 R2+ 的多 cue 组有 14.3% 被 dp10-cut 切点截断（其中约 11.9% 可避免，即 ≤10 条的多 cue 组），涉及 23% 的 cue；产品只有 2.9% 的组、2.5% 的 cue。
- **说话人切换的残余风险**（文本代理，不是标注）：停顿 <1 s 的相邻对里"前行问句、下行新话头"占 dev 8.6%、产品 4.8%，R2+ 把它们全部拆开；R2+ 之后仍相连且下行以答语词（はい、ああ、うん……）开头的占 dev 5.6%、产品 1.9%。
- `…` 结尾占 dev／产品 cue 的 5.7%／6.0%，统计里没有把它当句末。

### 2.3 产品时间轴与研究集时间轴不同

同 v7 §2.3：产品时间轴贴着说话边界，1–2 s 的小停顿比字幕组时间轴多一倍。本轮的 dev 结论对应的是"78% 的 cue 可重排"，产品上同一门槛只有 50%；产品是否放宽门槛是独立变体（§4.6），不改默认。

### 2.4 其他约束

- 翻译 run 显存峰值 15.5–15.9 GiB，余量 100–260 MiB；每批可见 cue 数上限保持 12，不得增大。`groups` 注入会增加少量输入 token（每包一行），执行者记录。
- **dp10-cut 没有任何 GPU run 和裁判分数**（ADR-0010 按逻辑推定采纳）。本轮的对照必须新生成，顺带得到 dp10-cut 的第一份质量数字；它只用于与候选配对，不回头与 b10-joint 比较。
- v3、v4、v5（剧集）确认集已开封；需要确认时从评测库 v2 盘点未用区间新建隔离集合，候选锁定后再生成。
- `translation_v3.Recipe` 加字段必须保持已有配方 hash 不变（`gap_split`、`gap_pack`、`pause_marks` 的做法与 `test_recipes.AdoptedBaselineTest`）。
- 产品 `kototoki/` 的翻译配方为 `b10-joint-degrade-v1`；本轮只在实验包评测，是否进产品另行裁定。
- 冻结的 C0 文本（`C0_INSTRUCTION`）不改；新提示以版本号替换 joint 句子，与 `joint-understanding-v1` 的做法相同。

## 3. 本轮要回答的问题

1. **Q1 模型是否真的在组内重排**：给出 `groups` 和放开的提示后，多 cue 小组里有多大比例的输出与严格对照的逐条归属不同（§4.4 重排率），人工抽查这些差异是否是"按中文语序重新分配"而不是乱动。重排率接近零即本轮否定结束：提示级放开对这个模型无效，备选路线见 §8。
2. **Q2 质量**：相对 dp10-cut（同包组成、同期裁判），全集 accuracy 是否非劣（剧集、电影分开，非劣界 0.05），**fluency**（grammar、unnatural、register）是否下降，cue-attribution 是否上升。只有多 cue 小组里的 cue 会变，单条小组的译文应与对照逐字相同（固定 seed 与 `cache_prompt`，v6 §2.1），执行者核对。
3. **Q3 显示风险**：组内重排是否造成失衡（整句塞进第一条、后面留尾巴）。用 §4.5 的校验器在候选与对照上各报一次读速与占比偏差的分布；裁判看不到时间，这是裁判之外唯一的新终点。
4. **Q4 是否值得成为研究侧默认**：采纳标准是 **accuracy 两次都非劣、fluency 至少一次改善且另一次不变差、cue-attribution 不升、critical 不增、交付完整、校验器标记率不高于对照的 1.5 倍**。改善的说法只有两次都为负才写进结论。多个条件只满足一部分时交 §8 由用户裁定，执行者不自行替换默认。

成功的定义是**四个问题都有带区间的答案**，其中 Q1 若为否，Q2–Q4 可省略。

## 4. 已定的设计（2026-10-18 讨论结论，执行者不再重选）

### 4.1 划组规则

- 包切好之后，只在**每个包的目标 cue 范围内**划组，不跨包；只读邻文永远不入组。批次组成因此与 dp10-cut 完全一致，逐条配对天然对齐。
- 规则 **R2+**：相邻两条停顿 <**1.0 s**（严格小于；重叠即停顿 <0 也算相连；缺时间戳按无停顿）**且**前一行去掉行尾空白与右括号／引号（`」』）)】〕"'”’`）后不以 `。？！?!.` 结尾。
- `…` 与 `、` 不算句末，保持相连。
- 大组**不设上限**，最大即整包。
- 不做 R3（答语词开头不连）。
- 门槛不随剧集／电影变化；1.0 s 以外的门槛、上限、R3、`…` 算句末都登记为变体（§4.6），本轮不跑。
- 单条小组不注入、不提示，与对照逐字相同。

### 4.2 提示：`joint-understanding-v2`

- 只替换 `joint-understanding-v1` 的归属句；共同理解、保留歧义与信息揭示顺序的句子保留。执行者定最终措辞并版本化进 hash，须覆盖四点：同组各 ID 是同一句话被拆成的几行，可按中文语序在组内重新分配内容；每个值都不能为空，长度与各自原文大致相称，不把整句塞进一个值；不同组之间仍各自只承载对应源 ID，不搬运邻条事实、不提前补完后文；组内也不改变信息揭示顺序以外的含义。草稿：

  > 先共同理解全部可见台词及跨条目的条件、否定、指代和语气，再表达各源 ID 的信息。groups 里同组的 ID 是同一句话被拆成的几行：同组各值合起来表达这句话，可以按中文语序在组内重新分配内容，但每个值都不能为空，长度与各自原文大致相称，不把整句塞进一个值。不同组之间仍各自只承载对应源 ID，不搬运邻条事实、不提前补完后文。保留原文歧义和信息揭示顺序。

- **`groups` 注入**：用 `recipes.inject()` 在 assistant 标记前加一行，与 `terms`、`target_context` 同款，形如 `{"groups": [["c12","c13"],["c15","c16","c17"]]}`；只列 ≥2 条的组，只含目标 ID。注入文字与键名版本化进 hash。
- grammar 不变（`unbounded` 空白，每个目标 ID 非空）。采样、`n_predict`、context、`cache_prompt`、重试全部不变。

### 4.3 变体与对照

- **唯一 GPU 变体 `grp1`**：dp10-cut 的切包与邻文 + §4.1 划组 + §4.2 提示。
- **对照 `dp10-cut`**：同包组成、同 seed，本轮新生成（§2.4）。
- 一轮**只有一个变体**，不追加；备选门槛与规则见 §4.6。

### 4.4 重排率（Q1 的终点）

- 对每个多 cue 小组，取候选与对照各条中文的字数占比向量（每条字数 / 组内总字数），L1 差 ≥ 阈值记为"重排"；阈值由执行者在 0.15–0.3 之间定并在票据说明，同时报 0.1／0.2／0.3 三档。
- 另报"译文逐字不同"的多 cue 组比例作为上界。
- 人工抽查：候选里重排的组随机抽 30 个（剧集、电影各 15），逐个标为"按中文语序合理重分配／只是改写没挪内容／挪错（跨说话人、信息落错行）"三类，比例进 §7；不引用原文到本文。
- 单条小组的译文须与对照逐字相同；不相同的条数单独报（它们不该存在，若存在要查原因）。

### 4.5 显示校验器（Q3 的终点，CPU）

- 对每条 cue 算中文字数（去标点与空白）除以该条时长的读速，以及多 cue 组内每条的字数占比与时长占比之差。
- 报候选与对照各自的分布：读速 p50／p90／p99、读速超过阈值的 cue 比例、占比偏差绝对值 ≥0.3 的组比例。读速阈值由执行者定（本仓库没有现成的读速规范；取值与依据写进票据），两套输出用同一阈值。
- 本轮它是观测终点，不是门禁；Q4 用的是"标记率不高于对照的 1.5 倍"。实现放 `experiments/reorder_groups/`，与统计脚本同处，纯 CPU。

### 4.6 评测设计

- **全集裁判**：dev 5397 条，候选与对照同包组成、同期各判一次（v7 §2.1 的漂移）；`scene_batching_v6` 的同包重判与配对比较直接复用。因为只有多 cue 组里的 cue 会变，另报"多 cue 组内 cue"子集的 Δ 与"单条组 cue"的噪声底（后者应接近 v6 的 +0.005）。
- 先 dev 主 seed 20261011–13 筛选（Q1 先于 Q2：生成完成后先算重排率与抽查，重排率接近零则不裁判）；Q1 成立再裁判；方向成立再用重复 seed 20261021–23 独立配对复现；复现通过的候选才谈确认集。
- 终点：全集 accuracy Δ（剧集、电影分开，50:50 总览）；fluency Δ 与 grammar、unnatural、register 分开；cue-attribution、wrong-referent、omission 分开；critical、major+；交付失败；重排率；校验器分布；输入 token、输出 token、墙钟、显存峰值。
- **登记但本轮不跑的变体**（下一轮或用户要求时才做）：门槛 1.5／2.0 s（主要面向产品时间轴）；大组上限 6（超过时在最长停顿处再切）；R3；`…` 算句末；把 dp10-cut 的 `cut_penalty` 加重或"不截断小组"作硬约束（改 ADR-0010，需另行裁定）；组级输出再程序切回（§8 备选路线）。

## 5. 判定纪律、预算与停止条件

- 判定纪律沿用 [v5 §3](2026-10-16-quality-exploration-v5.md)：对照固定 dp10-cut；裁判 `claude-opus-5-5-mqm-v1` 不改；三 seed 起谈质量；作品为聚类单位；剧集与电影分开；筛选与确认分离；成本与失败随结果一起记；未知值不填 0。
- 预算参考：对照 3 run + 候选 3 run 筛选，复现各 3 run，共最多 12 个 GPU run（每个约 4.5–5.5 分钟）；全集裁判每套 3 run 约 270 包、约 $29 标价，最多 4 套 ≈ $116。Q1 否定时只有 6 个 run、0 套裁判。
- 在筛选之前先做一张**小样票据**：取 dev 里多 cue 组最多的 10 个包（剧集、电影各 5）生成一次，人工看模型怎么重排，提示措辞只允许在这张票据里调整一次；调整后的版本进 hash，筛选不再改。
- 复现规则：筛选之后，无论结果是改善还是仅非劣，都用重复 seed 做一次独立配对；采纳看 §3 Q4 的条件是否两次都成立。
- 停止条件（任一满足即结题）：Q1 重排率接近零且小样票据调整一次措辞后仍如此；候选使电影侧或剧集侧全集 accuracy 显著变差，或 cue-attribution 显著上升；校验器标记率超过对照 3 倍；筛选与复现完成（正常结题）；Claude 配额耗尽且无离线票据可做。
- 无人值守原则同 v5：中途不请求用户裁定，需要裁定的事项集中到 §8；配额耗尽（退出码 75）时转离线票据或停下。GPU 票据在执行会话开始后按 tracker 顺序跑，`.local/gpu.lock` 规则照旧。
