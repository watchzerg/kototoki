## 1. 为什么做这一轮

- v10 只有一个成分过门：专名表注入 `q0-names`。它在产品 ASR 源上把不一致率从 0.050 降到 0.010，人名错误从 142 降到 96。但在 dev 干净源上（1 seed），人名错误反而从 25 增加到 35，电影 wrong-referent 变差 +0.039［+0.007, +0.072］。原因不明，所以不能直接进基线。
- ASR 感知提示（D1）的主终点跨 0，但全体 −0.067［−0.127, −0.007］、exact −0.076 小幅显著。它和注入都改 system 提示，叠加效果从没测过。
- 用户提出"段内放大、跨段截断"：只读邻文遇到长静音就截断，不把上一场戏带进来。v10 已有的相关证据是：邻文加长（前 50＋后 10）对 Q0 无改善；放到整场景前文时，电影 wrong-referent 上升。所以这里只验证"截断"这一刀，不再放大前文。dev 场景本身较短，已在场景边界截断；产品整片则不截断（v10 票据 09：Q0 在产品上平均可见前 19.6、后 5.0 条）。所以效应主要在产品上。
- 用户的原则：有效的进基线，无效的不进。"没测出差别"不等于无害，而且成分叠加没测过，所以本轮最后对过门成分做一次组合检查（§4.4）。

## 3. 本轮要回答的问题

1. **Q1 dev 反向的原因**：注入在 dev 上多出的人名错误与指代错误，分别属于哪一类——表条目错、表对但与参考字幕组惯例不同（裁判口径问题）、条目对但模型乱用（把代词、称呼或省略的主语换成名字，或套到别人身上）、与注入无关？
2. **Q2 注入能否在干净源上不伤质量**：修订后（或原样）的注入 N* 在 dev 3 seed 上是否两类非劣、wrong-referent 不显著变差、人名错误不增加。
3. **Q3 注入在产品上是否复现**：在新的产品 seed 上，N* 对 Q0＋替换是否仍然更好。
4. **Q4 ASR 提示叠加注入有没有增量**：N*＋`qwen-asr-aware-v1` 对 N* 是否改善。
5. **Q5 跨段截断**：只读邻文遇 ≥G 秒静音即截断，对 Q0 是否改善或至少无害；在产品与 dev 上各影响多少包。
6. **Q6 组合**：过门的成分合在一起，对产品等价链 Q0＋替换是否仍然更好。
7. **Q7 结论写法**：每个成分写三种之一——"进新基线候选"（列出适用范围）／"非劣无改善，不进"／"不进，原因 X"。新基线的身份由用户裁定（§8）。

## 4. 设计

### 4.0 通用规则

- 产品 ASR 源用**新 seed 20261054–56**：不在 v10 用过的 51–53 上再挑结论。dev 用主 seed 20261011–13。
- 一个产品 GPU 单位＝两部整片跑一个 seed。产品比较全部用普查（1728 单元，只判文本不同的单元）。
- 区间为 window bootstrap CI90（dev 作品等权、剧集与电影分开；产品沿用 `asr10._boot`），Δ＝候选 − 对照。
- 非劣界：dev 每类 accuracy CI90 上界 <0.05；产品全体每单元惩罚 CI90 上界 ≤0.05（与 v10 D 阶段 exact 桶同一尺度）。"改善"只在 CI90 上界 <0 时写。

### 4.1 阶段 A：离线（无 GPU）

- **01 实现**：
  - v11 根目录 `.local/q0-product-route-v11/`；
  - 给 `asr10` 的根目录与 seed 加参数（保持 v10 默认不变）；
  - 跨段截断选项（§4.3）：`qwen_options` 新键或 `wide_context` 新字段，默认值不进 hash，旧配方 hash 不变；
  - 送裁判前的 diff 工具；
  - 离线测试。
- **02 诊断 dev 反向**（回答 Q1）：
  - 输入：v10 的 `qwen-names-dev` s20261011 与 `qwen-wide` s20261011 的译文与判分，以及 dev 自建表。
  - 对每个"候选有、对照没有"的人名相关错误，以及每个新增的 wrong-referent，归入四类：（a）表条目错；（b）表对，但与参考字幕组惯例不同；（c）条目对，但模型乱用，即把代词、称呼或省略的主语换成名字，或套到别的人身上；（d）与注入无关。反方向（注入修好的错误）也要计数。
  - 另统计 15 张 dev 表的条目与参考中文的一致率，并与两张产品表比较条目性质（作品知名度、音译比例）。
  - 判据与样例写在票据里。样例不进 Git，因为属于转写内容。
- **02 的决定规则**（只允许一次修订，修订版记为 `qwen-name-table-v2`）：
  - （c）占多数 → 修订注入方式：只注入写法出现在**待译 cue** 里的条目（不看只读邻文），并在表头加一句"只在原文出现该写法的位置使用；不要把代词、称呼或省略的主语改成名字"。
  - （a）占多数 → 修订为只注入 `confidence: high` 的条目；同时在 §8 记下"表质量问题同样影响产品的替换"。
  - （b）占多数 → 不修订，N*＝v1。B 阶段除主判定外，再报告"排除惯例差异 cue 后"的 accuracy 作为附注，不改门。
  - 没有一类占多数 → 不修订，N*＝v1。
  - 无论哪种情况，选定的注入方式记为 **N\***。
- **03 跨段截断离线统计**：按产品与 dev 的实际时间轴，算 G＝5、10、20 s 时被截断的包占比、平均可见邻文的变化，以及截断点前后是否像换场（列 20 个时间点，只看时间和条数，不看内容）。**主臂固定 G＝10 s**，理由是包内本来就不含 ≥20 s 的静音，20 s 太宽，5 s 会切进对话停顿。如果 G＝10 s 在产品上影响的包少于 5%，04 之后的截断臂不跑，结论写"产品上很少触发，无可测效应"。
