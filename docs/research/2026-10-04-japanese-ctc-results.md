## 推荐结论

三个新增模型都展示了补充价值，但适合的上游与取舍不同。保留原 W0／W1／X0 定义及 Jonatas 对照，
将以下组合纳入后续候选；本轮已完成初筛后五个组合的十二窗补充评估，不自动采用产品默认。

| 优先方向 | 判断与理由 | 剩余限制 |
| --- | --- | --- |
| **W1／X0＋MMS jpn** | 本轮严格半秒成功最强的补充方向，两片均改善；分别比各自 Jonatas 增22／39条成功。 | X0 仍有约31秒极值；显存较高，CC-BY-NC-4.0。 |
| **X0＋Reazon 原生 token、无填充** | 约300M规模的另一组对齐候选，可测净增17，半秒成功增10；共同可测长尾明显改善。 | III 半秒成功下降4条；最坏旧字幕变成 coarse_time，不等于修复；多字 token 无独立字符边界。 |
| **W0＋hiragana** | 相比 W0＋Jonatas 成功增25、可测增13，两片均改善，值得继续有界评估。 | P95 略退，读音转换仍可能错误；模型权重许可未明确，新增 pykakasi 依赖。 |
| W1＋Reazon 两侧0.5秒填充 | 保留为减少大偏移和个案修复的次要取舍。 | 合计半秒成功下降5，III下降16，不优先替换 W1。 |

W0＋Reazon／MMS 与 X0＋hiragana 停在四窗筛查；W1＋hiragana 的半秒收益伴随 III 严重长尾，
暂不扩展。没有尝试按字幕人工修读音、按参考选择对齐器或把模型结果择优拼接；这些均不是本轮证据。

pykakasi 对人名、多音字与语境读法的错误仍可能强行产生有时间但不准确的对齐。

## 方法与证据边界

四窗筛查使用 II／III 各 window-01、window-04，合计 20 分钟。
沿用已冻结的 16 kHz 单声道 PCM16、源 offset 和完整上游文字。
W0 使用此前已修复的原 segment／自身 word 包络；W1、X0 使用原分段。
没有新增 ASR、VAD、人声分离或参考指导窗口。所有候选保留原识别全文，
CTC 失败、OOV、读音无法回映射时只失去时间证据，不删除文字。

采用现有完整分母评分，开始和结束都在阈值内才算成功；跨窗参考沿用原未决规则。
字幕 SRT 是显示参考，不是独立声学边界标注。四窗是开发筛查；本轮扩展十二窗，
其中四窗仍是同一批数据，不作为独立复现。未做新电影、全片或人工听辨验证。

## 固定接口

| 候选 | 本轮实现 |
| --- | --- |
| Jonatas | 原 WhisperX 归一化、标准 TorchAudio CUDA CTC；新入口与原输出做严格时间单元一致性核验。 |
| Reazon | 原生 tokenizer，多字符 token 保留整体 `word` 时间，blank 取模型配置 0；OOV 不赋时间。 |
| MMS | 明确加载 `jpn` tokenizer／adapter，验证实际语言与输出 head；复用原字符 CTC 适配层。 |
| Hiragana | 按发布者示例使用 pykakasi 2.3.0；假名 token 逆映射到原文范围，多字读音不均分成伪造字符时间。 |

Reazon 的无静音填充与两侧各补 0.5 秒静音分别预登记为独立配置。
后者是物理添加零采样，不是扩大原音频搜索范围；时间减去对应偏移，
完全落在填充区的 token 不算有效时间，部分相交者裁剪到原搜索范围。
原生 token 路径按 extractor 配置传 attention mask；旧 WhisperX 字符路径保持原不传 mask 的行为。
均使用现有稳定环境的 CUDA FP32，未安装官方示例中的 FlashAttention 2 或改用 BF16。
Python 3.13.16、PyTorch／TorchAudio 2.8.0、Transformers 4.57.6、WhisperX 3.8.6；
RTX 5080 16 GB、驱动616.92。未显式覆盖该固定环境的 attention 默认值。
复用旧环境是为了保留对齐算法与基线可比性；TorchAudio 2.8 `forced_align` 已弃用，
这份实验并不消除未来工程化时更换／维护该边界的需要。
因此测的是本机可复现的固定适配方案，不能代表所有精度与 attention 实现的上限。

加载、对齐时间与 PyTorch 峰值 allocated／reserved 显存单列；不把缓存 ASR 当作本次端到端测速。
下载和部分 CPU 准备与推理并行，GPU 模型推理串行，墙钟不用于精密性能排名。

## 四窗资源与集成取舍

下表每个模型覆盖相同四窗×三上游，共12个独立进程；Reazon 为无填充版。
范围为每次处理一个300秒窗口的观测，显存是 PyTorch allocator 峰值，非整卡占用。
加载时间包含的接口初始化责任不同，不能据此推断纯 checkpoint 读取速度。
