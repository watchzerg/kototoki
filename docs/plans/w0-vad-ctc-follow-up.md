状态：完成，十二窗六配置比较已核验  
日期：2026-10-04  
范围：Windows 11／RTX 5080，两片原十二个五分钟片段，完整分母 590 条。

结果：新 CTC 十二阶段全部完成；W0＋VAD＋CTC 半秒成功 302/590，
W0＋CTC 为 306/590，W1 为 320/590。共同可测长尾略改善，但全分母成功未增加、
内容覆盖减少，不建议在 W0＋CTC 上默认再加 VAD。详见[结果报告](../research/2026-10-04-w0-vad-ctc-follow-up.md)。

## 请求与目的

用户在理解[首轮组件实验](../research/2026-10-04-component-augmentation-results.md)后，
明确提出更看重字幕偏移少，希望尝试 W0＋CTC＋VAD。
首轮按无回归护栏停止叠加的决定保留为历史，本次是用户指定的独立追加实验。
不把“没有全面支配”解释为“时间没有实际收益”，也不擅自设定可接受漏字的上限。

实际处理顺序是原音频 → GPU Pyannote VAD → W0 识别 → 日语 CTC 对齐。
只追加 CTC，复用已经完成的 W0＋VAD 识别结果，固定 VAD、模型、解码及原始 PCM。
不增加人声分离或其它组件，不更改 W1／X0，也不同时调 VAD 参数。

## 固定配置与输入

- 来源：`.local/components/comp-vad-dev-v1/plan.json` 的十二个已曝光片段及完成的 VAD／W0 阶段。
- 核验缓存 ASR、VAD 清单、原始 PCM、源 offset、执行 harness、实际 GPU 与源码／模型身份。
- 新对齐使用与 W0＋CTC 相同的日语 wav2vec2、音频归一化及 TorchAudio 2.8 标准 CUDA CTC。
- 复用原词时间包络规则，使对齐搜索窗口包含该段自身的词时间；不读参考字幕指导窗口。
  原始 ASR segments、派生窗口和完整文字分别保留，禁止拼接语音后错用压缩时间轴。
- 全文必须与缓存 W0＋VAD 完全一致。已有漏字不会被 CTC 补回；对齐失败仍保留文字和全分母。
- 新身份为 `comp-w0-vad-ctc-dev-v1`，推理前冻结全部窗口、命令、版本和哈希。
  历史 VAD／ASR 成本与新 CTC 成本分开记录，不称为新端到端测速。

## 比较与解释

同一十二窗比较六个配置：W0、W1、X0、W0＋VAD、W0＋CTC、W0＋VAD＋CTC。
计分核心、参考、阈值、失败处理和裁剪边缘不确定性保持不变。

首先报告全部 590 条中开始和结束均偏移不到半秒／两秒／五秒的确定成功数；
再比较共同可测内容的 P95／P99 和大偏移，防止通过漏掉难句显得更准。
同时报告 CER、错漏多字、首尾文字覆盖、可测数和无有效时间的原因。
给出逐片结果及十二窗固定 seed、2000 次配对 bootstrap，不把同片结果当跨作品泛化。

本次只回答“叠加后时间是否更好、代价是什么”。原严格无回归替换资格仍单独报告；
没有达到它，不自动否定偏移改善的使用价值；有时间收益，也不自动接受内容损失。
预登记的六个确认窗口本次不启用，未经用户选择的产品默认配置不改变。
