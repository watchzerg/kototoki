# 地图

## 接跑手册（每次启动从这里开始）

1. 读[研究文档](../../docs/research/2026-10-21-q0-exploration-v10.md) §7 进度，找到第一张未 resolved 且 Blocked by 已全部 resolved 的票据；读它的 `## 执行记录`。**状态以文件为准**，不信任文档声称在跑的内容。
2. GPU 票据已获用户授权无人值守执行，预算以研究文档 §5 的表为上限。启动前只读核对 GPU：PowerShell `Get-Process | ? ProcessName -match 'llama|python'`、`nvidia-smi`，读 `.local/gpu.lock`。锁被存活 PID 持有、或有不明 llama-server 时不启动、不杀进程，转离线票据。
3. Hy 臂走 `translation_v3/server.py`（compat b11429），Qwen 臂走 `translation_v3/qwen.py`（`kototoki.llama_server`，官方 b11669）；两个 server 串行。
4. 驱动沿用 `scene_batching_v6`：`--round v10`（票据 01 建）。每个比较都要同期重判对照（v7 §2.1），Q0 对照译文可复用 `.local/general-model-translation-v9/` 的 run，分数不可复用。
5. 裁判（`claude -p`）退出码 75 = 配额耗尽：不循环重试；转离线票据，没有可做的就停下，在票据执行记录与研究文档 §7 写明停在哪里。
6. 预算台账写在下方 Notes，每个 GPU run 与裁判标价累计；阶段超限即结该阶段，总上限超出即结题。
7. 每完成一张票据：票据写 Answer 并 resolved → 本文 Decisions-so-far 加一行 → 研究文档 §7 更新 → 提交 Git（研究文档、INDEX.md 与 `experiments/` 下本轮代码；不提交 `.claude/settings.json`）。签名失败不绕过，记研究文档 §8 第 0 项。
8. 需要用户裁定的事项写研究文档 §8，不中途停下来问。按 §4.7 新增方向时新建票据并在 §7 写明理由。
