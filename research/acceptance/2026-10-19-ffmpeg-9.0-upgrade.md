# 2026-10-19 ffmpeg 升级到 9.0 维护分支

## 时间
2026-10-19。

## 对象
把产品默认 ffmpeg 从 gyan.dev full build（2026-10-01 git 构建）换成 BtbN win64 gpl 的 9.0.2 维护分支构建（`n9.0.2-28`，autobuild 2026-10-18，9.0.2 之后 28 个提交；上游最新稳定版为 9.0.2，BtbN 只提供该维护分支构建）。依据[依赖布局与资产清单](../../docs/development/dependencies.md#ffmpeg)的升级步骤。

## 环境与版本
新构建由资产脚本 `install-tools` 安装到本机工具目录，压缩包校验与 GitHub digest 一致；旧构建为上述 gyan.dev 版本。只用 CPU，不加载模型。

## 测试
- 素材：2 部日语电影（HF II／III）的 mkv，日语音轨（FLAC 立体声 48 kHz）。
- 做法：用产品 `kototoki.media.probe` 与 `derive_pcm16k`（与 `python -m kototoki` 的 extract 阶段命令行相同），分别以新旧构建派生 16 kHz WAV，比较样本数与 PCM 的 SHA256，以及时间轴补偿记录（补零／丢弃样本数、净补偿）与时长告警。
- 另：`just test-full` 用新构建合成小样本。

## 结果
- HF II（112,448,683 样本）与 HF III（117,205,333 样本）的 PCM 在新旧构建下逐字节相同，且等于冻结语料与 swr 回归记录的基线值。
- 补偿记录与时长告警新旧构建完全相同。
- `just test-full` 12 个用例通过。

## 结论
新构建可以作为默认 ffmpeg：派生 WAV 不变，下游 VAD／ASR／对齐的输入不变，因此没有重跑整片流水线。未覆盖：其他编码与声道布局的解码差异，只核对了这两部的日语音轨。
