# ADR-0013：专名一致性研究线结题——冻结最佳已知配置，不再继续

状态：已接受（2026-10-19）。  
日期：2026-10-19。  
关系：**不替代任何已有 ADR。** 翻译基线（[ADR-0010](0010-dp10-cut-translation-flow-baseline.md)）与产品配方（[ADR-0011](0011-dp10-cut-product-recipe.md)）不变；本线从未进入产品包 `kototoki/`，技术设计不改。  
范围：`experiments/name_consistency/` 这条"通用模型从日文侧建专名表＋生成后程序替换"的研究线。六轮报告见[调研索引](../research/INDEX.md#翻译后审校与人名专名一致性2026-10-19已结题adr-0013)。

## 决定

用户 2026-10-19 裁定：

1. **研究线关闭。** 不再开新轮次，不再提议"再调一轮规则"类的改动；agent 不得自行重启。将来若要重开，须由用户明确要求，且只值得做两个未测方向之一：一次性音译的模糊匹配（按读音或编辑距离），或"表可人工校对"的产品形态（见"后果与后续"）。
2. **最佳已知配置冻结如下**，作为这条线的定论与将来的参照：
   - 建表：`build_table.py`，no-think（Qwen 官方 non-thinking 采样，`--reasoning off`），提示 **v5**（`build-table-prompt-v5`；第六轮试过全部虚构示例的 v6，退步，已回退），seed 20261019；程序兜底全部开启：zh 形状过滤、称呼词黑名单、evidence<3 的 person 降为 medium、日文写法形状过滤（`_clean_ja`）。
   - 替换：`apply_table.py` 默认参数——规则一（落点必须覆盖整个名字，否则不动）、孤立单字开（`--isolated-singles`）；`--name-check`、`--pool-by-target`、`--bigram-isolation`、`--iterate`、`--weak-name-check`、`--min-confidence` 全部关闭或不用。
   - 合并：`merge_tables.py` 的交集、`zh-agree`、写法回退、写法层一致都保留为开关，**都不用**：没有一档在严格口径下优于单张表。
   - 冻结评估基准：第一轮的四张 v4 提示 no-think 表（`.local/name-consistency/03-four-v2/`，不进 Git）加上述替换默认，四部合计 161 处改动，Opus 逐行判 good 89%、有害 2.5%；盲序成对判分偏好替换后 88／平局 20／偏好原译 3；四部整片通读"略好读、无新错、覆盖不全"。提示 v5 与 v4 的差别（confidence 判据、称呼词与祷词不收、相近角色不合并）落在采样噪声内，v5 样本的额外有害行（爸爸→时臣）已由称呼词黑名单堵住。
3. **不进产品。** 第一轮 §5 第 3 条的条件（补 MQM 抽样与整片人工观感、改技术设计、另写 ADR）未满足，也不再去满足。它停在"可选的研究 demo"。

## 依据

六轮（2026-10-19，同日）把能试的规则层改动都试了一遍，第三轮之后默认没有再动过：

| 轮 | 改动 | 结果（四部合计，严格口径） | 裁定 |
| --- | --- | --- | --- |
| 一 | v2 表（每个写法配同粒度中文）＋替换 | think 68%／17%，no-think 75%／15% | 策略成立，精度不够 |
| 二 | 规则一（整个名字）、规则二（中文名核对） | 规则一 82%／4%；规则二误拦 73／103 | 规则一采纳，规则二放弃 |
| 三 | 孤立单字、二字组、迭代、交集、pool | 孤立单字 **89%／2.5%**；二字组 73%／20%；pool 84%／8% | 孤立单字设默认，其余不采纳 |
| 四 | 提示 v5 校准 confidence、弱校验、修扩展吞修饰 | 有害条目全是 high，过滤无效；v5 表 83%／5.4% | 默认不变 |
| 五 | 两次建表取一致、写法回退、称呼词黑名单 | 一致表 90%／4.3%（pool 4.7%） | 默认不变；黑名单保留 |
| 六 | 提示 v6 虚构示例、写法层一致、日文写法形状过滤 | 一致表 85%／7.1%（pool 5.5%） | 默认不变；形状过滤保留 |

剩余误差的三个来源都在规则层之外：

- **表里的错名**（4 行有害里的 3 行）是 27B IQ3 模型对次要角色的知识错，不是采样噪声：置信度校准分不出（第四轮），两 seed 取一致只清采样级的错（第五轮），换示例只是换了挂错的实体（第六轮）。本地 16 GB 显存装不下更强的模型，think 模式不更准（第一轮），外部 API 违反"本地运行"的不变量。
- **覆盖率**（士郎约 40%）的缺口是每句都不同的一次性音译（艾米亚希罗／埃米亚希罗／艾米亚希洛），跨 cue 统计从原理上覆盖不到；pool 能补 10–15% 的行，但代价是把表错放出来。
- **残字**（爱爱因兹贝伦）1 行，边角问题。

## 不采纳的替代

- 规则二（中文名与译者多数写法核对）：译者整片没写对的名字（切嗣、间桐、爱因兹贝伦）即使模型给对也会被拦，每拦 1 行有害牺牲 2.6–3.3 行正确改动。
- 二字组孤立：覆盖到 67–71% 但有害 20%（士郎郎、Rider手）。
- 迭代到不动点：第二遍 0 改动。
- 两表交集、两次建表取一致（含写法回退、写法层一致）：实体砍半或 good 不升，有害率都不低于单张表；写法层规则只校验中文是否被认可，拦不住写法挂错实体。
- `--pool-by-target`：错源是表错放出，表错不解决不能开。
- 提示 v6（虚构示例）：模型失去真实作品示例的锚定后更常挂错实体并输出罗马字。
- 继续新轮次（按实体名配对、写法读音校验）：预期只能让一致表追平旧默认，不会超过，投入产出不划算。

## 后果与后续

- 代码保留在 `experiments/name_consistency/`（101 项离线测试），README 写明冻结配置与命令；不并入产品包，产品不导入。
- 冻结证据只读：六份报告、`.local/name-consistency/` 下的表与矩阵、`.scratch/name-consistency/` 的票据与台账；需要改动时新增带版本的文件。
- 将来若用户要重开，两条有真实空间的路：① 一次性音译的模糊匹配（有界实验，目标士郎覆盖 ≥60% 且有害率不涨，做不到就关）；② 产品形态改为"表可人工校对"——每部 15–20 个实体，人改两个错名只要一两分钟，表正确后 4 行有害里的 3 行消失、pool 也可以开。两者都不在本 ADR 的决定之内。
