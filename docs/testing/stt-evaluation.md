## 参考数据与样本选择

2026-10-05 用户补充选样偏好：新增日语素材优先多人讨论、现场噪声及复杂声学场景，不优先选择环境过于干净的朗读。当前指定获取 YODAS2 国会讨论；获取身份和验证边界见[素材记录](yodas2-parliament-reference.md)。这是后续新增素材的选择方向，不改写已有电影实测，也不表示该国会录音已经通过听辨或成为精确真值。

真实模型评估按用户于 2026-10-04 确认的来源分层：Heaven’s Feel II、III 的 SRT 来自原版内嵌日文字幕，作为精确主参考，优先完成两片的比较；Heaven’s Feel I 的 SRT 从中日双语字幕抽取，可信度较低；Black Panther 是英文电影，其日语音轨与日语内嵌字幕可能使用不同措辞，可信度最低。后两片仅作补充参照。完整文件名、当前 SHA256 与来源见[素材文档](fatestay-reference.md)。

主报告分别展示 II、III 的文字误差、时间误差、覆盖率和失败分母；需要主参考汇总时，仅合并这两片，并注明 micro/逐片平均口径。I 和 Black Panther 单独列补充结果，不与主参考混合排名或抵消主参考失败。I 的分数须注明双语抽取的参考不确定性；Black Panther 未经独立听辨核对的文字差异不能直接记作模型错误或用于逐字准确度排名。

后续识别直接使用各影片目录已有的 `.jpn.flac`（Fate 三部）或 `.jpn.eac3`（Black Panther）。常规评估不重新从 MKV 提取音轨。按后端需要解码、下混、重采样或裁剪已有音频，派生 PCM 写入独立输出目录；记录源音频身份、实际 PCM 哈希、采样率、声道、样本范围和源时间映射。视频仅在需要核查来源或时间轴时只读查阅。

新一轮须冻结两片主参考各自的样本、参考版本与开发/验证/保留划分。旧单片的冻结 manifest、参考哈希、分数和阈值适用范围保持原样；不能把历史结果移记到当前清洗后的字幕或称为两片验证。已经用于诊断或调参的片段必须记录接触历史，不能通过改名或重新分集变成未见保留数据。

遵守[原始素材保护与哈希检查](fatestay-reference.md#preserve-originals)：视频保留在原位置，原始字幕不得修改，运行前后核对所用参考字幕的哈希，输出写在 `D:/movie/` 之外。日常离线测试使用小型合成或可再分发样本。私人媒体、完整转录文本和大体积输出不得进入 Git。

在比较候选之前冻结样本选择规则。同时覆盖容易和困难的场景：清晰语音、背景音乐、微弱或短促语音、重叠说话、长静音、窗口边界、重复短语、数字、专名和长输入。相关歌曲单独评估。少量短片段成功不能证明整片可靠性。

II、III 的精确参考地位来自用户确认的字幕来源，不表示每个显示区间都已完成声学标注。记录文字规范化规则，以及参考中未实际发声或经编辑的内容。不得将参考文本输入正在评分的识别流程。精确声学时间评估使用人工听辨复核的发声起止边界，并记录标注不确定性；原始字幕的显示时间不能自动视为词级声学真值。历史上的翻译 ASS 字幕仍不适合作为日语 CER 真值。

## 分开评价不同能力

| 维度 | 记录内容 | 不能据此证明 |
| --- | --- | --- |
| 识别 | CER 或适合语言的指标、漏识别、幻觉、重复、专名与数字错误 | 声学边界准确 |
| 对齐 | 起点和终点的有符号及绝对误差、中位数/P95/P99、缺失或失败单元 | 识别文字正确、字幕显示易读 |
| 时间结构 | 零或负时长、顺序错误、越界、重叠、字段缺失 | 与实际发声同步 |
| 字幕显示（若已实现） | 字幕显示区间、内部静音、时长与可读性、文字归属及说话人混合 | 底层词时间预测准确 |
| 性能 | 冷/热运行延迟、模型加载、ASR/FA 用时、峰值内存和显存、失败/重试、缓存使用 | 其他硬件上的准确度或兼容性 |

### 识别评分不依赖字幕拆分

同一段发声被识别成一条或拆成两条字幕，只要文字顺序和内容相同，识别分数应相同。不要按 SRT 行号逐条计算 CER，也不要把候选生成的句子或字幕条目作为评分窗口。

在看候选结果之前，按素材时间轴和场景建立独立于候选的固定评估窗口。窗口尽量位于发声之间，并覆盖完整语句；边界和跨界内容的归属规则须预先冻结。每个窗口分别拼接按发声顺序排列的完整参考文本与候选文本，再按同一规则规范化和计算字符编辑距离。窗口只是评估单位，不要求各框架采用相同的内部切片或字幕分段。

不能仅按候选字幕起点把整条文字强行分入窗口，这会让切片差异产生虚假的漏字或重复。跨窗口的内容按预先规定的文本对应关系或可靠的词时间归属；证据不足时保留边界不确定标记、复核或使用预先规定的合并窗口规则，禁止根据哪个候选更有利临时调整。保留整段或整片完整文本的汇总评分，用于检查窗口归属是否改变结论。

字幕条数、断句、换行、标点和可读性另行评价；时间偏移按基准中冻结的匹配单元与覆盖规则评价。文字正确但时间错误、文字正确但显示拆分不合适，分别记入相应维度，避免互相抵消。对齐时的文本匹配结果也不能代替完整识别文本的准确度评分。

### 文字规范化与汇总

评分前定义规范化规则。日语须记录全角/半角、Unicode 规范化、标点、汉字/假名变体和数字读法的处理方式。保留原文与评分用规范化文本；不要为使某个候选得分更高而追改规则。若报告 WER，注明分词方法；不同后端的原生词单元不能直接比较。

按已声明的规范化方式定义 `CER = (替换数 + 删除数 + 插入数) / 参考字符数`。同时报告编辑操作计数和参考字符数，区分所有字符汇总的 micro CER 与逐样本 CER 的平均值，不能将两者视为同一指标。重复输出会计入插入错误，不应在候选侧单独去重后评分。

参考文本为空的静音窗口不计算单窗口 CER；候选输出仍须作为插入错误计入整体文字统计，并单独统计静音幻觉事件及其长度。不能把这些窗口丢弃，或把未定义的单窗口 CER 记为零。参考字幕中漏记的真实发声和非口述文字，应在候选评分前通过独立复核标记，保留原始参考及修订来源。

## 时间误差与覆盖率

使用 `预测时间 - 参考时间`：正数表示偏晚，负数表示偏早。起点和终点分别报告。如果使用字幕条目的综合误差，明确写出定义，例如 `E = max(abs(start_error), abs(end_error))`。

同时报告有效匹配项的误差分布，以及全部预选项中的成功覆盖率。缺失、歧义、重复、部分匹配或时间结构无效的情况必须可见；不得通过从全部预选项的分母中删除失败项来改善结果。注明样本数和分位数算法；小样本 P99 不能提供充分的尾部风险证据。具体数值筛选规则由[字幕时间优先基准](subtitle-timing-benchmark.md)统一规定。

先建立语义/文本对应关系，再测量时间，允许有明确记录的一对多或多对一关系。不得看到误差后改配附近更有利的字幕。同一句发声的身份匹配并不证明其文字完全正确。部分短语的声学时间和整条字幕的显示区间属于不同测量。

分层抽样须保留选择规则和权重。加权估计不是全量普查。改进和退化都须记录，包括原先正确但修改后出错的样本。

## 受控比较

比较当前 W0 的 VAD、ASR 或 MMS 变体时，复用并更新 [W0 demo](../../experiments/w0_demo/README.md)，
通过其 Adapter／模块边界隔离变量；同块识别回归先使用冻结 VAD，再检查新分段的影响。
完整基准与源码身份见 [demo 验证](2026-10-05-w0-demo-validation.md)；旧报告 W0 的配置与成绩不自动继承。

1. 比较 aligner 或对齐后处理时，固定 PCM 与输入文本。
2. 比较字幕格式或显示策略时，固定文字单元与词时间。
3. 隔离识别路线差异时，尽量固定音频窗口与下游处理，记录无法控制的差别。
4. 先建立各框架最新文档推荐的完整流程基线，再用分阶段对照解释差异；优化完成后重新核对端到端结果。仅对齐与包含 ASR 回退的完整流程可能表现不同。

各框架的原生流程可以保留内置 VAD 和预处理。针对疑似问题的受控对照须明确改变了哪个阶段、哪份音频以及哪些时间映射，不能因为某一路线难以关闭内置处理就声称各路线已完全等价。

对实际输入 PCM 计算哈希，或记录其样本范围与来源。模型名、beam size 或 UI 设置相同不足以证明仅改变了引擎。GGUF/CT2/GGML 转换、量化、tokenizer、batch、内部切片、VAD 和上下文都可能引入额外变量，须如实记录。

不能把缓存命中当成新推理参数已实际执行的证据。记录哪些阶段复用了缓存、哪些重新计算。先做小规模诊断比较，证据支持时再扩大到更有代表性的输入。

## 运行记录

每次真实评估保留一份简洁、保护隐私的 manifest 和报告，包括：

- 问题、假设、基准、改变的变量、预先定义的标准，以及目标是诊断还是产品验收。
- 影片、参考可信度与主/补充用途、源音频路径及哈希、当前 SRT 哈希、所选音轨来源（如适用）、实际 PCM 身份、采样率/声道、样本数/时长、预处理、窗口、padding 和时间映射。
- 官方文档及模型卡的核对日期、代码/后端版本、模型与 aligner 标识/revision、转换/精度、语言，以及实际生效的解码/VAD/对齐/输出设置。
- Windows/GPU/驱动/runtime 信息，以及 ASR/FA 的实际 device/dtype；不支持或出现回退须明确记录。GPU 推理约束不能因实验失败而静默改成 CPU 推理。
- 原始后端响应的位置、可获取的原生/修正时间、单元映射、回退/重试/修正事件，以及适用时的最终输出身份。
- 测量值、覆盖率分母、失败与退化、可重复性、局限，以及敏感证据在常规日志之外的保存位置。

吞吐量使用 `RTF = 处理秒数 / 音频秒数`，注明包含哪些阶段。模型加载、热运行推理、对齐、解码和缓存复用分开记录。记录 batch size、同时运行的其他任务，以及峰值内存/显存测量方法。缺失的测量值应保持“未知”。

## 报告与验收

明确报告通过、失败和未验证的部分。文件有效、时间戳单调或识别分数较高，都不足以证明字幕同步。找到故障机制不等于已验证修复。历史发现记录在[时间戳失败案例研究](../research/2026-10-03-timestamp-failure-cases.md)；新的 Kototoki 实测应形成带日期、独立运行身份的 testing 报告。

历史上的半秒目标、旧样本选择、模型推荐或声称的 GPU 能力，不自动成为 Kototoki 的验收标准。字幕 demo 在执行候选筛选前须冻结链接的[时间优先评估方法](subtitle-timing-benchmark.md)；后续功能验收还需明确采纳相应标准。
