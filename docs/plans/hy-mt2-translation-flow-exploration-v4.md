### 1.2 方法学教训（v3 实测）

- **效应小于分辨率**：多数配方与 C0 的差在 ±0.05 以内，即 C0 accuracy 惩罚约 0.43 的 ±12%；而 v3 的 MDE 正好约为 0.05。
- **窗口层面的异质性主导结果**：
  - screen-a 与 screen-b 经常方向相反。
  - b10-joint 在筛选集 96 窗上 Δ −0.093（剧集 −0.170），在确认集上剧集反而 +0.072。同一批作品的新窗口就能把方向翻过来。
  - 少数作品和窗口（M03、W09，以及个别窗口 +0.5 到 +0.9）反复主导均值。
- **赢家诅咒**：从约 20 个配方里按筛选成绩挑出的最佳者，其筛选 Δ 必然偏乐观，最终判断应以独立确认为准。
- **裁判噪声**：两次重排重评的建议 MDE 为 0.042 和 0.057，major 翻转率 1–2%。S1 中途的复评没有发现“越评越松”的漂移。
- **机制线索**（可作为先验）：批次越大，误译越少，但跨 cue 的 wrong-referent 越多；joint 只能在中等批次上抵消这部分代价。
- **成本参考**：
  - 生成：一次 34 场景 run 约 10–11 分钟（b10-joint 约 608 秒）。
  - 裁判：每包 4 窗，约 $0.11（标价，走订阅额度）。v3 全程共 68 个 run、1440 个包，标价约 $159，没有遇到配额阻塞。

## 3. 探索方向

方向 1 是其余方向的前提，应先完成，或至少先完成其中决定分辨率的部分。方向 2–4 的先后和组合由执行会话决定。每个方向都要写明：要消除什么不确定性、预期机制、计划查看哪些失败样例。

### 方向 1：提高量尺精度（先做）

- **目标**：让方向 2–4 中可能存在的 3–6% 真实效应能被可靠检出，并降低“筛选赢、确认输”的概率。建议先估算目标 MDE 所需的窗口数、seed 数和重评次数，再决定规模。
- **已知方差来源**：窗口与作品的异质性（最大）、生成 seed、裁判重复噪声。分解它们可以利用 v3 已有数据：C0 的 3 个 seed、两次重评、各候选的逐窗差。
- **可选做法**（不限于此，取舍由执行会话决定）：
  - 每部作品取更多窗口，或者新增作品和集数；
  - 改用整场景或整段评分，减少窗口抽样带来的噪声；
  - 每个 run 评两遍再取均值；
  - 增加 seed 数；
  - 用 v3 的 19 个配方结果做回溯功效分析。
- **开放问题：新窗口的参考译文**。可选路线有：
  - 沿用“只看日文源文、参考仅作辅助”的 MQM，评测新窗时不提供参考；这需要做校准，证明不带参考时检出率和误报率仍然可接受；
  - 用 Opus 新建参考并复核，类似 reference-v3 的做法；
  - 两者混合。
  - 无论选哪条，都必须保证参考与裁判同候选设计隔离。
- **必须产出**：
  - 新的开发集；
  - 一个**新的、封存的确认集**，与开发集和 v3 的全部窗口在源区间上隔离，生成前锁定；
  - 新的 `decision-policy`，写明 MDE 推导方法，并在查看候选成绩之前冻结。

### 方向 2：采样温度及相关采样设置

- **要消除的不确定性**：官方 temperature 0.7 是否适合字幕翻译这种追求忠实的任务。v3 中各 seed 之间的差异是噪声的重要来源，降低随机性可能同时提高质量和可复现性。
- **注意**：
  - v3 代码把采样列为固定项，需要把采样做成配方字段，并保持 hash 兼容。
  - 低温或贪心可能更容易陷入重复或空白循环，要记录 4096 触顶和重试。
  - 温度降低后，seed 之间的方差也会变化，需要重新考虑 seed 数和功效。
  - v1 的 temperature 0 配方是旧裁判、旧流程下的结果，只能作为背景，不能当证据。
- 取值范围和是否联动其他采样参数（top_p 等），由执行会话决定。

### 方向 3：多候选生成再选择（MBR、自一致性等）

- **要消除的不确定性**：同一批次多次采样后，按候选之间的一致性（或其他本地准则）挑选，能否稳定减少偶发误译。机器翻译文献中，MBR 类方法通常有收益。
- **硬约束**：选择器必须**完全本地**，因为这是产品路径。Claude 裁判只能用于评测，不能用于选择。可以考虑的本地准则包括候选间字符或词级相似度、本地小模型打分、用同一模型做选择提示等，由执行会话决定。
- **代价**：生成约为 N 倍。要报告质量和墙钟的权衡，并给出 N 的边际收益曲线。如果收益只在 N 很大时才出现，要如实标注其实用性。
- **与方向 2 的关系**：多候选需要随机采样才有多样性；温度选择与 N 相互影响，可以考虑联合设计，但要控制组合数量。

### 方向 4：把已翻译的中文作为只读上下文

- **要消除的不确定性**：给模型看前面批次已经产出的中文译文，能否改善称呼、术语、语气的前后一致性，以及跨批的指代。v3 的错误类别显示，wrong-referent 和 terminology-inconsistency 是可改进的类别。
- **注意**：
  - 生成变为批次间串行依赖，前面的错误可能传播；
  - 输入容量上限 4032 tokens（总 context 8192 − 输出 4096 − 余量 64），b10 的输入预算要实测；
  - prompt 缓存的前缀复用方式会改变，要核对首请求的 `cache_n` 和墙钟；
  - 只能使用模型自己的历史输出，不能使用参考或裁判反馈。
- 显示多少条译文、放在什么位置、是否同时保留日文邻文，由执行会话决定。
- 现有的 MQM 窗口评测可能看不到跨批的一致性收益，可以考虑补充一致性指标，但新指标必须先校准，再用于判定。

## 4. 判定纪律（沿用 v3 中有效的部分）

- 盲评，包里只出现不透明的 run 哈希；同一对比较只用一种执行面的结果。
- 每个候选至少 3 个 seed，与对照配对；剧集和电影分别按作品等权，总览各占 50%；风险窗单列；报告逐作品 Δ 和 LOO；critical 不得增加；交付失败不得增加。
- `decision-policy` 在查看任何候选成绩之前冻结；改动必须新建版本，并写明理由。
- 筛选只用开发集。最多锁定 1–3 个完整配方，**一次性**在新确认集上检验，使用 Holm 校正；锁定后不得修改配方。
- 报告要讨论赢家诅咒：筛选 Δ 只作为排序依据，最终结论以确认结果为准。
- 每个候选在台账中追加一条：假设 → 唯一变化 → 结果 → 判定 → 下一步。失败也要记录；未知值不填 0。

## 5. 约束

- 只在本地运行；GPU 生成在后台进行，检查 `.local/gpu.lock`，不抢占、不杀其他进程。
- 裁判配额耗尽（退出码 75）时不要循环重试：先推进不需要裁判的工作，没有可做的就停下，恢复后从 `status` 续跑。
- 不续跑 v2，不修改冻结代码和历史证据，不改写 v3 的报告、台账和产物。
- **不自动替换基线**；采纳由用户决定，并另立 ADR。
- 子 agent 显式指定模型：默认 sonnet，复杂的统计或协议设计用 opus。子 agent 不得自行运行 GPU 任务。

## 6. 收敛与停止

满足以下全部条件即停止：

1. 方向 1 完成：新开发集和新确认集已建立；量尺精度达到预定目标，或者明确说明为什么达不到。
2. 方向 2、3、4 各自完成有界筛选并给出趋势（包括“无效”），或者写明阻碍。
3. 有希望的配方已经过新确认集检验，或者明确没有值得确认的配方。
4. 中文报告（`docs/research/` 下）诚实给出 0 个、1 个或若干个通过确认的配方，以及代价与适用范围。

只因资源或外部原因停下时，报告写“尚未收敛”。
