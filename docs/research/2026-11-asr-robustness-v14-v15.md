# ASR 稳健性 v14–v15：w0 模型不变的守卫、补窗与专名后校正

## 状态
concluded。v14、v15 均于 2026-11-09／10 当天起草、立项并结题；v15 的补跑与翻译影响实测在 2026-11-10／11 完成。本轮进产品的只有 A 守卫（[ADR-0030「复读 repeat-strict」](../adr/0030-asr-window-plausibility-guard.md#复读-repeat-strict)，原 ADR-0023，已实现）；B、C3 不进。守卫后来又由 [ADR-0030](../adr/0030-asr-window-plausibility-guard.md)（`guard-v3`，加语速与已知幻听句两条规则）扩展，那一步不属于本研究。

## 时间
v14：2026-11-09 立项并结题。v15：2026-11-10 立项并结题，翻译影响阶段补跑到 2026-11-11。

## 问题
产品中文字幕错误约四分之三来自 ASR，翻译侧已基本饱和。在不换 w0 模型、不改 VAD 参数的前提下，三类后处理能否降 CER 或堵住缺陷：A 幻觉／重复守卫，B 窗内无字子段补窗，C 日文转写的后校正（v15 收窄为"只允许按专名表替换"）？

## 策略
- v14：A 置空（压缩比 >2.4、触顶、`avg_logprob` <−1.0 等信号）与对问题窗口加 `no_repeat_ngram_size=5` 单次补解；B 对窗内 ≥0.5 s 且无字的 VAD 子段重解码（先离线估上限，不够则不跑）；C 用 Strata 上的 Flash-Next 做日文后校正（C1 无表、C2 注入专名表，提示 v1／v2）。门：两部都降且合计 ≥0.3 pp。
- v15：A 按"安全网"（零误报、拦住已知复读窗）而非"降 CER"选规则与动作（置空／折叠重复／补解后折叠）；B1 实跑，只报数不设门；C3 为只按专名表替换，C3a 纯规则版（离线）、C3b Flash-Next 判定版；条件触发后量对翻译的连带影响（用户裁定直接跑）。
- 不换模型、不改 VAD、不做多次解码挑选；`cross` 不在范围（ADR-0003「产品 STT 引擎」，原 ADR-0012）。

## 环境与版本
- w0：faster-whisper 1.2.1＋ctranslate2 4.8.3，large-v3（CT2），新 Pyannote VAD，MMS `jpn` 对齐（产品 W0 配方）。
- C 臂：Strata 0.2.12（build 0.1.58）上的 Qwen3.8-Flash-Next IQ3_S，不加参数启动（DFlash2）；HF III 专名表用产品建表配方 `q3-names-v1`（最多 5 次尝试取第一张合格表）。Strata 需整机可用内存 ≥52 GiB，v15 首次因可用内存不足推迟，重启后补跑。
- 判读：Opus 子 agent 只读抽看（用于被标记窗与被改 cue 的归类，不设门）；翻译影响阶段的裁判见"测试"。GPU RTX 5080。

## 测试
- 数据：2 部日语电影（HF II／III）的产品 w0 整片输出与官方参考 SRT；A 的规则扫描额外盘点 101 个 w0 样本（5618 个窗口：产品整片、VAD 参数变体、整片与窗口 demo、国会录音），由 Opus 判读被标记窗是否为正常语音。
- 指标：官方整片口径 CER（基线 HF II 16.81%、HF III 13.77%）；单元口径 CER（参考与产品 cue 按时间重叠成单元，分 exact／light／heavy／missed 桶，与官方口径差约 1 pp）；C 另报改好／改坏／无影响、人名命中率、有害率。两种口径都把删除计入 CER，所以守卫值不值由整片 CER 决定。
- 翻译影响（C3 头写法变体 `c3a-entity` 对基线，Q3 规则翻译）：产品 ASR 源成对盲评，判分 profile `v5-asr-pairwise-v1`（Claude Opus 5.5 裁判，参考日文加语境、盲序 A／B 两份中文），Δ为候选罚分减对照罚分，单元 bootstrap CI90。

## 结论与去向
- **A 采纳**：`repeat-strict`＋折叠（折叠后仍命中则置空），产品 W0 配方 id `w0-faster-whisper-large-v3-guard-v2`（[ADR-0030「复读 repeat-strict」](../adr/0030-asr-window-plausibility-guard.md#复读-repeat-strict)，原 ADR-0023）。验收：HF III 第 51 窗被折叠（94 → 31 字），官方 CER 13.3973%；HF II 守卫零命中、与基线逐项相同。收益是堵住偶发整窗复读，不是平均 CER。
- **B 不进**：补窗重解码净变差。**C 不进**：v14 自由校正收益不足 0.3 pp 且大量改写；v15 的表内替换（含纯规则头写法版）对译文无可测收益，翻译注入的专名表已覆盖其作用（用户 2026-11-11 裁定 B、C3 不进产品）。
- 没有待裁定项；"STT 下一轮的对象"关闭，不提议新轮次，立项由用户提出。

## 教训
- 模型不变的后处理在这两部电影上能触达的编辑量不到两部总编辑量的 6%（幻觉窗约 40、空子段 ≤110、专名与同音字约 44）；其余是长窗漏转、窗口外的参考文字与普通替换，只能靠换模型、改 VAD 或改分窗。
- 守卫应按"安全网"判：先要对真实语音零误报，再看拦住多少；压缩比与 `avg_logprob` 单独置空会误伤歌词和短台词。
- 把窗口置空会把替换与插入换成删除，CER 收益看整片口径，不看拦住多少错字。
- 专名表里"转写中出现最多的写法"常常就是 ASR 的习惯性误写，规范写法应取表的头写法（`entity_ja`）；评估时参考字幕的汉字／假名惯例会抬高"有害率"，这是量尺问题。
- 两处立项条件写得不一致（A2 进入条件、B0 的分摊口径）会造成越权争议，立项文档应把同一条件只写成一句。
