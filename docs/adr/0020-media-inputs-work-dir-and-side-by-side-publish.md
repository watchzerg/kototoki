# ADR-0020：音频也作输入、工作目录移出目标目录、双语字幕发布到源文件旁

状态：已接受（2026-11-08，用户决定）。替代 [ADR-0007](0007-bilingual-subtitle-pipeline-architecture.md) 第 7 点中工作目录的位置、第 9 点中"`<output_dir>/.work/lock`"、第 10 点（三份 SRT 一起发布、按 `published.json` 判定覆盖、`force`）；第 8 点"从视频容器解码"扩展到音频文件。
范围：产品包 `kototoki/` 的输入范围、工作目录布局与发布。不改任何 STT、建表、翻译配方与身份。

## 决定

1. **音频文件也是输入。** 扫描 `input_dir`（递归）时扩展名清单默认为视频 `.mkv .mp4 .m2ts .ts .mov .avi` 加音频 `.wav .flac .mp3 .m4a .aac .ogg .opus .mka`（配置键 `[input] extensions`，替代 `video_extensions`）。视频还是音频由 ffprobe 判定：除封面图（`attached_pic`）外没有视频流即为音频。音频文件走同一条阶段链，只是不做原音轨流复制（`audio.<ext>`），仍按同一配方解码、下混、重采样为 `audio-16k.wav`；时长校验改对所选音轨的时长（无流时长时用容器时长），且解码短于它只告警、不判截断：没有画面要对齐，而 VBR MP3 缺 Xing 头时 ffprobe 的时长是按码率估的。视频输入仍是短于视频流超过 1 s 判失败。
2. **工作目录移出目标目录。** 新配置键 `[paths] work_dir`，默认仓库内 `.local/work/`（已被 Git 排除）；`[paths] output_dir` 删除。每个目标目录在其下有一个子目录 `<work_dir>/<input_dir 末段名>-<绝对路径 sha12>/`，内含 `lock`、`input.json`（目标目录绝对路径）、`index.json`、每片 `<id>/`、运行日志与 server 运行证据；`cache/`（`HF_HOME`／`TORCH_HOME`、模型核对缓存）在 `<work_dir>/cache/` 由各目标目录共用。目标目录改名或移动后对应不上旧子目录，从头重跑。`work_dir` 不得位于 `input_dir` 内，也不得位于仓库内 `.local/` 以外。
3. **只发布双语字幕，写在源文件旁。** 最终产物只有 `<源文件所在目录>/<主名>.ja-zh.srt`；`ja.srt` 留在工作目录，不再发布单独的 `zh.srt`。无语音的文件同样发布零条目的 `ja-zh.srt`。
4. **已存在即跳过。** 扫描时源文件旁已有 `<主名>.ja-zh.srt`（只看文件名，不论是否本项目生成）即跳过该文件，不进任何阶段；要重做就删掉这份字幕。`[run] force` 与"按 `published.json` 判定覆盖"随之删除；`published.json` 只作审计记录（双语字幕的 SHA256、来源身份、翻译 run 目录）。
5. **主名冲突。** 同一目录里主名相同的两个输入（如 `ep01.mkv` 与 `ep01.mp3`）争用同一份字幕路径：按相对路径排序靠后的那个在扫描阶段报错、记为失败，其余照常。
6. **不迁移旧数据。** 旧 `<output_dir>/.work/` 的中间产物不读取、不迁移，由用户删除；新布局从头跑。

## 依据

- 用户决定（2026-11-08）：目标目录里的音频也要出字幕；中间文件不该污染目标目录；播放器按主名自动加载同目录字幕，因此只把双语字幕放到源文件旁。
- "已存在即跳过"比按 SHA 判定覆盖简单，且不会覆盖片源自带或用户自制的同名字幕。

## 约束与未关闭项

- 音频输入只经离线测试与合成 ffmpeg 测试验证，未用真实音频文件跑过整条链。音频输入不再因时长偏短而失败，代价是真正损坏、只解码出前半段的音频文件也会照常出字幕（只覆盖前半段），只在运行日志留 WARNING。
- 改了配方（如 cue 规则、翻译配方）后，已发布字幕不会自动重做；需删掉 `*.ja-zh.srt` 再运行（中间产物按身份续跑，只重做受影响的阶段）。
- 目标目录须可写；只读或网络盘上的目录未验证。
