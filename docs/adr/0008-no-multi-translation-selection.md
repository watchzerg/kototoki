# ADR-0008：不自动选用"翻译多次再挑选"的方法

状态：已接受。合并整理于 2026-11-08（保留现行规则；历次变更见[决定索引·演进链](INDEX.md#演进链)，原文见 Git 历史）。产品翻译现行配方见 [ADR-0029](0029-translate-per-cue-resolution.md)；规则本身不变。  
范围：翻译质量探索与产品的取舍规则。翻译基线与 H0 等历史身份见 [ADR-0021](0021-q3-strata-names-baseline.md)。

## 决定

1. 放弃 `mbr8s`（每批 8 个样本，按 bge-m3 语义共识逐条选择）与 `mbr8c`（逐条 chrF-MBR）：不进产品，也不做"高质量模式"开关。依附于它们的后续一并关闭，包括并行槽位的质量判分，以及按剧集／电影分配更便宜的 MBR 变体。
2. agent 设计探索方向、排序投向、给出建议或在无人值守执行中自行决策时，都不选"翻译多次"的暴力方法，也不把它们列为候选或推荐，除非用户在对话中明确要求。用户明确要求时按其范围执行，不外推到其他场合或下一轮。

## 范围

**受约束**：同一条字幕生成一份以上完整译文，再选择、投票或合并：

- 多样本或多 seed 生成，配合 MBR、共识或 reranking 选择；
- best-of-N，用裁判、QE 模型或打分器挑选；
- 多次独立全量翻译再投票（self-consistency）；
- 按共识早停的多样本，以及上述方法的任何更省版本（更小的 N、并行化、按类别分配）。

**不受约束**：产品已有的可靠性重试（每请求最多 2 次相同尝试）与降级（10→5→1）。两者只在输出无效时重来，不在多份有效译文中挑选。

**边界情况**：总生成量明显翻倍、但不属于上述任何一类的做法，如先整遍翻译以抽取术语再翻一遍，或翻译后整遍审校改写。交互时先问用户；无人值守时写进研究文档的"待用户裁定"，不执行。

## 依据

- v4 `mbr8c`：确认集 Δ −0.016（约 −4%，集中在剧集），墙钟约 6 倍（[v4 报告](../research/2026-10-translation-flow-v1-v4.md)）。
- v5 `mbr8s`：全新剧集确认集 Δ −0.036（约 −7%），电影未确认，翻译墙钟 6.3 倍；更省的变体（N＜8、早停）不在重复 seed 上复现，与低温组合也不叠加（[v5 结题](../research/2026-10-quality-v5.md)）。
- 产品中文错误约四分之三来自 ASR，翻译侧在产品输入上的收益上限约为总惩罚的 1%。用户判断几个百分点的质量收益换数倍墙钟不值得。

## 约束与未关闭项

- 产品翻译保持单次生成（现行 `q3-translate-v1`，见 ADR-0029）；研究侧 Q 线同样单次生成。后续质量探索在单次生成前提下找方向，如提示、上下文、术语、后处理与模型本身。
- v4、v5 的多样本代码（`archive/2026-11-18-pre-research-restructure:experiments/translation_v4` 的 `mbr8`、`archive/2026-11-18-pre-research-restructure:experiments/quality_v5` 的 `mbr_cheap.py`、`mbr_semantic.py`、`parallel_probe.py`）作为历史证据保留，只在用户明确要求时复用。
