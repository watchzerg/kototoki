## 接跑手册（每次启动或配额恢复后，从这里开始）

1. 运行 `uv run --locked --offline python -m experiments.translation_v3 status`。它只读文件，列出各 run 的生成进度、裁判进度、`judge-blocked.json`、队列和建议的下一步。**以它的输出为准，不以本台账的文字状态为准。**
2. 只读核对 GPU：PowerShell `Get-Process | ? ProcessName -match 'llama|python'` 和 `nvidia-smi`；读取 `.local/gpu.lock`。若锁被存活的 PID 持有，说明生成正在跑，不要再启动生成，也不要杀进程。
3. 生成（GPU，不消耗 Claude 配额）：用 `queue add` 加任务，再在**后台**运行 `run-queue`。它会跳过已完成的 run 和场景，中断后重跑即可续上。
4. 裁判（消耗 Claude 配额）：`judge --run <RUN> --backend cli`。
   - 退出码 75 表示配额用完或未登录，详情见 `judge-blocked.json`。
   - 此时不要循环重试。先去推进不需要裁判的工作（生成、统计、写台账），或者结束本轮，等配额恢复后再从第 1 步开始。
   - CLI 未登录时改用备用执行面：`judge --backend export` 导出待评包；再派 `model: opus` 的子 agent 逐包读取 `judge-queue/<packet>.md`，把结果写到 `judge-inbox/<packet>.json`；最后 `judge --backend ingest` 校验收录。同一对比较只能用同一种执行面的结果。
5. 统计：`compare --candidate <RUN 前缀> --control c0 --split screen-a`；判定规则以 `decision-policy-v3.json` 为准。
6. 每完成一个候选，在下方“执行记录”追加一条：假设 → 唯一变化 → Δ／区间／类别／critical → 判定 → 下一步。

**隔离**：主会话不读确认集的参考和裁判原文，不把参考或裁判反馈用于设计候选。确认集在 `locked-candidates.json` 写入之前不得生成。

**禁止**：续跑 v2 的任何任务；修改 v2 目录或 `experiments/translation_flow/` 的冻结代码；把 v2 的 Sol 分数与 v3 的分数混算。
