# X0 吸收 WhisperX 流程：适用性与隔离验证

状态：源码核查及两窗三臂验证完成；保留当时未通过无回归替换条件的结论  
最后更新：2026-10-05  
范围：原生 Windows／RTX 5080，Qwen-ASR＋同一 MMS；只研究流程策略，不升级环境或切换默认后端。

## 大白话结论

后续采用说明：用户随后明确，合理流程设计的采用不以有限样本显著涨分为前提，也不要求移植VAD。
据此已建立[X0 demo](../../experiments/x0_demo/README.md)及[ADR-0002](../adr/0002-x0-demo-flow.md)：
默认fixed30保留，另正式支持无VAD、全音频的cut-merge。新配方的候选切分再合并不同于本报告的历史energy算法，
不能继承这里的分数。以下结论保留为当时预登记比较的判断，不再作为建立demo或采用流程设计的门槛。

2026-10-05 再后续采用：用户在整片比较后明确采用 X0 新 Pyannote＋MMS，见[ADR-0003](../adr/0003-new-pyannote-baselines.md)。该决定替代 X0 无 VAD fixed30 的现行基线定义，canonical demo 的 CLI 默认仍为 fixed30、迁移待实现和验证。下文旧 Pyannote 过滤臂的建议与分数保持历史身份，不能转移给新 Pyannote；Whisper 专属 token、特征补齐及 CT2 解码仍不适用于 Qwen。

**值得吸收的是“在较合适的位置切片、保持原音频坐标及共用对齐接口”的思路，不是把 WhisperX 整套搬给 Qwen。**
低能量切点、保留全部音频的小样本确有时间收益：半秒内成功64→70／112，漏字50→48；
但插字23→25，第二片文字误差略退。因此它值得保留为研究候选，尚不值得替换默认固定30秒。

**本轮旧 VAD 过滤合并当时不建议加入默认 X0。** 虽然总体 CER 更低，漏字却增到55、半秒成功降到63／112，
还增加检测和加载成本；不能只看一个总分就说更好。
Qwen 已有独立解码和纯文字输出，MMS 也已共用；Whisper 的 token、特征补齐和 CT2 解码逻辑不适用。
没有出现符合预登记条件的无回归优胜组合，本轮停止扩展、不追调参数。

## 研究依据

本次先核对实际调用链，再决定实验。完整源码、固定版本及官方链接见
[源码核查](2026-10-05-x0-whisperx-source-audit.md)；运行前规则见
[最小验证方案](../plans/x0-whisperx-flow.md)。W0 的复用依据是
[demo](../../experiments/w0_demo/README.md)、[契约](../specs/w0-reusable-demo.md)与
[两窗验证](../testing/2026-10-05-w0-demo-validation.md)。

本研究时的 X0 定义是 Qwen 固定30秒、无 VAD＋MMS。旧 `run_cross.py` 默认仍用 Jonatas CTC，
所以不能仅凭旧 `X0` 标签取一份成绩作基准。本轮基准与变体都重新识别，并调用同一
`experiments/w0_demo/alignment.py::MmsAligner`，不把更换 CTC 的效果算到切片策略头上。

| 策略 | 核实的状态 | 本轮处置 |
| --- | --- | --- |
| 低活动切点、有界窗口、原坐标映射 | 可跨识别模型使用，但质量取决于音频和上下文 | 小样本验证 |
| Pyannote 过滤及 cut/merge | W0 有可直接复用实现；不连续块之间才跳过音频，块内保留静音 | 单独身份验证，不改 X0 默认 |
| 逐块独立、文字识别后再对齐 | X0 已逐窗重新请求、无前文 prompt，输出纯文字 | 无需重复移植 |
| Whisper 语言／任务／时间 token、EOT 过滤、CT2 beam 参数 | 与 Qwen tokenizer／生成器不是同一契约 | 不移植 |
| Whisper 补到30秒、冻结 Mel、Torch STFT 数值 | 即使维数相同，也不能替代 Qwen processor／mask／音频 token 长度规则 | 不移植 |
| MMS jpn 加载、归一化、标准 CUDA CTC、text_only 和全文保留 | 已有共用实现 | 复用并固定，不能称为新增质量收益 |
| batch、重叠去重、自动回退、字幕句切 | 会增加独立变量或产品责任 | 本轮不叠加 |

Qwen 官方旧 wrapper 自身已有低能量切点 helper，本机 native HF 路径未调用它。
本轮 `energy` 是受30秒上限约束的独立策略，不声称逐行移植 WhisperX 或与旧 Qwen helper 等价。
WhisperX 论文的 Whisper 收益也不能直接当成 Qwen 证据。

## 实验身份和可复现边界

入口为 [`experiments/x0_flow/`](../../experiments/x0_flow/README.md)。只增加切片策略、Qwen Adapter 和跨环境阶段连接，
复用 W0 的 `PyannoteVad`、`FrozenVad`、`read_audio`、`run_pipeline` 校验与 `MmsAligner`。
历史 runner、W0 recipe、依赖和 X0 默认均不改动。

私有清单 `.local/x0-flow/pilot-v1/study.json` 在新识别前冻结，采用 II／III 各 window-01，
各300秒、mono16k PCM16，源偏移分别351.402125及366.2666875秒。
两窗已多次用于研究，选它们是为了复用输入身份及历史对照，不是独立保留集。
本轮不宣称它们覆盖耳语、歌声、重叠对白等全部难场景。

- `fixed30`：连续覆盖全部原样本的30秒窗口。
- `energy`：每块上限前5秒内，以100ms 网格比较前100ms RMS，最小值并列取最晚切点；末尾不足30秒保留整体。无阈值、无神经 VAD、无删除、无重叠。
- `pyannote`：现有 W0 checkpoint／onset0.5／offset0.363／min-cut／merge，按原时间跨度组成最长30秒连续块，不添加新的上下文 padding。

`fixed30` 对 `energy` 隔离切点策略；`pyannote` 对 `fixed30` 比较现有过滤合并这一完整策略。
后者同时改变保留范围、块数和上下文，不能据其结果进一步断言“单纯删静音”的因果收益。
若要分离检测得分切点与删除的作用，需另做同检测器的保留全部音频实验。

ASR 固定 Qwen3-ASR-1.7B-hf、本机 revision、BF16／SDPA／greedy／batch1／ja／max4096；
不引入 Whisper 特征、token 或 Qwen 原生 FA。MMS 全部固定 jpn、CUDA FP32、同归一化和显式 TF32 作用域。
三阶段顺序运行，模型不同时驻留；私有结果记录源码快照、输入／模型哈希、包版本、GPU证据、完整文字及字符时间。

本机为 Windows 11、RTX 5080（16303 MiB）、驱动616.92、Python3.13.16。
Qwen 环境为 Torch2.14.1＋cu130、Transformers5.18.0；MMS／Pyannote 环境为
Torch／TorchAudio2.8.0＋cu128、Transformers4.57.6、Pyannote.audio4.0.7。
使用既有固定环境是控制变量，不是安装或升级建议。
Qwen revision 为 `bcd2b5b7f32b480ab5790554cfa8347f246a14f3`；
MMS 为 `facebook/mms-1b-all@3d33597edbdaaba14a8e858e2c8caa76e3cec0cd` 的日语 adapter。
VAD checkpoint SHA256 为 `0b5b3216d60a2d32fc086b47ea8c67589aaeb26b7e07fcbe620d6d0b83e209ea`。

完整进程成本按 plan＋ASR＋align 三个进程墙钟相加，包含导入、加载、校验、输出，排除评分和资产获取。
阶段内部计时另报；不可把只重放 ASR 给 MMS 的几秒成本冒充完整链。
新 ASR 和新 MMS 都实际执行，阶段间保存的文字只是跨环境传递，不是复用历史识别缓存。

## 评价限制

完整文字使用现有规范化和字符编辑距离，报告替换 S、删除 D、插入 I；重复只作字面候选诊断，不删除输出。
时间按同内容跨度与 SRT 参考比较，保留全部参考分母、不可测及失败；同时看严格半秒成功、严重偏移及共同可测集合。
SRT 显示时间不是人工声学真值。插入 I 不能直接叫幻觉，未收录的真实歌声不能叫 VAD 误报。
两窗不计算 bootstrap，不宣布整片或跨作品有效；已知旧 X0＋MMS 的约31秒极端偏移位于 III window-05，
本轮没有覆盖它，不能声称修复该问题。

## 实测记录

### 基准适配等价性

新 `fixed30` 两窗的20个原始分段、完整1304字符、全部1304个字符单元与历史
`.local/results/jctc-mms-full-v2-hf-{ii,iii}-window-01-x0-mms/result.json` **严格相等**。
两窗分别598／706字符，不只比较规范化文本或近似时间；记录在私有 `baseline-parity.json`。
这支持把后续差异归到分片策略，排除了本次 Qwen Adapter 或共享 MMS 接入在这两窗改变基准输出的情况。
它不表示历史基准本身没有识别和对齐错误。

两片新 Pyannote 的原始 score hash 和合并窗口也与 W0 已验证记录一致，见 `vad-reuse-parity.json`。
三组的实际 ASR／MMS 输入样本范围一致性由评分前校验另行检查；不是只凭配置名称推定相同。

本轮不支持“加 VAD 就会明显省时”。这也不证明换 CPU VAD、常驻模型或批量方案的成本，它们没有测试。
Qwen PyTorch 峰值 allocated 六组均约4.048 GiB；没有新增整卡或 MMS 进程峰值采样，不能据此宣称总内存下降。

### 严重偏移和重复逐项核对

fixed30 有1条可测偏移大于2秒，另外两组均为0；三组均无大于5秒的可测项。
该条为 `hf-ii-cue-0049`，fixed30 的3.847秒在 energy 中变为0.254秒，pyannote 中为1.964秒；
**两组都仍可测，没有通过让该条丢失时间来消除极值。** 这是相对字幕参考的个案改善，不是全片声学同步保证。
本轮没有覆盖已知 III window-05 的约31秒极值。

相邻块“规范化后后缀＝下一块前缀，长度至少2字”的字面重复候选：fixed30与energy两窗均0，
pyannote在II有1处2字候选。完整文本最长连续重复片段字数，II／III分别为 fixed30 8／2、energy 8／3、pyannote 6／2。
这些是诊断计数，可能包含真实重复台词；没有听辨就不能把它们全部记成错误，更没有做自动去重。
本轮没有证据证明某策略解决了跨片重复，也没有独立歌声标签来比较歌声召回。

## 采纳范围与后续问题

| 判断 | 本轮处置 |
| --- | --- |
| 共用 source-window／完整文字／MMS 接口、设备与身份核验 | 值得继续复用，已用于本次隔离原型；工程收益与质量收益分开 |
| 低能量切点、保留全部音频 | 有局部实测收益，保留独立候选；本轮因 III 插字／CER 回归停止扩展，不改默认 |
| 当前 Pyannote 过滤＋merge | 有些错字和个案时间变好，但漏字、覆盖、严格时间与成本有退步；不建议加入默认 |
| Whisper 特征、token／CT2 解码、原生句级 cue | 不适用或不属于当前目标；不移植 |
| 独立解码、纯文字后对齐、MMS归一化与失败保留 | X0 已有或已共用，不再计作新增优化 |
| VAD得分辅助切点但不删除音频、其他CPU／GPU VAD | 尚未验证；若继续，应固定同一检测器只改变保留政策，再独立评估检测器 |
| padding、重叠去重、批量／常驻模型、长窗口 | 尚未验证，必须分开身份，不能把本次切点结果外推过去 |

后续若继续研究，优先用独立场景及人工对白／短声／配乐／歌声标注确认取舍，
不要在这两个已接触窗口反复调阈值再称为泛化改善。歌声保留不算误报；评分参考未收录的真实歌词不能直接当幻觉。
本轮实验当时没有新增采用 ADR，保留原 X0 的固定30秒、无VAD、MMS 定义；后续流程及新基线采用分别见 ADR-0002 和 ADR-0003。

## 验证、产物与剩余工程限制

- 六条新链的 Qwen 参数／输入／输出及 MMS 前向／标准 CTC 均有实际 CUDA 证据；没有CPU回退、生成触顶或对齐失败。
- 独立评分核对每段 float32 PCM hash、MMS归一化源样本范围、完整全文、阶段依赖及源码身份；六组均通过。
- 六组 Qwen 权重／配置／生成配置／安装源码、MMS模型文件／有效参数及冻结实验源码逐项相同，记录于 `shared-model-integrity.json`；全部阶段均未导入WhisperX。
- 推理前核验派生音频、参考和源字幕；评分前后重验两片原FLAC／SRT、派生音频／参考及评测源码，均与冻结哈希一致。未修改原素材。
- 原型8项离线测试在后端环境全通过；根环境5通过、3因NumPy缺失跳过。共用W0的35项根环境测试27通过、8项可选依赖跳过；没有宣称跳过项已在本轮补跑。
- 既有组件评测11项测试及新评分辅助函数的GPU证据／cap／PCM错误检查通过；新增代码编译及7份受影响文档的本地链接检查通过。
- 私有输出包含 `study.json`、各臂 `source/`、`plan.json`／`asr.json`／`result.json`／`transcript.txt`、`process-costs.json`、`baseline-parity.json`、`vad-reuse-parity.json`、`shared-model-integrity.json`及`evaluation-v1/summary.json`／`integrity.json`。完整台词与音频未进入文档。
