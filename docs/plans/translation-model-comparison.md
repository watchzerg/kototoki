## 已确认范围

| 模型家族 | 本轮必须纳入的候选 |
| --- | --- |
| Hy-MT2 | 7B Q8_0、30B-A3B Q3_K_M |
| TranslateGemma | 12B Q8_0、27B Q3_K_L |
| Tower+ | 9B Q8_0 |

五个版本分别记账、分别报告；30B／27B 不作为可省略的后续追加。具体路径、revision 与 SHA256 以资产指南及其本地 manifest 为准。

主比较采用 `V2-native-adapted`：候选使用相同冻结窗口、允许的日文上下文与计分 IDs，各自保留原生模板。窗口内合并、多 ID 或输出适配可以采用，但须保留可靠计分映射。超出窗口的背景、全文预分析和跨窗记忆属于独立 `P-flow` 扩展，不混入本轮主比较。

TranslateGemma 若需要辅助模型从整段译文映射回计分 IDs，采用显式 assisted 配方，保存原生译文、映射与辅助成本。纯映射只关联原生中文字区间，不改写、不读取中文参考或裁判反馈。其他候选无需为了形式一致而增加相同辅助步骤。这样的结果比较具体翻译流程，不将辅助收益归为裸模型能力。辅助角色、输入范围和失败口径在 dev 验证后冻结；无法可靠映射时记录失败或不可评，二者按事先约定的交付契约区分。

当前开发实现的显式适配是 `native-scored-groups-v4`：依据同一冻结窗口的原始 `translate_ids`，将日文按计分／非计分身份划为最大连续组，由本地辅助模型关联到未改写的原生中文区间。一个计分组保留全部原始 IDs，但中文字只保存一次，不伪造逐 cue 对齐。中间出现非计分条目时必须另分组，不能把整段当核心。评价仍对原窗口的全部原始计分 IDs 给出同一 0–4／0–2 分数；自定义结构校验核对完整区间、来源身份与原生文字，不证明语义边界正确。此格式不适用外部逐 ID JSON validator，并显式记录该边界；未扩大上下文、未加跨窗记忆，因此仍属于 `V2-native-adapted`，不是 `P-flow`。映射无法确定保留 null；实际原生翻译交付失败按交付零分记账。该格式已通过开发语义闭环并纳入正式冻结；结构通过本身不证明语义归属正确。

本轮语义评价采用 `sol-high-auto-v1`，按其要求使用 `gpt-6.1-sol / high` 的全新请求。流程草案中的人工日语复核、人工重组或人工裁决不属于本轮执行步骤；自动处理无法解决的问题保留明确终态。候选流程内的辅助检查与评估裁判分离，参考答案及裁判反馈不进入翻译、映射或修订输入。

## 准备状态与剩余验证

2026-10-06 的只读审查已完成：评估库全部 2,479 个文件冻结核验通过；输入／参考关联、计分 IDs、分类视图和划分检查通过；结构 validator 自测通过。五份模型文件存在、大小匹配，manifest 均为 `verified`；冻结时完整权重哈希沿用资产指南中的核验记录；正式推理后已重新扫描全部五份权重，SHA256 均与冻结身份一致。

数据实际规模为 smoke 15 窗口／75 条、dev 41／204、test 83／414；运行时仍从冻结文件发现实际清单。smoke 是 dev 子集，不重复计分。整片候选字幕未经全量审定，本轮“完整评估”指完整固定 test，不代表完整影片或整个字幕库。

五版本均已通过真实 GPU 原生 smoke/dev 运行，模板文本及实际 token 输入均核对；30B 使用独立标识的 loader 兼容修正，27B 也已在本机运行。TG 纯映射各有 2/16 开发不可评项，作为已知覆盖限制冻结。优先一次加载一个模型，记录实际设备驻留；改变量化、模型或驻留方式须另记配置身份，不能静默替代后混报。

## 执行阶段

### 1. 实现三套 demo，验证五个版本

先建立最小可复用翻译路径，以合成样本和少量 smoke 检查加载、语言方向、原生模板、停止条件、输入输出预算、源文覆盖和映射。实现需要的运行环境与薄适配层，复用现有资产和校验工具。预分析、glossary、compact、反思及完整显示编辑不作为首轮全部必做项。

完成条件：五个版本逐一留下实际运行证据或明确阻碍；可运行路径能保存原始结果、尝试记录和成功／失败终态。某版本仍无法运行时保留未完成身份，并继续不受影响的工作，不以小模型替代后宣称五候选完成。

### 2. 在 smoke/dev 上联调完整评估闭环

覆盖完整 smoke，并加入 dev 中四条计分的窗口 `11-1-2` 或等价合成边界，避免假定每窗五条。联调机械检查、结果映射、主评、盲复评、必要裁决和程序汇总；用合成故障覆盖漏项、截断、映射不可评、裁判失败、争议未决及作品窗口数不等。

在 dev 上反复修复 demo 和评估逻辑，按实际问题选择必要优化。现有 validator 不代替逐窗口终态账本；原始输出与校验失败均保留，冻结库工具不原地修改。辅助模型具体选择和批次策略可以在此阶段确定。

完成条件：端到端输出可核对、可恢复，所有预期输入都有终态，失败与缺分不会被汇总丢弃；语义评估确实执行，而非仅通过 JSON 检查。记录实际耗时和裁判工作量，确认正式执行可行。

### 3. 冻结正式比较配置

依据 dev 结果固定五候选身份、运行环境、输入范围、模板、参数、辅助步骤、恢复上限、评估提示和汇总规则。原生接口差异可以保留，数据范围与评分对象须一致。具体冻结字段与产物遵循自动评估流程，不另维护第二份评分规约。

完成条件：运行清单和配置可复现，小样本闭环通过；未解决的兼容性问题、映射限制和预计覆盖明确列出。尚有候选无法参与时，后续成绩明确为不完整比较。

### 4. 执行完整固定 test

对五个候选逐窗口执行完整 test，按自动流程全量主评，再对风险与固定抽样窗口的并集进行复评及必要裁决。保留全部预期分母，电影和剧集分别按作品等权汇总。

允许修复内容无关的工程故障，保留旧产物、更新版本并统一重跑受影响任务；评分实现修正也须对受影响候选一致重算。若根据 test 表现改变提示词、上下文、恢复策略或裁判口径，另记开发后的新实验，不再声称该 test 未用于调优。test 参考和裁判反馈不能用于逐例修补候选译文。

完成条件：每个预期候选／窗口都有可追溯的结果或失败／未决记录；所有必需评估任务已完成或明确记录阻碍，程序汇总与原始账本一致。

### 5. 输出最终报告与复现入口

报告五个版本的分作品及电影／剧集成绩、严重错误、交付可靠性、未决覆盖、复评稳定性、总耗时和显存。区分模型原始输出、辅助流程成本和评估成本；给出适合当前机器与此类字幕的条件化建议。缺分区间允许排名变化、差距过小或复评不稳定时，明确无法稳定区分。自动裁判结果不表述为人工验证准确率，片段测试不表述为跨作品泛化或音画同步验收。

完成条件：交付可读中文报告、机器可核对的汇总、原始运行证据与复现命令，并更新评估入口、demo README 及本计划状态；五候选未全部完成时报告明确标为不完整。
