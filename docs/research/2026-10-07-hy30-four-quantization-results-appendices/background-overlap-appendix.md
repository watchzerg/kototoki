系统 RAM／commit 完整观测数、缺测数及分布已按全 session、各 GPU phase、请求活跃／无本正式请求三个口径保存于 `resource-missingness.csv`。目标进程 working set／private commit／WDDM dedicated/shared 字段也保留；它们针对 GPU server PID，不是裁判 PID。进程内存各有 2,052 条无目标 PID 缺测；WDDM 两字段另有各 147 条缺少 PID counter instance，缺少实例不能当作零。加载前无目标 PID 的空值属于预期缺测，详见 `overlap.json` 的 null_reasons。

逐阶段 UTC 和实际请求重叠在 `phase-overlap.csv`，空闲／加载／预热／回归／新增集／卸载／释放均单列。`time_scope=monitor_observed_phase` 对应资源监测标签；worker 事件经轮询转发可能滞后约一秒，因此另存 `worker_original_phase_lifetime` 对齐原始 worker UTC。失败阶段的终态也保留，阶段生命期不证明集合已全部成功。`monitor-cpu.csv` 保留采样间隔中位数和最大值；间隔来自实测，0.25 秒是目标间隔。聚合 CSV 与每个原始 resource-summary 的 sample_count 全部逐 session 对账。

裁判进程 CPU seconds、working set／private commit、系统 CPU 利用率和网络发送／接收 bytes 均未采集，数据记为 null。不能依据请求数量、CLI 时间或整机 RAM 反推这些数值。全局 reservation、串行网络阶段和实际请求并发是调度证据，不能替代 CPU／网络计量。

后台裁判与性能在时间上重叠，但没有相同 GPU session 的无裁判反事实。量化内核、生成长度、显存压力、时钟／温度、缓存和其他后台进程也可能影响性能；不能将轮次或候选差异单独归因于裁判并行。首轮“无正式裁判”也不证明整个 Windows 主机空闲。资源峰值是采样观测，短于采样间隔的峰值可能漏测；GPU 接收时刻与内存观测时刻异步。

来源与复核：`source-hashes.json` 保存 16 份 runtime-final、resource-summary、resource-events，四份已终结聚合产物及相关执行代码的 SHA256；权重不重复哈希。`stage-metadata-projection.json` 仅白名单调度元数据，原始 journal 使用截止前完整行前缀 hash。`request-metadata-projection.jsonl` 不包含 packet、译文、参考、评分或 rationale；截止前已结束的 attempt 保存原始元数据 hash，截止时在途的记录只保存规范化 as-of 投影 hash，后续完成不会改变本快照。
