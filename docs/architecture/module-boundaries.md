## 依赖方向

- 允许：X0 → W0（`read_audio`、`setup_runtime`、`gpu_lock`、`read_vad_manifest`、`MmsAligner`）；外部 VAD 阶段 → W0（`gpu_lock`、`read_audio`、`vad_candidates`）；W0／X0 → `kototoki_eval.schema`。
- 允许：完整 SRT 流程 → 逐窗翻译运行时（`translation_demo.adapters`、`client`、`run`、`translation_demo_runtime` 的纯函数）。
- 现存的当前→历史依赖（只读导入，不得扩大）：X0 → `experiments.qwen.run_qwen`（Qwen 资产身份常量与 `checkpoint_identity`、`check_gpu`）；完整 SRT 流程 → `experiments.translation_flow.srt`（SRT 读写与覆盖校验），其测试另导入冻结的 `translation_flow.v2_prepare`／`v2_recipes` 做 C0 等价核对；W0 测试导入 `experiments.framework_equivalence` 作数值参照，运行时不导入。
- 产品包 `kototoki/`（分层图见[架构总览](INDEX.md#依赖与装配)）：依赖只向下，编排 `job` → 媒体、cue、内嵌字幕清洗 `embedded`（纯函数，只依赖 `srt`）、合并、阶段计划 `plan`、专名 `names`、翻译子系统、共享 session 所在的中间层 `strata` → （`names` 与翻译都经中间层 `strata` 与 `local_client`）基础层（`config`、`recipes`、`artifacts`、`srt`、`workers/protocol`、`schema`、`logs`、`procs`、`judge`、`guard`；`procs` 是进程原语，只用标准库与 ctypes；`judge` 为 `cross` 引擎新增，`guard` 为 ADR-0023 的复读守卫，两者都不导入 torch、推理模块、`experiments` 与 `kototoki_eval`）。`plan` 与 worker 壳同在中间层：壳导入 `plan` 取身份与模型清单；`plan` 只在核对翻译阶段时延迟导入翻译子系统（`translate.plan`），壳不会触发这条边。四条硬规则：
  - **编排层不导入任何推理模块。** `job` 只以 `sys.executable -m kototoki.workers.<stage> --jobs <path>` 启动阶段 worker，与它们的全部通信是 jobs 文件、工作目录里的产物和退出码；`tests/core/test_job.py` 的禁止导入测试（`torch`、`ctranslate2`、`faster_whisper`、`transformers`、`pyannote`、`torchaudio`、`torchcodec`、任何 `experiments.*`）守门。编排不导入 worker 壳；期望身份来自 `plan`，模型核对只用 `workers/gpu.verify_models`（导入时不加载推理库）。
  - **推理模块互不导入。** `vad`、`asr_*`、`align` 只依赖基础层，各自在独立进程里加载模型；阶段之间只经产物文件交接。三壳共用的入口、读 WAV、模型核对与 CUDA 守卫在 `workers/gpu.py`，只被 worker 壳与编排导入，不属基础层。
  - **基础层不依赖 torch、ffmpeg、网络与上层。** 它是所有离线测试的根基，编排器可以直接导入。`judge` 同受此限：不导入 torch、`experiments.*`、`kototoki_eval`，`normalize` 复制过来而不引用（与 `schema.validate_transcript` 同一做法）。`guard` 也是：只导入 `recipes` 与 `judge.normalize`，算法从研究脚本复制。
  - **产品包不导入 `experiments.*` 与 `kototoki_eval`。** 历史实现只复制不引用；`kototoki_eval/` 继续承担评分，产品侧的 `validate_transcript` 复制在 `kototoki/schema.py`。`tests/core` 的全仓库边界测试用 AST 扫描 `kototoki/` 全部模块守门，并要求 `tests/core` 自身不导入 `experiments`（[ADR-0025](../adr/0025-product-package-boundaries.md)）。
- `kototoki/local_client.py`、`kototoki/strata.py` 与 `kototoki/names/`（[ADR-0014](../adr/0014-name-consistency-in-product.md)、[ADR-0019](../adr/0019-product-translation-q2.md)、[ADR-0022](../adr/0022-product-names-on-strata.md)、[ADR-0025](../adr/0025-product-package-boundaries.md)）的现行规则：
  - **`local_client` 是中间层，不属基础层**：它发 HTTP，基础层不得导入它；`strata`、翻译子系统与 `names` 单向依赖它（它只依赖基础层）；不导入 torch、`experiments.*`。产品里没有 llama-server 的进程生命周期代码（ADR-0025 起在研究侧 `experiments/translation_v3/llama_server.py`）。
  - **`strata` 是中间层，不属基础层**：起停 Strata 进程（`strata` CLI）、轮询显存（`nvidia_smi`、`wait_for_free_vram`）、核对身份、持有共享 session，只依赖基础层与 `local_client`（`LlamaClient`、`InfraFailure`）；不导入 `names`、翻译子系统、torch、`experiments.*`。`names` 与翻译子系统都单向依赖它；研究侧脚本也直接导入它（`translate/strata.py` 已删除）。翻译子系统不导入 `names`，只读它写出的 `name-table.json`（经 `plan` 传入内容）。
  - **`names` 只依赖基础层（`artifacts`、`srt`、`recipes`）与中间层 `strata`（`Session`、`StrataRefused`、`MODEL` 等身份常量）、`local_client`（`InfraFailure`、`explicit_oom`）**，不导入 `config`、torch、`experiments.*`（历史实现只复制），不导入翻译子系统。
  - **编排以普通导入使用 `kototoki.strata`、`kototoki.names`、`kototoki.translate`、`kototoki.merge`**：这四个模块只依赖标准库层面的产品代码、不导入 `plan` 与 `job`、不加载 torch，直接导入不成环；`tests/core/test_job.py` 的禁止导入测试照常守门，测试以属性 patch 替换其中的函数。`plan` 核对 names 阶段时延迟导入 `names.recipes` 只取 `BUILD_RECIPE_HASH`（不需要 `names.plan`：建表没有 run 目录，表不当前即需要模型），worker 壳不会触发这条边。
- 禁止：`kototoki/job.py`、`kototoki/__main__.py` 导入 `torch`、`ctranslate2`、`faster_whisper`、`transformers`、`pyannote`、`torchaudio`、`torchcodec`；`kototoki/` 任何模块导入 `experiments.*`（历史实现只复制）。
- 禁止：`kototoki_eval` 导入任何推理或 `experiments` 代码；推理入口导入 `experiments/provision`；当前模块写入或修改历史实验包（`translation_flow/v2_*`、`translation_judge/`、`translation_eval/` 等冻结证据）。
- 文件契约代替导入：W0／X0 不导入外部 VAD 阶段的入口，只读其 manifest；评分 CLI 只读 `result.json`；各入口只读语料准备产出的 WAV 与参考 JSON。

## 状态与契约

- 每个运行目录由创建它的入口独占：`.local/w0-demo/`、`.local/x0-demo/`、`.local/vad-comparison/`、翻译 `--output-dir` 及 v3 根目录（默认 `.local/translation-evaluation/hy30-flow-v3/`）。目录已存在即拒绝；结果、全文和缓存只写在该目录内。
- VAD manifest 是窗口的唯一权威：runner 将其原字节复制为 `vad-manifest.json` 并记录 SHA256，运行中来源变化即失败。manifest 中的 `stages` 是外部进程成本的快照，不计入 W0／X0 自身 `stages` 或 `wall_s`；回放 manifest 不是新的 VAD 推理（`fresh_inference=false`／`precomputed_external_manifest`）。
- 输入身份以内容为准（`file_sha256`、`pcm_sha256`、采样率、声道、样本数、时长、`offset_s`），路径可以不同。
- 运行身份（recipe 名、v3 `recipe_hash`、模型 SHA256、冻结源码哈希）是派生结果可比的前提；同名配方内容不同时拒绝续跑。
- X0 子进程之间只通过运行目录中的 JSON 交接（`request.json` → `plan.json` → `asr.json` → `alignment.json`），每阶段重验源码与输入哈希。

## 并发与生命周期

- `.local/gpu.lock` 是所有 GPU 作业共用的互斥文件，存在两种实现：`experiments/w0_demo/run.py::gpu_lock`（O_EXCL 创建，写 `pid`＋`recipe`，退出时删除；W0、X0 父进程、CUDA 设备的外部 VAD 阶段使用）与 `experiments/translation_v3/procs.py::ProcessLock`／`server.py::GpuLock`（写 `pid`＋`pid_created`＋`run_id`；存活持有者在时退出码 3，死锁只在 `--break-stale-lock` 时替换）。两者都不抢占、不杀进程。上面只是研究侧的两种主要实现：全仓库约有 10 个写入方、4 种 payload 形状，除产品（`kototoki/procs.py::ProcessLock`）外都在 `experiments/` 与 `scripts/smoke/`；全部以 `O_EXCL` 创建，互斥有效；只有产品与 v3 记录 `pid_created` 并处理过期锁。统一这些写入方不在当前范围（[ADR-0025](../adr/0025-product-package-boundaries.md)）。
- 产品包只有一个服务进程：Strata（几乎占满整卡），由共享的 `strata.Session` 在第一次真正需要请求模型时启动（可能在 names 建表，也可能在翻译），names 与 translate 两阶段之间不停，整批共用；启动前 `strata launch --status` 必须为空（不抢占别人的 launch），空闲显存达到 14000 MiB、可用内存达到 52 GiB；结束、出错或编排被中断（`Session` 是上下文管理器）都执行 `strata launch --stop` 并核实 status 为空、显存回到 14000 MiB；没有影片需要模型时不启动。产品不再启动 llama-server（[ADR-0022](../adr/0022-product-names-on-strata.md)）。产品进程被强杀时 Strata 可能留在后台，下次运行因 status 非空而拒绝，需手动 `strata launch --stop`。
- 逐窗翻译运行时（`translation_demo_runtime.py`）不获取 `.local/gpu.lock`，只检查端口是否被占用；与其他 GPU 作业的互斥由操作者保证。
- 模型生命周期按阶段串行：W0 通过工厂在 VAD 关闭后加载 ASR，ASR `close()` 后再加载 MMS；X0 每阶段一个独立子进程，进程退出即释放；父进程持锁直到全部子进程退出。
- 例外：`cross` 引擎的 asr 阶段在同一 worker 进程内让 Whisper（CT2）与 Qwen（torch）同时常驻，直到进程退出（是否采用共驻在 ADR-0012 决策时按探针峰值判定，已通过；当时备选的三段式整批转写没有实现，运行时不按显存回退，细节见 [STT worker](modules/stt-workers.md)）；阶段之间仍然串行，translate、align 不与之共驻；共驻峰值实测 10688 MiB（探针）／10030 MiB（产品路径验收），见 [ADR-0012](../adr/0012-cross-asr-judge.md#依据)。
- 取消：X0 父进程在中断时 `terminate`→10 秒后 `kill` 当前子进程，记录被中断阶段成本并清理 `tmp/`；v3 把 llama-server 放入 KILL_ON_JOB_CLOSE Job Object，Python 被强杀时服务器随之退出。发出取消不等于 GPU 已释放；完整 Windows 取消／OOM 恢复仍未验证（见 [X0 pipeline](modules/x0-pipeline.md#代码与验证入口)）。

## 产品包的责任边界

双语字幕流水线（`kototoki/`）按"谁有权做这个决定"划分，每项只有一个归属：

- **时间轴**只在三处出现：媒体定零点，推理模块输出 WAV 本地坐标（含 `align.json` 的 units；`align.map_records`／`MmsAligner.align` 不收 offset），日文 cue 给窗口边界、VAD 子段与 units 各加一次 offset。采用内嵌日文字幕的文件（ADR-0024）没有后两处：字幕时间由 ffmpeg 按同一个输入零点转出，`embedded.clean` 只排序、不改写任何时间。编排、翻译、合并不得出现任何时间换算；翻译子系统只读 `ja.srt` 相邻 cue 之间的停顿长短来切包与取舍邻文（ADR-0011），不改写、不换算任何时间。
- **跳过与替换**由产物契约的 `is_current` 判定，期望身份与"下一个要跑的阶段"由阶段计划模块给出，编排只负责问；推理模块永远不决定"要不要跑"。
- **失败分三级，各归一层**：窗口级（`failed_windows`，推理模块填、协议校验，不进对齐、cue 与翻译）；文件级（worker 报 `failed` 事件、退出码 1，协议记账，编排继续下一文件）；worker 进程级（退出码 2 带 `fatal` 事件：该文件失败，编排从下一文件重启 worker；退出码 2 带 `startup_failed` 事件：模型加载失败与文件无关，本阶段剩余文件全部失败、不重启；其他退出码，或退出码 0／1 而有待跑文件没有事件：按崩溃处理，最后一个有事件的文件之后的那个文件记 `WorkerCrashed`，从其后重启）。这些判定是 `protocol.classify_launch` 的纯函数规则，编排只循环与记账。批次级：任何阶段撞 `.local/gpu.lock` 都以退出码 4 结束整批，不写逐文件 `failure.json`（[ADR-0025](../adr/0025-product-package-boundaries.md)）。翻译子系统内部的基础设施失败（传输／连接断开、OOM、server 错误、Strata 起不来）自己消化到重启 Strata 两次为止（受共享 session 整批最多 3 次启动失败的上限约束，额度只由 `Session` 计数与置 `unavailable`），再往上抛即为该文件的文件级失败；`StrataRefused`（身份不符、已有别的 launch 在服务、专家区退到 mmap）不重试，共享 `Session` 置为不可用，本批其余需要模型的影片在 names 与 translate 都直接失败；批次终态失败（两次尝试都失败）在子系统内按 10→5→1 降级，单条仍失败保留日文。专名建表的传输／HTTP／OOM 失败停掉 Strata，是该文件 names 阶段的文件级失败（下一部需要模型的影片再启动，计入整批 3 次），建表终态失败（5 次都不合格、超预算）只写空表、不算失败（翻译照常，不注入）。发布没有专名替换，因而没有替换失败。
- **发布**只有编排能做：把 `ja-zh.srt` 写到工作目录暂存 → `record_published`（审计）→ 原子移动到源文件旁。源文件旁已有同名字幕的文件在扫描阶段即跳过，不进任何阶段（ADR-0020）。
- **锁**全归编排：`<work_dir>/<目标目录键>/lock` 与 `.local/gpu.lock` 都在编排器手里；翻译子系统、`names` 与共享的 `strata.Session` 都不取锁。
- **身份**：各阶段 `recipe_hash` 归 `recipes.py`，翻译配方 hash 归 `translate/recipes.py`，专名的建表配方 hash 归 `names/recipes.py`，模型 SHA256 经产物契约的缓存；翻译身份 = `{ja_srt_sha256, recipe_hash, seed, names_sha256}`，其中 `names_sha256` 是注入行的哈希，手改表中会被注入的条目即换身份、重译（只改 medium／low 条目不会）；每个阶段的期望身份由哪些上游、配方与模型组成只在 `plan.py` 写一次，worker 壳与编排消费而不复制；没有模块把绝对路径写进身份。
- **子进程环境**归编排：`PYTHONUTF8=1`、离线变量、共用 `HF_HOME`／`TORCH_HOME=<work_dir>/cache/` 由编排传入，worker 不自行设置 PATH 或 DLL 目录。
- **日志**目的地与格式只归编排（`job._run_logging`、`kototoki/logs.py` 的格式；worker 壳的 `gpu.main` 只把子进程日志按同一格式写到 stderr，由编排存档）；产品模块经各自 `kototoki.*` logger 发进度与告警（`job`、`translate.*`、`strata`（Strata 启停、等显存与内存、接入检查，前缀 `[strata]`）、`names.table`（不合格的尝试）、worker 壳；`names` 包顶层不发日志，建表结果行由编排写）；推理模块（`vad`、`asr_*`、`align`）不发日志、不打印；转写、译文、提示与模型响应正文不进任何日志（细则见[批次编排：运行日志](modules/batch-orchestration.md#运行日志)）。

接缝：有两个适配器的位置才是真接缝，只有一个适配器时保持具体实现、不抽象。真接缝有三处：ASR 引擎（`w0`、`x0`、`cross` 三个适配器写出同一种 `asr.json`，由 `config.engine` 选择；`cross` 由 `asr_whisper`＋`asr_qwen`＋`judge` 组合而成，不是新的推理模块；[ADR-0012](../adr/0012-cross-asr-judge.md)）、编排器 ↔ 阶段 worker（真实子进程／测试用伪 worker 脚本，接口是 jobs 文件＋增量结果＋退出码）、names 与翻译 ↔ Strata HTTP 服务（本机回环客户端 `local_client.LlamaClient`／测试用伪客户端，两阶段都经 `Session.client(trace_dir, *, timeout)` 取得）。[ADR-0019](../adr/0019-product-translation-q2.md) 起 `StrataServer`（启停与身份核对）是**单一具体实现**，不抽后端协议：产品只有 Strata 一个推理后端，Hy-MT2 后端随 H0 配方一起删除；`strata.Session(server_factory=...)` 只是测试可替换伪服务的内部接缝。Strata 的生命周期在 ADR-0019 时只有翻译一个使用者，留在 `translate/strata.py`；[ADR-0022](../adr/0022-product-names-on-strata.md) 让 names 成为第二个使用者，于是连同共享的 `Session` 一起抽到中间层 `kototoki/strata.py`（第二个使用者出现后的抽取），`translate/strata.py` 随之删除、研究侧导入改指中间层。`ManagedServer`（端口检查、引擎与模型核对、显存轮询、驻留校验）在 [ADR-0014](../adr/0014-name-consistency-in-product.md) 时因翻译与建表两个使用者抽成共享模块（`ServerSpec`）；ADR-0022 后产品没有使用者，[ADR-0025](../adr/0025-product-package-boundaries.md) 起随唯一使用者搬到研究侧 `experiments/translation_v3/llama_server.py`（产品不为研究侧导入方保留代码；产品符号移动或改名时同一提交里机械改研究侧导入行），产品只留客户端 `kototoki/local_client.py`，显存轮询并入 `strata.py`。翻译的同调用内重启与降级留在 `generate.py`，经共享 `Session` 的 `stop()`／`ensure_started()` 重启；names 不做同调用内重启（每部影片最多 5 个请求，传输失败即停掉 Strata 并让该影片失败）。媒体 ↔ ffmpeg、VAD 与对齐后端、配置来源、SRT 写出器都只有一个实现，不做后端协议类或抽象层；换模型时改配方常量与实现，不改接口。在只有一个适配器的位置新建接缝须先在本节写明第二个使用者。内部接缝只供各自模块的测试使用、不属对外接口：共享的 `strata.Session(server_factory=..., client_factory=...)` 可换伪服务与伪客户端（`client_factory` 只经 `Session.client()` 使用，names 与翻译不直接碰它；真实客户端是 `local_client.LlamaClient`），`protocol.run_worker` 的 `start` 回调可换伪处理函数，`artifacts.replace_with_retry` 的 `replace` 可注入。

测试穿过与调用方相同的接缝：`cues`、`merge`、`srt`、`artifacts`、`protocol`（含 `classify_launch`）、`procs`、`judge`、`config` 直接按接口离线测；与研究实现的等价在 core 里钉字面量或 sha256，实时对照在 `tests/equivalence/`（`just test-equivalence`，属 `gate-full`，ADR-0025）；媒体测命令行构造与合成媒体；推理模块用冻结窗口门禁（重任务）；翻译子系统用伪客户端走完整流程；编排用伪 worker 脚本。需要越过接口去戳实现时，先怀疑模块形状。编排是最深的模块（一个入口承载全部流程知识），worker 壳的 `__main__` 只做入口，流程知识在协议模块。
