# 三候选的组件增量实测

> 2026-10-05 当前入口说明：本文W0／W1／X0与保留三候选的结论属于当轮旧配置。当前W0／X0的新实验按[统一指南](../guides/baseline-testing.md)使用标准demo，本文历史分数不变。

状态：本轮有界实验完成；未得到满足既定替换条件的新组合  
日期：2026-10-04  
范围：Windows 11、RTX 5080、日语电影 II／III，当前 W0／W1／X0 的缺失组件实验。

结论：保留现有三条候选。HTDemucs 分离和新增 VAD 未形成稳定整体收益；
最有价值的新组合是 **W0＋原词时间包络桥接＋归一化标准日语 CTC**，
保持全文不变，将半秒确定成功从 241/590 提高至 306/590，
但可测数减少 5 项、五秒成功减少 4 项，且未在既定八轴上支配任何原候选。
这是明确的时间收益与覆盖取舍，不是“足够更优”的替换结论。

用户后续明确提出时间偏移优先，并要求尝试 W0＋CTC＋VAD；
独立追加结果见[后续报告](2026-10-04-w0-vad-ctc-follow-up.md)，本文保留首轮原始结论。

## 问题与比较边界

本轮按照用户要求，先加一个最可能有帮助的组件；存在收益才继续叠加。
保留 W1 已有 Pyannote／ASR／归一化 CTC，保留 X0 的原有 CTC；没有强拆内部模块。
[预登记方案](../plans/component-augmentation.md)定义固定四窗筛查、完整十二窗开发与追加确认。
[来源核查](2026-10-04-component-augmentation-sources.md)区分组件兼容性与实际效果。

文字分数为相对原 SRT 的连续全文 CER、S/D/I；时间按相同内容匹配，使用全参考分母，
边缘项和匹配不确定性保留。时间成功不是按候选 cue 编号对应；不会为了对齐参考而改分句。
显示使用固定 minimal writer，独立记录短 cue、未渲染字符等。
这些字幕参考尚未成为独立人工声学真值，不以系统性平移时间来提高得分。

旧 round2 十二窗均已曝光。四窗为两片 window-01／04，共 20 分钟、193 条参考，
属于开发筛查，不能推广为全部 590 条或未见电影表现。
III 额外六窗在读取新增组件得分前另行冻结；同电影新增区间仍不是跨作品保留。

## 首个组件的配置与执行

分离使用 Demucs 4.1.0，官方单模型 HTDemucs `955717e8`、float32 CUDA；
权重 revision 与哈希见来源报告及 `.local/models/htdemucs/acquisition.json`。
既有 large-v3、日语 CTC 与 Qwen ASR 资产均重新哈希，与原获取登记一致。
新增隔离环境为 Python 3.12.15、Torch 2.8.0+cu128；保持项目已验证的 5080 runtime，
不因新增组件升级旧后端环境。完整版本清单保存在本轮私有 `demucs-requirements.lock`。

同一份已有 16 kHz mono PCM → 44.1 kHz 复制双声道 → vocals → 16 kHz mono PCM16。
采用官方均值／标准差处理并恢复幅度，shifts=0、overlap=0.25、固定 seed、关闭 TF32，
不做输出峰值归一化；记录削波数量和样本长度。原音频与字幕均只读。
每条路线所有原阶段接收同一份派生音频，因此因果变量是新增的这一分离组件。
它可能同时影响识别、VAD 和对齐，不能把端到端变化全部归于某一个内部阶段。

首窗 GPU smoke 成功：52 次 CUDA forward，处理约 19.76 秒、加载约 0.50 秒，
PyTorch 峰值分配约 0.60 GB、保留约 0.86 GB。输入输出均 4,800,000 个采样，
端点无额外裁样，PCM16 削波为零。这证明本机执行及数据契约成立，不证明质量提升。
原始单声道已经丢失立体声线索和高频，本实验不代表原始 FLAC stereo 分离的质量上限。

四窗 HTDemucs 筛查全部完成，16 个新阶段成功，基线与增强共 24 个计分 slot 的输入、GPU 和上游身份均通过独立核验。
完整分母为 193 条、1955 字符；四个窗口不生成 bootstrap。

这不等于所有降噪／分离模型无效，尤其不代表原生 stereo 输入、其它模型或其它音频的结论。
下一步为预登记的原音频＋GPU VAD 独立消融。

### 独立 W0＋CTC：输入契约诊断

原样追加 CTC 的十二窗尝试已经完成：11 窗通过，III-05 的进程正常退出但对齐证据检查失败。
唯一失败发生在 46 个 CTC record 中的第 6 段：原 W0 父 segment 为 96.14～96.16 秒，
但它自身的 word 为 95.46～96.16 秒。20 ms 输入只有 320 个采样，补至最小 400 后仍只有
1 个 emission 帧，却需对齐 3 个 targets；TorchAudio 拒绝 `T < L + R` 的不可能路径。
其中一个 target 是标点 wildcard，但去掉标点也有 2 个 targets，不能把根因归于标点。
模型真实 CUDA forward 正常，原 PCM、源 offset、472 字符全文和 46 个原 segments 均未改变。

该结果有 453 个有时间字符、19 个 text-only 字符，失败段 3 字符仍在全文中。
按冻结协议，主结果将整窗登记为 `alignment_failed`，保留文字 CER 和全部时间分母；
这不等同于整窗 ASR 丢失，也不删除失败产物。

跨十二窗检查 635 个 segments／5157 个 words，发现 11 个父段未覆盖自身词范围，
涉及 II-05、III-02／04／05／06；词时间均有限、未越界，取包络后相邻段无重叠。
由此另登记**只修复对齐搜索窗口的包络配置**：根据 ASR 自身时间扩大这 11 段，
保留原始 segments 及映射，文字和模型不变，不用参考字幕、经验 padding 或得分指导修复。
本轮首次尝试及其失败仍独立评分，修复另用实验身份验证。

首次尝试完整计分：CER 16.412%、S/D/I 526/274/274，与原 W0 完全一致；
完整边界仍为 519/590，可测从 377 降为 349。半秒确定成功 241→290，
但两秒成功 363→345、五秒成功 374→347，均计入失败窗的全部分母。
共同可测 342 项的 P95 为 1.523→0.838 秒，P99 为 4.742→2.194 秒。
此尝试没有在合并或逐片八轴上支配任何原候选。
配对 bootstrap 的半秒成功差值区间为 −0.165～+15.152 个百分点、
可测覆盖为 −13.986～+0.163 个百分点；联合 P95 全部不可测。

## 停止决定与未验证边界

按预登记护栏，分离、VAD、独立 CTC 均没有产生足够更优且无观测回归的组合。
不继续在失败方向叠加第二组件，不更换 W1／X0 已有组件，也不升级为产品后端决定。
W0＋CTC 保留为有明确时间收益的研究选项；当前两片均有覆盖／五秒成功退化，
本轮不晋级追加确认，事先冻结的 III 六窗仍未用于推理或得分。
这些未曝光区间没有被算成验证通过，更不构成新电影泛化证据。

本轮验证的是固定 HTDemucs 单声道输入链、固定 GPU Pyannote 窗口策略及固定日语 CTC，
不是所有降噪／分离／VAD／对齐器的穷尽搜索。原始 stereo 分离、其它降噪模型、
WhisperX 文字接 Qwen FA 等仍未实测，不能据当前结果判定无效。
Qwen FA 的独立接口可适配 WhisperX，但不能直接填入其 Wav2Vec2 CTC loader；
Canary CTC 不支持当前日语素材，Subtitle Edit 的 Japanese aligner 是现有模型的转换版本。
具体版本、官方依据和未测试的接口边界见[组件核查](2026-10-04-component-augmentation-sources.md)。

## 执行成本与部署负担

以下为每个 300 秒片段的实际 harness 墙钟最小／中位／最大值，包含独立进程加载开销。
GPU 串行，但不是安静窗口正式测速；不能把缓存的历史阶段相加称为一次新端到端测速。

| Pyannote VAD，十二窗 | 12 | 9.489 / 9.511 / 13.737 |
| W0＋VAD 的 ASR 子阶段 | 12 | 10.557 / 14.797 / 22.210 |

| X0＋VAD 的 CTC 子阶段 | 4 | 15.852 / 20.609 / 22.194 |
| 同片 VAD＋Qwen ASR＋CTC 合计 | 4 | 72.939 / 77.176 / 88.780 |

修复版十二窗新 CTC 共 155.365 秒，原 W0 缓存 ASR 历史墙钟为 334.427 秒；
两者相加仅用于阶段成本记账，不冒充本次新端到端延迟或整片连续性验证。

Demucs 的 PyTorch 峰值分配／保留约 573.42／824 MiB，Pyannote 为 248.75／412 MiB；
Qwen VAD ASR 峰值分配约 4.048 GiB，保留 4.242～4.688 GiB。
CT2 和 CTC 没有同口径的 PyTorch allocator 峰值记录，不能用包含桌面的整卡采样冒充进程峰值。
VAD 缩短 W0 的 ASR 计算，并不抵消此次文字／覆盖退化。

分离额外引入隔离 Demucs 环境和约 84 MB 权重；VAD 及独立 CTC 复用本机已有权重，
但跨 CT2／WhisperX 环境的进程桥接、完整文字及源坐标核验仍是集成成本。
