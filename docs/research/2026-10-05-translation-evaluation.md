# 日语到简体中文字幕：评估方法与小规模实验建议

状态：exploratory；来源核验完成，实验尚未执行。  
最后更新：2026-10-05。  
范围：电影／长对白的日语文本到简体中文字幕质量评估；区分翻译、ASR、上下文和字幕显示。本文不建立翻译功能、不改变当前 STT 里程碑，也不采纳任何翻译模型。全部外部来源访问于 2026-10-05；未上传本地影片、音频或转写，未运行翻译或自动评审推理。

## 建议结论及证据边界

建议以具有上下文的双语人工错误分析及盲配对为主，COMET／xCOMET／MetricX 和 LLM-as-judge 为辅助；语义正确、字幕可读和时间同步分开报告。任何候选，包括 Astra，都需要在相同输入、提示、上下文和人工标准下实测；现有来源不能证明它一定最佳。

已核验的是以下论文和官方工具描述。尚未验证的是：本机运行条件、候选日中字幕能力、自动指标在这批影片上的漏检率、评审模型与人的一致性、实际延迟／费用，以及任何数值验收门槛。下面的样本规模和决策流程均为提案。

## 为什么必须看场景，而不是只看一句中文

Läubli 等的文档级盲配对实验发现，完整文档比孤立句子更能区分人类与机器译文；Freitag 等则使用专业译者、完整文档上下文及 MQM 错误分析，并观察到与众包评价不同的系统排序。这些研究支持检查语义与篇章关系，不能把其语言对／新闻领域结果直接当成日中电影结论。[文档级评估论文](https://aclanthology.org/D18-1512/)、[Experts, Errors, and Context](https://aclanthology.org/2021.tacl-1.87/)

文学翻译研究中，段落上下文有助于翻译，关键错误仍然存在；该研究包含日语相关方向，但不是本文拟评估的日语电影到简体中文字幕。[Literary Translation 研究](https://aclanthology.org/2023.wmt-1.41/)

**项目推论／建议：**以连续场景为评价单元，保留前后对白、当前说话人及已确认人名表。先根据日文源文检查译文，再在本地播放原音频与画面核对语气、画外音、指代、可见物体和台词歧义。原文／上下文无法确定的地方标记“歧义待核”，不奖励评审模型自行补剧情。评审可看完整场景，翻译模型可用的上下文须另外冻结、记录，避免把隐藏答案或后续剧透泄漏给某一候选。

日语省略主语时，中文未必需要补出“他／她”；不能用中文流畅或常识合理替代源文证据。画面可能消除歧义，也可能是声画反讽。只有文字输入的模型没有获得的声画线索，应另记为信息缺口；多模态与纯文字系统应建立独立比较组。

## 人工标注：MQM 思路，加上剧情风险清单

MQM 允许按用途选择错误类型、严重级别和权重；其官方示例不是统一强制分数。Minor 对可用性影响有限，Major 严重改变意义／可理解性，Critical 则达到整体内容不适用或严重风险。可接受的措辞偏好不能当作错误。[MQM 官方 scoring models](https://www.themqm.org/mqm-pillars/the-mqm-scoring-models/)

建议冻结以下字幕用简化表，标注源文证据、目标文字范围、类型、严重程度、判断理由和人工修订；一处根因造成的多个表象避免重复计数。

| 检查项 | 要回答的问题 | 项目建议标签 |
| --- | --- | --- |
| 准确性 | 漏译、增译、错译；是否凭空补充人物意图、情节或因果？ | Accuracy：omission / addition / mistranslation |
| 剧情关键意义 | 否定／条件／承诺是否反转；谁对谁做了什么、谁知道什么是否改变？ | 具体错误类型＋独立 `plot-critical` 风险标记 |
| 跨句与人物 | 代词、说话人、对象、人名、称谓、敬语、时间和数量是否一致？ | Accuracy / Terminology / Consistency；级别按影响判定 |
| 中文表达 | 意思正确后，中文是否自然、符合人物口吻，是否过度书面或解释？ | Fluency / Style / Register |
| 输出合约 | 是否全为要求的简体中文，编号／文本对应完整，是否有解释、拒绝或原文残留？ | 合约失败或 untranslated；与语义错误分别记账 |

“他没杀她”变成“他杀了她”，或把受害者写成实施者，属于必须逐例审查的关键反转。**不能仅看到否定词或代词错误就自动判 Critical**：可能只是局部 Major，也可能让整个关键场景无法理解。建议用 `plot-critical` 标记列出所有关键反转，再由场景证据决定 MQM 级别；该标记是本项目提案，并非 MQM 官方类型。剧情门槛应独立于平均错误分，不以多条流畅译文抵消。

初试报告同时给出 Minor／Major／Critical 数量、受影响 cue 与场景比例、剧情关键案例和失败比例。若需汇总，可冻结 1／5／25 的示例权重并以日文源字符数归一化，同时保留原始计数；这是自定义 MQM 风格统计，不能直接与其他论文的 MQM 总分比较。字幕允许的压缩要先说明：可以省去不影响功能的赘词，不能为降低阅读速度删掉否定、条件或剧情信息。

## 自动指标能提供什么

| 方法 | 适合用途与已核验事实 | 不能据此得出的结论 |
| --- | --- | --- |
| COMET／COMETKiwi | 官方工具区分需要 reference 的模型和 reference-free QE 模型；模型、输入模式及版本必须明确。当前仓库还提供 DocCOMET／context 用法。 | 普通句级打分不会自动获得整片人物关系；QE 是预测质量，不是已证明译文正确。不能把有／无 reference 的分数混在一起排名。 |
| xCOMET | 提供质量分、错误范围和严重级别，适合把可疑片段交给人工复核。原论文主要评价 WMT22／23 的 zh-en、en-de、en-ru／he-en。 | 原论文的关键错误压力测试并非日中电影验证；没有预测错误范围不等于没有错误，预测范围也不是人工事实。 |
| MetricX-24 | Hybrid 可带 reference 或以 QE 模式运行。官方仓库直接报告 WMT24 ja-zh 结果，具有该语言对的评测证据；当前公开模型分数截到 [0,25]，越低越好。 | 不能从 WMT 文字评测直接推出字幕剧情理解达标；单句分数不是正确概率。下载版与官方 WMT24 提交版有差异，不应混称同一配置。 |
| BLEU／chrF／TER 等 | 有可信中文参考时用于参考相似度和回归辅助，固定分词、归一化和分段。 | 一条正确意译可与参考差别很大；高字面相似度也可能保留一个致命否定错误。日文原字幕不能作为中文候选的同语 reference。 |

依据：[COMET 官方仓库](https://github.com/Unbabel/COMET)、[xCOMET TACL 论文](https://aclanthology.org/2024.tacl-1.54.pdf)、[MetricX 官方仓库](https://github.com/google-research/metricx)、[MetricX-24 论文](https://aclanthology.org/2024.wmt-1.35.pdf)。MetricX README 的 ja-zh 是 WMT24；公开模型增加多句合成训练样本并裁剪分数，未来执行时应记录具体 model ID、revision、精度、库版本和最大输入长度，不能只写“MetricX”。

**项目建议：**有经过双语审核的简体中文参考时，再加 reference-based 指标；没有时使用明确的 QE 模式并标注“无人工中文参考”。原有商业／网络中文字幕可帮助检查，但先确认是否同版本、同配音、同字幕用途，以及是否删改或意译；不要把未审核字幕当唯一真值。由候选模型生成的“参考”只能称 pseudo-reference，会引入模型偏好，不能承担最终裁判角色。

先造少量可公开的合成挑战例：正确译文与否定反转、人名交换、主体／宾语互换、数量改变、漏译条件、未翻译原文各一版，检查自动评分是否按预期区分。再在人审场景中复核高分片段及低分片段，统计关键错误漏检；不能只核查低分样本。不要直接拼整片超过模型长度上限，也不要静默截断上下文。多个指标分别展示，不用未经标定的加权总分伪造精确排序。

## LLM-as-judge：盲评仍需控制偏差

MT-Bench 研究展示了位置、篇幅和自我增强偏差及顺序交换方法；这里的 MT 指 multi-turn，并非机器翻译。Self-Preference Bias 研究进一步发现，匿名标签和顺序交换后，部分评审仍相对人类偏好自己的输出风格。因此，生成译文的同一模型不宜成为唯一评审；这也不能量化今天任何模型在日中字幕上的偏差。[MT-Bench 论文 v4](https://arxiv.org/html/2306.05685v4)、[Self-Preference Bias 论文 v2](https://arxiv.org/html/2410.21819v2)

GEMBA 的原始研究证明 LLM 评审可用于其测试条件下的系统级机器翻译评价，主要语言对是 en-de、en-ru、zh-en；不能借其系统级结论宣称日中字幕逐句评判已验证。[GEMBA 原论文](https://aclanthology.org/2023.eamt-1.19/)

建议流程：

1. 匿名 A／B 候选，去掉模型名、速度、价格和生成理由。提供同一日文源文、相同场景上下文、同一术语表和上述规则；不要询问“哪个更像 Astra 风格”。
2. 要求先列每个候选可核验的语义错误及证据，再给 A 胜／B 胜／语义相当／两者均不可用／信息不足。将中文流畅与语义充分性分项记录，不能默认更长、更文雅就是更好。
3. 在独立调用中交换为 B／A。把顺序矛盾记为评审不稳定，不强迫选赢家；另报真实质量平局。不同评审模型可提供交叉核查，但多数票不是消除共同偏差的保证。
4. 双语人工盲审校准集，复核所有剧情关键项、judge 分歧和近似平局，同时抽查一致高分结果。只有达到本批资料上可接受的一致性后，才用 judge 扩大初筛。
5. 记录评审 model ID／revision、提示、输入上下文、温度、调用次数、顺序及失败；保存错误证据而非只有分数。评审指令将字幕当作待评价数据，防止其中台词或模型附加文字成为新指令。

以上是基于论文的项目方法推论，尚未证明可用于全自动验收。本文未向外部评审发送项目素材。

## 字幕时间／阅读指标与语义分开

时间正确不代表翻译正确，中文意思正确也不保证能在原时间窗内读完。建议分别报告：源音频语义覆盖、译文意义、cue 起止与说话对应、跨说话人混合、断句、重叠／乱序／空 cue、每秒字符 CPS、每行字符 CPL、每块行数 LPB，以及实际播放的阅读体验。

Netflix 简体中文普通字幕指南规定每行 16 字、最多两行，成人至多 9 CPS、儿童至多 7 CPS；其 SDH 规则不同。这些是该平台的交付规范，可以作为初试参考，不是 Kototoki 已采纳的门槛，更不能机械继承删重复／删歌曲等编辑政策。[Netflix 简体中文指南](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215986007-Chinese-Simplified-Timed-Text-Style-Guide)

A-TASC 将翻译质量与 CPL／CPS／LPB 等约束分开，且发现 (Sacre)SubER 在语序重排时可能给不可理解的字幕更好分数。它的测试背景主要是 English→Asian TED 内容，不能直接迁移为日中电影质量结论。当前 SubER README 已明确 **>=0.4.0 支持 zh／ja／ko**，需相应 `-l` 参数；不要继续引用旧版本“完全不支持 CJK”的结论。[A-TASC／SacreSubER 论文](https://aclanthology.org/2025.acl-long.157.pdf)、[SubER 当前官方仓库](https://github.com/apptek/SubER)

SubER 需要同语种字幕 reference，可作显示／编辑差异辅助；不能将日文 SRT 与中文 SRT 直接比较来衡量语义。若中文参考与候选有不同切分，应使用工具明确支持的对齐方式并保留其身份；不能强行按第 n 条比第 n 条。字符统计需冻结标点、空格、Latin／数字、组合字符的计数规则，并复核长专名和混排，不把降低 CPS 当成漏译的合理化。

## 未翻译原文与混合文字预检

Unicode 的 Script 属性描述文字体系而非语言；日语同时使用 Han、Hiragana、Katakana、Latin。因此不能凭 Han 字比例区分日文与中文，也不能把所有假名、英文或人名视为失败。[Unicode UAX #24](https://www.unicode.org/reports/tr24/)

建议保留原文，另作轻度 Unicode／空白规范化副本用于检测：逐段与原文完全相同、长片段高相似、连续假名、重复中文、空输出、目标语言不符、额外解释、cue ID 缺失／多出均进入审查队列。人名“田中”、短词“先生”、数字、引用和作品名可能合理相同；韩文／Latin 字段可能是角色名或品牌。简繁字符检测也存在共享字形，需人工确认及固定工具规则。语言识别器对短句易失效，检测只能给风险标记，不能自动证明译文合格。

计数同时给出“疑似未翻译”与人工确认的 untranslated，并列允许保留的专名／引文规则。没有假名或输出全为汉字，依然可能是日语原文照搬或词义错误。

## 建议的小规模实验

### 冻结素材与两类输入

建议首轮取 12 个连续场景，每个 30–90 秒，覆盖平稳对白、快速对白、多人／画外音、敬语／人物关系、否定条件及专名／剧情揭示。4 个用于提示／规则校准，8 个作为冻结保留集；总量约 100–200 cue，实际以原始场景完整性为准。这个规模用于发现明显失败与决定是否扩试，没有足够能力证明通用最优。

按当前参考政策，主样本优先 II／III 的原版日文字幕；先在本地听看抽样校正、记录非逐字和缺词问题。日文参考仅是源文本 oracle 的起点，不自动等于音频真值。保持原字幕只读、保留哈希与场景时间映射；不要将不确定的中文参考或较弱参考片混入主排名。

| 实验轨 | 翻译输入 | 要检验的问题 |
| --- | --- | --- |
| O：source oracle | 经人工核对的日文源文本＋冻结上下文 | 在较好源文条件下，模型自身如何翻译？ |
| A-W0：ASR 输入 | 冻结 W0 日文结果＋同样规则可用的上下文 | ASR 错误如何传到中文？ |
| A-X0：ASR 输入 | 冻结 X0 日文结果＋同样规则可用的上下文 | 另一路 ASR 的输入与端到端风险如何？ |

O 与 A 轨分别报告，不能合并均分把 ASR 错误误称翻译能力差。所有轨都对原始声音／人工核对的源意思评价端到端意义；A 轨另记录“对所给 ASR 文本是否忠实”，标记 ASR 引入、翻译引入、两者共同／无法归因。模型成功修复 ASR 错误要有音频证据，合理猜测不算成功。不要把 A 轨的 oracle 纠错答案放入它的输入。

### 控制变量及执行次序

1. 最多三候选；冻结完整模型身份、提示、术语表、文本上下文策略、采样／seed、输出合约和失败记账。区分“孤立 cue”与“连续场景批量”条件；不要让某一模型获得更多人物表或更长上下文。
2. 先在 O 轨校准四场景，确定小而完整的输出与评审规则；若比较上下文策略，只使用校准集选策略，随后冻结，不用保留集反复调提示。
3. 在八个保留场景执行所有候选 O／A 轨；语义比较先固定时间轴和显示规则。需要优化合并／切分时另设显示实验，允许 cue 数量变化但必须保持可追溯映射。
4. 两名具备日中能力的人工评审独立标注／盲配对；资源不足时由一人全审、第二人复核全部关键项及预先冻结的随机子集，报告覆盖不足。分歧做有证据的裁决，保留初始分歧。
5. 在公开合成挑战及人工场景上标定自动指标／judge，分轨汇总；隐私资料保持本地，未来外部模型调用必须符合用户授权。
6. 用场景作统计单位，报告配对胜／平／负、严重错误、关键反转、完整失败分母、延迟／资源／费用。可做场景级配对 bootstrap，但八场景的区间只表达这批数据的不确定性；同一电影相邻 cue 不当作大量独立样本，另列逐片／逐场景结果。

超时、拒绝、空输出、截断、格式损坏、错目标语言均保留；质量分可以只对成功样本计算，但同时给全部输入的成功率／失败数，注明共同有效子集。只报告后半次成功重试会低估成本和失败风险。本文没有提出已采纳的晋级分数；建议先以“无未解决的关键剧情反转、覆盖与合约可接受、盲评具有稳定优势、成本在预算内”为扩试条件，近似平局保留多个候选。
