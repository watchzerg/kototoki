# ADR-0012：产品 STT 增加可选引擎 cross（x0 转写＋Whisper 交叉打分裁判）

状态：已接受（2026-10-19）。依据见下文"验收与裁定"：T6 产品路径验收两部电影 CER 都低于 w0，但合计降幅 −0.95 pp，**低于预设的 1.0 pp 验收线**；用户 2026-10-19 据此裁定仍采用 `cross` 作为可选引擎，默认保持 `w0`。  
日期：2026-10-19（提出与接受同日）。  
关系：**不替代任何已有 ADR。** 它在 [ADR-0007](0007-bilingual-subtitle-pipeline-architecture.md) 决定 1（GPU 阶段按"阶段 × 整批"推进，每阶段一个子进程）的框架内扩展 asr 阶段的内部形态，阶段链、子进程与文件交接不变；[ADR-0008](0008-no-multi-translation-selection.md) 只约束翻译，不涉及 STT 两路识别之间的裁判。STT 引擎默认仍是 `w0`（[ADR-0003](0003-new-pyannote-baselines.md) 的基线身份不变）。  
范围：产品包 `kototoki/` 的 asr 阶段新增引擎取值 `cross`。不做：不改阶段链，不改 align／cues／translate 的接口，不改 MMS 与翻译阶段的显存模型，不把 `cross` 设为默认，不做剧集或新材料确认。行为描述已吸收进当前正文：[STT worker](../architecture/modules/stt-workers.md)、[阶段计划](../architecture/modules/stage-plan.md)、[产物契约](../architecture/modules/artifact-contract.md)、[配置与媒体](../architecture/modules/config-and-media.md)、[技术设计](../specs/bilingual-subtitle-pipeline.md)。

## 决定

用户 2026-10-19 裁定直接产品化，剧集与新材料确认推迟：

1. **新增可选引擎 `cross`，默认不变。** `[stt] engine` 取 `w0 | x0 | cross`，默认 `w0`；改默认须新 ADR，且按项目惯例先在全新隔离材料上确认。
2. **裁判配方**（常量写进配方 `CROSS`，id `cross-w0-x0-whisper-judge-v1`，不做配置项）：窗口级，两路文本规范化后做字符级编辑距离对齐，非匹配操作的极大连续段为分歧区间；Whisper 对每个区间的两个假设（w0 原文、仅该区间换成 x0 原文）做教师强制打分，分数为 Σ log `text_token_probs`（不含结束符）；d ＝ score(hyp_x) − score(hyp_w)，**d > −1.0 取 x0，否则保持 w0**，无长度项（λ ＝ 0）；多区间各自独立判定后一起应用；打分批上限 16。守卫：两路相同的窗口不打分、合并结果为空而 w0 非空时保持 w0、x0 窗口失败时取 w0、打分抛错的窗口取 w0 并告警计数（不算窗口级失败）、w0 窗口失败时仍记失败（是否以 x0 替代留待后续）。
3. **共驻与回退。** 同一 asr worker 进程内同时常驻 Whisper（CT2）与 Qwen（torch），逐文件按"Whisper 转写 → Qwen 转写 → 裁判"推进。共驻采用的判据是探针实测整卡峰值加 1 GB 余量仍 ≤ 13.5 GB；否则回退为 Whisper 整批转写 → 卸载 → Qwen 整批转写 → 卸载 → Whisper 整批打分的三段式，产物与接口不变。T0 探针实测峰值 10688 MiB（加余量 11712 MiB < 13824 MiB），[采用共驻](../research/acceptance/2026-10-19-cross-coresidency-probe.md)；产品路径验收 asr 阶段整卡峰值 10030 MiB，三段式回退未触发、未实测。
4. **阶段链不变。** 裁判放在 asr 阶段内部，不是新阶段：下游只看到同构的 `asr.json`；两路结果与裁判记录另存 `asr-w0.json`、`asr-x0.json`、`asr-judge.json`，只作审计与离线复算，不参与 `is_current`。

## 背景与依据

三份同日研究（HF II／III 两部电影、cue 并集单元口径）加一份候选调研：

- 合并的理论上限：两部合计 CER 16.16% → **11.90%**（oracle 拼接，[oracle 上限](../research/2026-10-19-asr-pair-oracle.md)）。
- MMS CTC 当裁判只到 **15.40%**，替换区间 AUC 0.49（接近随机），长度项符号两片相反（[MMS 裁判](../research/2026-10-19-asr-pair-ctc-judge.md)）。
- Whisper 单独当裁判到 **14.31%**，拿到上限增益的 **43%**；替换区间 AUC **0.774**；参数两片稳定（λ 0／0.25，m −1）（[交叉打分](../research/2026-10-19-asr-pair-cross-score.md)）。
- 叠加 Qwen 或 MMS 反而稀释：Whisper＋Qwen 14.56%、三路 14.60%，都不如 Whisper 单独；"两者都同意"14.23%，差距在选裁判的噪声内，且多依赖一个模型。
- 自偏好：oracle 判 x0 更好的区间里 Whisper 仍偏向自己 52%，这是稳定偏置，阈值 m −1 吸收（Qwen 偏向更重，阈值要 +3.5～+7.5 nat，所以不让它当裁判）。
- 为什么 Whisper 能判自己：生成时走岔路与"判断两句话哪句更配音频"是两件事（[交叉打分](../research/2026-10-19-asr-pair-cross-score.md) §1）；候选来源见[裁判选型调研](../research/2026-10-19-acoustic-judge-survey.md)，交叉打分排第一（推断），今已实测。

要打的折扣（验收时对照）：8 个纯表记样本里 Whisper 改了 6 个，计入 CER 但不影响译文；Whisper 分数不含结束符，多字少字类区间有"越短越占便宜"的偏差；研究是 cue 并集的单元口径，产品是 VAD 窗口口径，数字会有差异。

## 验收与裁定

依据两份同日验收记录：[T0 共驻显存探针](../research/acceptance/2026-10-19-cross-coresidency-probe.md)与 [T6 产品路径整批验收](../research/acceptance/2026-10-19-cross-asr-acceptance.md)（HF II／III，官方整片口径，对照 w0 基线）。

| 验收线 | 实测 | 判定 |
| --- | --- | --- |
| 两部 CER 都低于 w0 | II 16.81% → 15.93%（−0.88 pp）；III 13.77% → 12.75%（−1.01 pp） | 通过 |
| 两部合计降幅 ≥ 1.0 pp | 合计 15.25% → 14.30%，**−0.95 pp**（编辑量 3375 → 3165；达线需 −222，差约 12 处编辑） | **未达**，差 0.05 pp |
| 裁判统计与探针同口径 | 402 窗口、相同 41、分歧区间 1084、改为 x0 200（18.5%），1084 个区间的决定与 d 逐个相同 | 通过 |
| asr 阶段整卡峰值 ≤ 阈值 | 10030 MiB，加 1 GB 为 11054 MiB ≤ 13824 MiB | 通过 |
| 翻译阶段照常启动 | asr 结束后整卡回到 851 MiB，llama-server 启动前空闲 15120 MiB ≥ 14700 | 通过 |

- **未达线与裁定**：1.0 pp 是验收前按研究单元口径（−1.85 pp）扣除口径与表记差异后设的保守线；官方整片口径只拿到研究降幅的约一半（−0.95 pp），低于该线。用户 2026-10-19 在知悉这一点的前提下裁定**仍采用 `cross` 作为可选引擎，默认保持 `w0`**。未达线的原因没有拆分（表记改动与真实识别改进各占多少未量化）。
- **增益构成**：两部合计替换 −82、插入 −175、删除 +47；删除增加与"结束符偏差"的预期方向一致，插入减少是主要收益。
- **折扣在数字里都存在**：15 个抽查的切换里 6 个是纯表记改动（计入 CER 但不影响译文），另有 3 个是删掉单字或长音、1 个删掉一串喘息拟声，其余 5 个是词义替换，未听音、对错未判。
- **成本实测**：asr 阶段墙钟 1211.6 s，为 w0 asr 阶段（323.4 s）的 3.75 倍；整批 1754.8 s（w0 整批 890.3 s）。

## 代价

- asr 阶段墙钟约为 w0 的 3.75 倍（实测 1211.6 s 对 323.4 s：w0 转写 286.0 s＋x0 转写 863.7 s＋打分 40.7 s＋加载与启动），整批约 +97%（1754.8 s 对 890.3 s）；用户已接受。
- 每个文件两次转写；asr 进程同时占 CT2 与 torch 两套 CUDA 显存，共驻是产品里唯一的新进程形态；T0 探针与 T6 验收均无 DLL 冲突与 OOM，整卡峰值实测 10688／10030 MiB（探针／产品验收，桌面占用不同）。
- 产物与身份多一族：`asr-w0.json` 等三个审计文件，`CROSS` 配方嵌入 W0／X0 子配方，任一变化即身份变化。
- 译文层收益未测。

## 不采纳的替代

- **MMS 当裁判**：顺手选的，实测替换区间 AUC 0.49，只到 15.40%。
- **加入 Qwen 的分数**：替换 AUC 0.774 → 0.733，CER 14.56%，劣于 Whisper 单独。
- **三路（Whisper＋Qwen＋MMS）**：14.60%，没有改善。
- **"两者都同意"才改**：14.23%，与 Whisper 单独的差距在选裁判噪声内，却需要 Qwen 的阈值（两片不稳）。
- **幻觉过滤**：CER 收益 ≤ 0.24 pp，且误删单汉字真台词。
- **裁判作为独立阶段**：裁判需要两路文本与 Whisper 同时在手，独立阶段要再加载一次 Whisper，并改 `plan.py` 的阶段链、身份与"下一个要跑的阶段"；放在 asr 内部则 align 及之后只看到 `asr.json`，接口不变。

## 后果与后续

- 新材料确认与译文层收益**都未测**：验收只在 HF II／III 上对照 w0 基线（官方整片口径，合计 −0.95 pp，未达 1.0 pp 线，用户裁定仍采用）；译文层收益需 v5 第 2 步的裁判，外部推理，另行裁定。
- 改变默认引擎须新 ADR，并先在全新隔离材料上确认。
- w0 失败窗口以 x0 替代的做法研究未覆盖，本期不做，留待后续裁定。
- 增量说明已吸收进当前正文并删除（2026-10-19）；三段式回退未实测，若共驻某天不可用再验证。
