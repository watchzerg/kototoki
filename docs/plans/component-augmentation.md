## 固定原则

保留[历史三条候选](../architecture/stt-candidate-pipelines.md#历史三候选及其已测组件)及当时参数和组件；本已完成方案不定义未来基准线。
W1 原生 VAD 与现有 CTC 保留；X0 保留现有 CTC。先尝试单个缺失组件，
有收益才考虑第二个组件。对齐器替换只在公开支持的边界进行，作为独立消融，
不把强制对齐、CTC、识别和分离混为同一职责。

继续使用原评测核心和[完整分母、文字／时间／显示分表](../testing/subtitle-timing-benchmark.md)。
不调整参考边界、不用参考指导推理、不按候选表现排除项目、不伪造词级时间。
字幕时间不是声学真值。没有人工声学标注就不能宣布声学精度通过验收。

## 实验顺序与停止条件

1. 核查官方组件接口、日语支持、模型身份与本机可执行性；分析已有失败分布。
2. 首轮筛查固定使用旧 round2 的两片 window-01、window-04，共四窗 20 分钟。
   这些是已接触样本，只用于开发；不能称为新保留集。选择基于固定编号，非新组件得分。
3. 优先评估能作用于三条路线共同缺口的人声分离／降噪，具体模型及配置在推理前登记。
   一次只增加一个组件，保留音频长度及源时间，记录每个阶段的音频身份。
   如方向无收益则停止叠加，并转向 W0／X0 缺失的 GPU VAD 或 W0 的独立对齐消融。
4. 有价值配置扩展到旧 round2 全部 12 窗，保留逐片结果和全部失败。
   不把筛查子集当作独立重复，不依据追加成绩回改筛查配置。
5. 在追加确认前锁定配置及确认输入；优先采用与原 12 窗不重叠的固定区间。
   II 已有整片接触历史，III 也有局部历史接触；必须披露，不能概称全新盲测。
6. 只有新增组件显示稳定收益才继续叠加。最终保留原三基线对照，记录新增成本和部署负担。

沿用[原筛选规则](../testing/evaluation-config-v1.md)的保守自动替换条件：
CER、D、I 不增加；完整／可测覆盖及全分母时间成功下界不降低，至少一项改善。
有取舍的非支配方案可继续研究，但不能自动称为足够更优。
严格时间目标仍为完整分母 95% 小于 0.5 秒、99% 小于 2 秒，不能用条件 P95/P99 替代。
十个以上窗口才做固定 seed 的窗口成组 bootstrap；未决范围能翻转结论时说明证据不足。
不额外臆定用户愿意接受的识别退化或“足够更优”的百分点门槛。

## 执行与证据

首个组件固定为 Demucs 4.1.0、`htdemucs` 单模型；官方 safetensors 仓库
`adefossez/HTDemucs` revision `cbc8a9b1a87023b7fd74e7b3412e6321c0eab003`。
使用已有 16 kHz 单声道输入，复制双声道并重采样到 44.1 kHz，分离 vocals 后恢复
16 kHz 单声道及原始样本数；shifts=0、overlap=0.25，保留官方输入归一化，不做输出峰值归一化。
W1／X0 的 VAD、ASR、CTC 均接收同一派生 vocals 输入，不新增第二种组件。
此输入链不具有原 FLAC 的立体声线索和高频，结论不代表原生 stereo 分离上限。

第二个独立方向预登记为 **W0／X0＋GPU Pyannote VAD**，只处理原始实验 PCM，
不先叠加分离器。沿用已安装 WhisperX 3.8.6 的 Pyannote 权重与原生
onset=0.5、offset=0.363、最多 30 秒语音合并窗口；每窗最多增加 0.2 秒上下文，
在音频边缘和相邻间隙中点裁剪，不能重叠或删除原生语音范围。
源坐标按样本还原，不能拼接后误用压缩时间。
W0 通过公开 `clip_timestamps` 输入区间，保留原解码设置；其内部 10 ms mel 帧量化另记。
X0 在原始音频的这些样本区间上识别，再使用原有归一化标准 CTC；不修改旧桥接器的连续窗约束，
新增独立非连续窗桥接并验证全文不变。W1 原生 VAD 保持不动。
该方向先用同一四窗开发筛查；其成绩只归属于新增 VAD 及由此引起的分窗变化。

执行决定：分离四窗三路 CER 均回归，停止该输入链；X0＋VAD 四窗无整体收益，停止。
W0＋VAD 四窗满足八轴改善后原样扩展十二窗，但删除和完整覆盖回归，主要差值区间跨零，
因此不继续 VAD＋CTC 堆叠。第三方向改为独立 **原 W0＋归一化标准日语 CTC**：
使用旧 round2 的十二窗原 PCM 与已核验的 W0 缓存全文／原 segments，保持源偏移，
仅运行现有 CTC 阶段并与三条原基线比较。缓存 ASR 与新计算成本分开记账。
该方向不改 W1／X0，不使用参考字幕指导对齐窗口，也不把旧 II 章节探索当作本轮新证据。

原 W0＋CTC 首次十二窗出现一个明确输入契约问题：III-05 的原父 segment 仅 20 ms，
但其自身 word 时间为 700 ms；CTC 得到 1 帧、3 个 targets，不满足解码所需帧数。
保留并独立计分原失败尝试，另登记最小修复配置：每段对齐搜索范围取原父 segment 与
其有效原 word 时间的包络，限定于源音频范围；已覆盖全部词的段保持不变。
只使用 ASR 自身时间，不加经验 padding、不参考 SRT、不按 CTC 成绩调窗；全文、源 offset、
模型及 CTC 参数均保持不变。原始 segments 与派生搜索窗口及身份映射分别保存。
同一确定规则作用于全部十二窗，先进行离线契约检查，再另起实验身份运行。

在新组件得分产生前预登记追加 III 确认区间：总时长的
10%、27.5%、45%、57.5%、72.5%、90% 起点，各 300 秒，16 kHz 样本取整。
它们避开旧 round2 窗口和已记录媒体抽查，最短隔离约 66 秒。
若进入此步骤，先锁定配置，不再据结果调参；六窗不生成 bootstrap 区间。
这些是同作品的未曝光区间，不是未见电影或跨作品独立保留集。

确认语料现已按预登记区间准备：`.local/components/confirmation-corpus/manifest.json`，
六窗共 1800 秒、227 条参考，其中六条跨裁剪边缘。最短曝光隔离 66.266625 秒。
manifest SHA256 为 `65b1a2e879b3fdea72b02e61ffe939d020c84fcf02fa2fac665bef689e312db2`。
准备入口 `experiments/components/prepare_confirmation.py` 复用已解码且核验身份的全片 PCM，
没有再次提取视频；六份裁剪与原 PCM 对应样本逐一哈希一致，源 FLAC／SRT 前后哈希一致。

- 所有新模型推理使用 GPU，串行执行；普通解码、重采样和评分可用 CPU。
- 新增依赖隔离于 `.local/`；不升级现有冻结后端环境。
- 模型获取与推理分开；记录版本、revision、许可、哈希和真实 forward 设备。
- 源音频和字幕只读，实验产物保存在 Git 忽略的 `.local/components/` 及 `.local/results/`。
- 旧结果及冻结源码不覆盖；新增适配器和评估入口使用独立文件。
- 比较完整端到端成本；缓存文字重对齐只能报告重算阶段成本。
- 新适配器需要离线契约测试和真实 GPU smoke；入围方案补充重复性与连续性证据。

## 初始核查

现有三者均没有神经降噪／人声分离。W1 已有 GPU Pyannote，W1／X0 已有日语 wav2vec2 CTC。
旧 W0＋标准 CTC 探索已有收益和长尾取舍，不能把重复实验包装成首次发现。
`uv run --locked --offline python -m unittest experiments.analysis.test_round2 -q`：
12 项通过，证明既有边缘／失败记账测试可运行，不代表新增组件质量通过。

本任务属于差分质量研究，没有单个已确认软件故障；诊断技能的“复现单一 bug”阶段
以固定输入、完整计分和同参数单组件消融替代。兼容性或执行故障另做最小复现。
